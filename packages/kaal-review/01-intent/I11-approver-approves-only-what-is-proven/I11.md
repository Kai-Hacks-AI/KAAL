# review/I11 approver-approves-only-what-is-proven

An approval that a GitHub App gives stands in for a person, so it is given only when the files prove the pull request is what it is approved as, and only for the exact revision they were read at. The KAAL Approver approves one kind of pull request, a SYNC that is a pure merge of the base, and only when a check signed by the Inspector says so at the same revision. When anything is unknown, stale, or not the Approver's to decide, it does nothing: it never declines, never merges, never comments and never approves what it raised. The kind of a pull request is read from its content and never from its title, body or branch name.

**Done when** the Approver's authority is written down once as its own declaration, a decision to approve is reached only from evidence of a pure merge and a passing signed check at one and the same revision, and every other case ends in no approval with a named reason.
