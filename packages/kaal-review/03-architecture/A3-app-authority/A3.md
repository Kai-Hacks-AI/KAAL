# review/A3 app-authority

Who owns what, for the Apps of the shopfloor:

| Element | Owner | Holds |
| --- | --- | --- |
| the Inspector and the Approver, their declared authority and the rule that no App decides on what it raised | Review | one declaration per App, `13-source/github-apps/<app>.json`, the judgement of a set of declarations, and the source of the workflow of each |
| the Dispatcher | Release | its own authority, which may later cover more pull request types than PROMOTION; its declaration is its own |
| the App adapter | Hosting | the closed list of abilities, the mapping to GitHub permissions, manifests, tokens, API calls and logo slots, for every App |
| the judge, the sign step and the one check per registered control | Controls | what a check says and how it is posted |
| creating and installing each App, storing each key, drawing each logo | the Owner, by hand | nothing in the repository |

A declaration says what the App needs in neutral abilities; Hosting turns that into what GitHub grants. The judgements are pure functions in `13-source/scripts/judge-app.mjs`: `readDeclaration(text)`, `judgeApps(declarations)`, `judgeWorkflow(text)`, `judgeSelfModification(paths, surface)` and `checkEvidence(evidence, expected)`. Each returns findings, reads nothing from Git or GitHub, and never runs what it reads; a malformed input is a finding and never an exception. The workflow source is `13-source/workflows/inspector.yml`, which a WIRE installs under `.github/workflows` without change; this Change adds no `.github` file and no WIRE.

None of it is shipped in the Skill, which stays free of KAAL's own Apps. The package does not yet have `13-source`; adding these files under it is the first step of Review's move to the layout, which stays a separate Change. The ability names are provisional until Hosting's list (hosting/C114) is merged; the Cases use its words then.
