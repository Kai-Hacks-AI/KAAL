# review/F27 review-item

A Review item is a definition that exists before any assessment is performed. It is one Markdown file named `V<n>.md`, with front matter and three chapters. Its front matter holds `id` (`<namespace>/V<n>`, the namespace being the capability that owns the item, as for a Case) and `validates`, one or more subject references. A subject reference is the id of an element as its owner states it, or `path:<repository path>` for a thing that has no id. The chapters are `Question` (what is assessed), `Criteria` (what would make the answer yes, as a list) and `Expected evidence` (what an appraiser is expected to have seen, as a list). An item names no result. The kind of the subject is not restricted: an Intent, a Requirement, an Architecture element, a Defect, code, a Skill, an instruction file, a document, another Review item or a result may all be validated. An item with no `validates`, no Question, no Criteria or no Expected evidence is reported as a finding and not listed as an item.

**Done when** a tree of items is read and each well-formed item is listed with its subjects, question, criteria and expected evidence, and each malformed one is a named finding, with subjects of any kind accepted.
