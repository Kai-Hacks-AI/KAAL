# review/F41 approver-trusted-execution

The Approver's workflow executes only code from main, never code of the change it decides on. It runs on a trusted trigger, judges from facts and never checks out the head. The decision of review/F40 therefore also needs evidence of its own execution, given as data: the trigger that started it, the revision of the code that ran, and whether the head was checked out. What the execution is compared with is not chosen by the caller. The revision of main is a fact that Hosting produced (review/F40), and the trusted triggers are a fixed list in the judgement itself, which is code of main, so changing them is a reviewed change on main and never an argument; the list starts as `workflow_run` alone and is the CTO's to change. It answers `approve` only when the trigger is in that list, the code that ran is the revision of main in the facts, and the head was not checked out. Otherwise it answers `abstain` with a finding: `trigger-not-trusted`, `code-not-main` or `head-checked-out`, and `execution-unproven` for missing evidence of execution, evidence of the wrong shape, a fact that is anything but the expected value, or no revision of main in the facts. A missing proof of trusted execution is an abstention and never an approval, so the judgement fails closed. A list of triggers offered by the caller, in the facts or in the evidence, is ignored. This requirement fixes what the files and the facts can show; the workflow and the operational proof of trusted execution before adoption are the CTO's and are not in this Change.

**Done when** evidence of execution of main's code on a trusted trigger without a checkout of the head is approve under F40, a list of triggers offered by the caller is ignored, and each of an untrusted trigger, code that is not main's, a head that was checked out and missing or malformed evidence of execution is abstain with its own finding.
