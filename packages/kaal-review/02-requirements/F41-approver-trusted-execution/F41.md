# review/F41 approver-trusted-execution

The Approver's workflow executes only code from main, never code of the change it decides on. It runs on a trusted trigger, judges from facts and never checks out the head. The decision of review/F40 therefore also needs evidence of its own execution, given as data: the trigger that started it, the revision of the code that ran, and whether the head was checked out. It answers `approve` only when the trigger is one of the trusted triggers named in what is being decided, the code that ran is the revision of main named there, and the head was not checked out. Otherwise it answers `abstain` with a finding: `trigger-not-trusted`, `code-not-main` or `head-checked-out`, and `execution-unproven` for missing evidence of execution, evidence of the wrong shape, or a fact that is anything but the expected value. A missing proof of trusted execution is an abstention and never an approval, so the judgement fails closed. Which triggers are trusted, and what runs the Approver, are decided with the CTO and given to the judgement as data; this requirement fixes what the files and the facts can show and does not fix the workflow.

**Done when** evidence of execution of main's code on a trusted trigger without a checkout of the head is approve under F40, and each of an untrusted trigger, code that is not main's, a head that was checked out and missing or malformed evidence of execution is abstain with its own finding.
