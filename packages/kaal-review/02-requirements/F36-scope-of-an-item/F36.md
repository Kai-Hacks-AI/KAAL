# review/F36 scope-of-an-item

What an item examines is its scope, written as the entries of the existing front matter field `validates`: the id of an element, `path:<repository path>` for a file, `path:<repository path>/` for a folder with everything under it, or several entries for a set. No field is renamed and every item that exists stays valid. Asked about a file, `about(answer, 'path:<file>')` returns the items whose scope names that file and those whose scope is a folder that contains it; asked about a folder it returns the items that name that folder or a folder above it, and none that name only something below it. An element id is matched exactly, as today. A `path:` entry that is empty, absolute, holds a backslash or a dot segment is a finding named `bad-scope-reference`, and the item is still listed. A path is read as text and never looked up on disk.

**Done when** a file is found by the items that name it and by those that name a folder above it, a folder is found by the items that name it or a folder above it, an element id is still matched exactly, and each malformed path entry is a named finding.
