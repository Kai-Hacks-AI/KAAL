# review/F37 reference-of-an-item

What the scope of an item is compared against is its reference, written in the front matter field `against`. Every item has one: one or more entries, each the id of an element (an Intent, a Requirement, an Architecture element or a Defect for instance), a `path:` entry as in F36, or the reserved entry `intrinsic`. The entry `intrinsic` says that no outside reference is needed because the scope is compared against itself: its own stated purpose, its own definitions or its own consistency. It is written, never implied, so an item that leaves the reference out is told apart from one that has an intrinsic reference. An item with no `against`, or an empty one, has no reference and is not valid: it is a finding `item-incomplete` whose `missing` list names `reference`, and it is not listed. `navigate` lists the references of every item, and answers `judgedAgainst`, the items by reference, `intrinsic` among them, so that a reader can ask which items are judged against a Requirement and which only against themselves. An entry that is empty or a malformed `path:` entry is a finding named `bad-against-reference`. A reference is not resolved and is not known to exist, as for a subject, and Review keeps no list of kinds. Whether an outside reference is the right one, and whether an intrinsic one is enough, stay judgements of the appraiser; the script checks only that a reference is stated.

**Done when** the references of an item are listed, the items are found by a reference and by `intrinsic`, an item without a reference is not valid and says so, an item with an intrinsic reference is valid, and each malformed entry is a named finding.
