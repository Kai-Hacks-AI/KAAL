# review/F37 reference-of-an-item

What an item is judged against is its reference, written in the optional front matter field `against`: one or more ids of an element, an Intent, a Requirement, an Architecture element or a Defect for instance, or `path:` entries as in F36. A review must have a reference in substance, and there are two ways to have one: an external reference, the entries of `against`, or self-contained criteria, the Criteria chapter that every item carries, which say what would make the answer yes without pointing outside the item. `against` is optional and is never required for an item that has Criteria; Criteria are never optional, with or without `against`, because an external reference says what to judge against and only the Criteria say what would make the answer yes. An item with neither, no `against` and no Criteria, is not valid: it is a finding `item-incomplete` that names the missing reference in substance, and it is not listed. Whether Criteria are in fact self-contained, and whether an external reference is the right one, stay judgements of the appraiser; the script checks only that the substance is there. `navigate` lists the references of every item, and answers `judgedAgainst`, the items by reference, so that a reader can ask which items are judged against a Requirement. A reference entry that is empty or a malformed `path:` entry is a finding named `bad-against-reference`. A reference is not resolved and is not known to exist, as for a subject; Review keeps no list of kinds. An item that examines and is judged against the same single entry is listed without a finding.

**Done when** the references of an item are listed, the items are found by a reference, an item with Criteria and no `against` is valid, an item with `against` and no Criteria and an item with neither are each not valid and named, and each malformed reference is a named finding.
