# review/C4 validates-element

A review validates any element: it is target agnostic, as testing is, and knows no kind of element. What is missing is a way to find the reviews of one element by the element's id, and a confirmed statement that a review of a focus Review does not define, such as a control, is valid when it carries its own reference and actual. A first slice: one optional field in the review's `subject.json`, one confirmed rule, one recorded application; no change to the Skill, to the Nodes or to any other package; no DO is authorized by this PLAN.

## Baseline

`main` holds `kaal-review` 0.0.1 with the focused review (review/C1) and the standalone proof (review/C2). `subject.json` names a focus, a reference, an actual, what is inspected and the questions. It does not say which element the review is about, so the reviews of one element cannot be found by its id. A focus not defined by Review is valid only when its reference and actual are provided (review/C1, `lib.mjs`); no application shows that for a control.

## PLAN

Adds F26 and the Cases review/T295 and review/T296, red because no application carries a `subject` and none has a focus of `control`. Ids: C4, G5, F26, T295, T296 (within the block T292 to T299 handed out by the Coordinator).

- **`subject`**: `subject.json` accepts an optional field `subject`, the id of the element the review validates, exactly as that element states it. When present it is one non-empty id without spaces, and the review record names it. Review does not resolve the id, does not know the element's kind and does not check that the element exists: that is the business of whoever owns the element. A review that carries no `subject` stays valid, as every existing application is.
- **A focus Review does not define**: `control` is such a focus. It is valid when its reference and actual are provided, which is the rule that stands. No new rule is made; the Case shows it holds for a control.
- **Naming**: the field is called `subject` as requested, inside the file `subject.json`. The Owner may prefer another name before the DO.

Which elements carry which `subject` ids is not Review's decision. Review finds nothing by itself: the id is what a consumer searches for.
