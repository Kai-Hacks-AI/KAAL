# review/C7 scope-and-reference

Kai's framing: testing verifies and review validates; review is broader than testing, and testing is more precise. A review target can be an element, a file or a folder, and a review needs both a scope, what is examined, and a reference, what it is judged against. This Change gives Review items that scope and reference, and the navigation from a file, a folder or a reference back to the items. It is the first bounded increment of the validation view; a PLAN, and no DO is authorized by it.

## Baseline

`main` holds review items (C5): `validates` takes element ids or `path:` entries and `navigate` answers by exact subject. Nothing says that a `path:` entry may be a folder, an item cannot state what it is judged against, and "which items cover this file" finds only items that name that very file. The older review record (C1) already has a reference and an actual, in free form; items have neither word.

## Gaps

| Gap | Target | Gap |
| --- | --- | --- |
| review/G8 | I10 review has scope and reference | an item cannot examine a folder or a set with a meaning, cannot say what it is judged against, and neither can be asked for from the other side |

## Design question: the words

KAAL already uses these words, and a new pair should not collide with them.

| Word | Where it is used today |
| --- | --- |
| focus, reference, actual | the C1 review record: the focus fixes a reference and an actual, each read at an exact commit |
| subject | review items (`validates`), the `subject` field of a record, and Testing's `tests` relationship |
| target | the Target column of a gap: the Intent a gap is measured against |
| scope | write areas and path scope in Engineering and Release |

Kai asked for a scope (what is examined) and a target of review (what it is judged against). Options:

1. **Scope and reference (recommended).** Scope is what is examined: the entries of `validates`, each an element, a file, a folder, or a set of them. Reference is what the scope is judged against: `against`. This reuses `reference`, which C1 already means in exactly this sense, and keeps `target` for the gap table. The key `validates` stays, so nothing migrates, and a *subject* is one entry of a scope.
2. **Scope and target.** The words as Kai wrote them. `target` then means the Intent of a gap in one place and the reference of a review in another.
3. **Subject and reference only.** No new word; a folder or a set is a subject. Smallest, but it leaves "what is examined" with no word for a set.

The PLAN carries option 1. The CPO may choose another; the words move in the Skill reference and the finding names only, and no Case depends on them, because the Cases name the front matter keys, which stay `validates` and `against` whichever word is chosen. Whether the key `validates` should later become `scope` is a separate Change.
