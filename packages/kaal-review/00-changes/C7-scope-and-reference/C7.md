# review/C7 scope-and-reference

Kai's framing: testing verifies and review validates; review is broader than testing, and testing is more precise. A review target can be an element, a file or a folder, and a review needs both a scope, what is examined, and a reference, what it is judged against. This Change gives Review items that scope and reference, and the navigation from a file, a folder or a reference back to the items. It is the first bounded increment of the validation view; a PLAN, and no DO is authorized by it.

## Baseline

`main` holds review items (C5): `validates` takes element ids or `path:` entries and `navigate` answers by exact subject. Nothing says that a `path:` entry may be a folder, an item cannot state what it is judged against, and "which items cover this file" finds only items that name that very file. The older review record (C1) already has a reference and an actual, in free form; items have neither word.

| Gap | Target | Gap |
| --- | --- | --- |
| review/G8 | I10 review has scope and reference | an item cannot examine a folder or a set with a meaning, cannot say what it is judged against, and neither can be asked for from the other side |

## Design question: the words

KAAL already uses these words, and a new pair should not collide with them.

| Word | Where it is used today |
| --- | --- |
| focus, reference, actual | the C1 review record: the focus fixes a reference and an actual, each read at an exact commit |
| subject | review items (`validates`), the `subject` field of a record, and Testing's `tests` relationship |
| target | the Target column of a gap: the Intent a gap is measured against |
| scope | write areas and path scope in Engineering and Release |

The CPO chose scope and reference as the vocabulary, over *scope and target* (which would give *target* two meanings) and over *subject and reference only* (which leaves a set with no word). Both are rejected. The key `validates` stays and is read as the scope; a *subject* is one entry of a scope. Whether `validates` should later be renamed `scope` is a separate Change.

Following the Owner's direction, three things are distinct and overlap-free:

| Word | Means | Written as |
| --- | --- | --- |
| scope | what is examined | `validates`: an element, a file, a folder, or a set |
| reference | what the scope is compared against | `against`: an element id, a `path:` entry, or the reserved `intrinsic` |
| criteria | the dimensions and rules by which the comparison is judged | the Criteria chapter |

## PLAN

| Requirement | Intent | What it adds |
| --- | --- | --- |
| review/F36 | review/I10 | a folder or a set as scope, found from a file and from a folder above it, with malformed paths named |
| review/F37 | review/I10 | `against` is required: an outside reference or the stated `intrinsic` one; the items found by reference; an item without one is not valid |
| review/F38 | review/I10 | criteria are dimensions of judgement and not the reference; an item without them is not valid; a criterion that is plainly a reference entry is named |

Architecture is review/A4. The Cases are review/T1554, review/T1555 and review/T1556 under `test/plan/scope-reference/`, plain `.test.mjs`.

### Scope, reference and criteria stay apart

The contract, from the CPO and the Owner. Every review item has a scope, a reference and criteria, and none stands in for another. The reference is never optional and never replaced by criteria. Where no outside reference is needed, the reference is **intrinsic**: the scope is compared against itself, for instance a document against its own definitions, and it is written `against: [intrinsic]`, so that a review with an intrinsic reference is told apart from one that forgot its reference. Criteria say how the comparison is judged. Neither a reference nor an intrinsic reference makes criteria unnecessary, and criteria never make a reference unnecessary.

Acceptance expectations: T1555 asserts that an item with an outside reference is valid, that an item with `intrinsic` is valid and found as such, that an item with no `against` or an empty one is not valid and not listed and says the reference is missing, and that malformed entries are named. T1556 asserts that an item with a reference and no Criteria, and an item with Criteria and no reference, are each not valid and say which is missing, and that a criterion that is word for word an entry of `against` or `validates` is a named finding while the item stays listed. That a criterion is truly a dimension of judgement, that an outside reference is the right one and that an intrinsic one is enough are the appraiser's judgements and are not scripted.

Migration: the two examples under `00-changes/C5-review-items/examples/items` and the fixtures of the existing tests gain an `against`, in the DO.
