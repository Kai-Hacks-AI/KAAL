# review/C2 standalone-product

The delivered `kaal-review` package must function without any unrelated KAAL package present. Engineering owns dependencies, builds, verifies, delivers and embeds packages, and may use `kaal-testing` to develop or test Review; that is not a product dependency and this Change does not remove it. This Change adds the missing proof that the delivered product stands alone: it checks the packed package, in isolation, against the product contract. A first slice: no change to the Skill, to the Nodes or to any other package; no DO, no promotion and no publication is authorized.

## Product contract

A delivered KAAL package needs no other KAAL package. The permitted shared product dependencies are `kaal-hosting`, to implement Linux, Windows, macOS and other OS support once, and `kaal-foundation`, for mandatory shared semantics. Every other KAAL package, `kaal-testing` included, must not be required for standalone operation. Engineering-time use of any package is not restricted by this contract.

## Baseline

`main` holds `kaal-review` 0.0.1. Its packed contents are `LICENSE`, `README.md`, `package.json`, `payload/*.md` and `skills/kaal-review/SKILL.md`. It declares no runtime dependency and neither the payload nor the Skill names another KAAL package, so the product appears to satisfy the contract today. No check proves it: the existing tests run inside the workspace, where every KAAL package is present, and the pack test lists files without testing isolation. Its `kaal-testing` devDependency and the ownership test that imports `kaal-testing/attribution` are Engineering-time and stay.

## DO

Not authorized by this PLAN. Add `test/standalone.mjs`, which acts as a consumer. It packs the package and extracts the tarball into an empty directory outside the workspace. It builds a consumer environment that holds the extracted product and the permitted shared dependencies and no other KAAL package. It derives what to exercise from Review's own declaration, not from constants in the Case:
- **Skill.** The Skills named by the extracted `skills/` directory load as Agent Skills: front matter parses, name and description are present, and the name matches the directory.
- **Nodes.** The Nodes the extracted payload holds are registered into a fresh Engine from the extracted copy alone, as the README declares, and the Engine's catalog then lists them. The set compared is whatever the payload holds.
- **Runtime closure.** Every dependency the manifest declares and every import in a shipped source file resolves from the consumer environment, and only to permitted packages. A name mentioned in prose is not a dependency and is not checked.

It also reports the packed file list as supporting evidence, which the Case may print but does not assert on. Turn T292 green by renaming it to `.test.mjs`. The existing ownership verification is retained as it is and is not weakened or replaced.
