# retro/F1 retro-record

A retro is one Markdown file in the consumer's `<capability>/02-learnings/retros/`, with front matter `id`, `format` and `reflects`. The id is `<capability>/RT<n>`. `format` names the method, `4L` today. `reflects` is a non-empty list of Change ids the retro looks back on, and it is the only link: a retro points at Changes, nothing points back. One retro is written for each landed collector. What a retro means for any process, such as when work counts as closed, is for the consumer to decide. A file with another id pattern, no format, an empty or malformed `reflects`, or an id that another file also holds is refused with the reason and is not listed as a retro.
