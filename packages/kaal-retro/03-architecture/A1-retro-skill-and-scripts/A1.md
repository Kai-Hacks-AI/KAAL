# retro/A1 retro-skill-and-scripts

The package `@kaihacksai/kaal-retro` holds one Skill, `skills/kaal-retro/`, with `SKILL.md`, `references/4l.md` (the lenses and the result shape, from the agent's seat) and two scripts in `scripts/`: `find-retros.mjs`, which exports `findRetros(files)`, and `judge-retro.mjs`, which exports `judgeRetro(text)`. Both print JSON on the command line and know no repository path. Order follows BASS: the consumer's AGENTS.md routes "looking back on your own work" to the Skill by its description, the Skill carries the method, and the scripts only find and check form.

The Skill's description is its offer. By Exchange it offers any consumer two things in words: finding retros with the Changes each reflects, and a form-only judgement of a 4L retro. A consumer with Retro alone has everything it needs. Retro knows no phase, station or control, and what a consumer does with a found retro is the consumer's own.

The Retro id is `RT<n>` with `format: 4L`, not `4L.<n>`. One id kind then has one finder, whatever the format; a retro keeps its id when its format is reworked; a new format is a new `format` value with its own judgement, and the judgement says `unjudged` for a format it does not know. With `4L.<n>` each format would be its own id kind with its own finder, and changing a format would change an id.
