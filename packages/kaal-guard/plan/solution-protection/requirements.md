# Solution protection: Requirements

Each obligation names, in brackets, the Intent outcomes it serves. Numbers continue Guard's own (F up to 40, N up to 13).

## Functional

- **guard/F41 Registration beside the guarded thing.** [guard/I10] A folder registers its checks in `guard.json` beside it: `{ "checks": [ { "name": "test", "command": "npm test", "aggregates": ["solution"] } ] }`. `name` has no space or colon; the check's id is `<folder>/<name>` (`packages/kaal-controls/test`). `command` follows guard/F9 and runs in the folder that holds the file. `aggregates` lists the aggregates the check belongs to; a check may belong to several. Anything else in the file is refused as cannot judge, naming the file and the member.
- **guard/F42 Add-only from the base.** [guard/I11] The registrations the base holds are the baseline. The candidate's registrations are the baseline plus any it adds, and a pull request's own additions run in it. A candidate that removes a baseline registration, or changes its `command`, `aggregates` or folder, is cannot judge, naming the file and the check. The one exception: the candidate's diff holds only registration files (`guard.json` and the aggregates file), so that it lands alone and reviewed, as guard/F7 already asks of a trusted declaration.
- **guard/F43 The aggregates file and the always list.** [guard/I10, guard/I11] `aggregates.json` in Guard's configuration directory (default `.kaal/config/guard`, the consumer's choice by `--config`) states, per aggregate, `always`, the check ids that must run in every run, and `exempt`, a map from a path to the reason it needs no registration. It is read from the base. A missing or unparseable file on the base is cannot judge, never empty. `aggregates` is valid only for the name `solution`; `change` and `delivery` are refused as not built yet.
- **guard/F44 Completeness.** [guard/I10] Every `package.json` in the repository (outside `node_modules`) with a `test` script must be covered: its folder holds a `guard.json` check that belongs to `solution`, or its path is in `exempt` with a reason. Otherwise `plan` fails naming the folder and the exact `guard.json` or `exempt` line to add.
- **guard/F45 Plan.** [guard/I10] `kaal-guard plan --aggregate solution` writes the expected set (always, plus every registration that belongs to the aggregate, from guard/F42) and the CI matrix over it, as JSON. An empty expected set is cannot judge.
- **guard/F46 Fold.** [guard/I10, guard/I12] `kaal-guard fold --aggregate solution --plan <file> --reports <dir>` passes only when the set of checks that reported equals the expected set exactly and each one's report records success (guard/F2: pass, or not applicable shown as such, or held shown as held). An absent report, an empty set, a report of anything else, and a report of a check nobody expected each fail, naming the check. It reads the per-check reports, not a count and not a job result. This is the same contract as release/C170, kept in one function so the two stay equal.
- **guard/F47 One name in both places.** [guard/I10] The workflow template runs `plan`, one job per check (named by its id) and `fold`, on `pull_request` and `merge_group`. The fold job's name is the only name a ruleset requires (`Solution protection`, provisional, to be confirmed with Release). A per-check job's name never equals a fold name, so it cannot be required by accident.
- **guard/F48 Report.** [guard/I12] `run --report <path>` writes the check's result, and `fold` writes the aggregate's, as `guard-report.json`: check id, aggregates, result, finding, fix hint, the registration file it came from, and for a fold the checks that decided it. A crash, a missing registration, an unparseable file and an unreadable list are written there too, never only to a log. The output and the CI step summary name the file.

## Nonfunctional

- **guard/N14 Honest exits.** [guard/I10] A check that did not run is never a pass: a command that cannot start, a crash of `plan`, `run` or `fold`, and a missing report each exit non-zero and are recorded.
- **guard/N15 Dumb and independent.** [guard/I10] `plan`, `run` and `fold` read exit statuses and reports only. They import nothing of Controls, Testing or Core, and take no mode.
- **guard/N16 Legacy stays out.** [guard/I11] A `.kaal/config/guard/<name>.md` declaration is never a member of an aggregate, and `aggregates` in one is refused.
