# defect/C1 defect inventory

A Defect is a passive description of an undesirable condition, usually free text, and holds no state. Its state is derived from the Test Cases that point at it, the way a Control's status is judged from the Cases that test it: a Case points at a Defect with its first line, and a judge reads the records a Case runner made. A Defect is recorded in the context where it was born and that record is authoritative; kaal-defect discovers the records, keeps no second list, derives each Defect's state and lists the unresolved inventory as an input to planning, grouped by the Architecture element that addresses a Defect. It ships no Defect. Running the Cases is Testing's, finding is Review's, a Defect is born as its record plus the Test Case that proves it, where a correction belongs is Architecture's, and the fix is a Change plus whatever else is needed. What a Defect's state allows is the policy of the consumer or integration gate. It does not select a CARE treatment (Contain, Accept, Ratchet, Eliminate) or authorize a release. Every validated Finding creates a Defect and its proving Test Case, whatever the treatment later chosen; Eliminate runs by a hotfix or by a fix through a normal Change. No Defect is moved and nothing is wired to CI.
