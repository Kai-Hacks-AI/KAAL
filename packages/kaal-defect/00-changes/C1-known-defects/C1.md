# defect/C1 defect inventory

A Defect is a passive description of an undesirable condition, usually free text, and holds no state. Its state is derived from the Test Cases that point at it, the way a Control's status is judged from the Cases that test it: a Case points at a Defect with its first line, and a judge reads the records a Case runner made. An accepted Defect is recorded in the context where it was established and that record is authoritative; kaal-defect discovers the records, keeps no second list, derives each Defect's state and lists the unresolved inventory as an input to planning, grouped by the Architecture element that addresses a Defect. It ships no Defect. Running the Cases is Testing's, establishing a Defect is Review's, and where a correction belongs is Architecture's. What a Defect's state allows is the policy of the consumer or integration gate. No Defect is moved and nothing is wired to CI.
