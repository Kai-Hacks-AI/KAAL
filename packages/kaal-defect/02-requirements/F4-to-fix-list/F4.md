# defect/F4 unresolved inventory

The mechanic lists every Defect record that is not `answered`, grouped by the context of the Architecture element that addresses it (the existing `Architecture —addresses→ Defect` relationship, an `addresses:` list in the element), otherwise by the context that holds the Defect. Where a Defect was found, where another Defect may explain it, and where Architecture places the correction are three separate things: Defect never moves a record, never sets a field to say where a correction belongs, and judges no explanation between Defects. The list is an input to planning, not an order to fix and not a release veto.
