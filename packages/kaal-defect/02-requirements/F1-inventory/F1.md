# defect/F1 inventory

An accepted Defect is a record in the context where it was established, and that record is authoritative. The mechanic discovers the Defect records of the places the caller hands over and derives the inventory from them; it keeps and reads no second list of Defect ids, so membership is not a second source of truth or a second acceptance decision. An accepted Defect persists unresolved across Changes and releases until its derived state is `answered`. The caller hands over where the Defect records, the Architecture elements and the Test Cases are; the package knows no folder name or number.
