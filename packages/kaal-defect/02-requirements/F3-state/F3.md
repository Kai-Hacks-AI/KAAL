# defect/F3 state

The state of a Defect is derived from the records of the Cases that point at it, at one revision, and never stored on the Defect. A record is `{case, run, revision, outcome, covers}`, and outcome is `GREEN`, `RED` or `UNKNOWN` as a Case runner reports it. A record of another revision is stale and does not count. A missing record, or any outcome other than `GREEN` or `RED`, is `UNKNOWN`. A Case is `RED` if any applicable run is `RED`, `GREEN` if every applicable run is `GREEN`, otherwise `UNKNOWN`. A Defect is `confirmed` when some applicable Case is `RED`, even if every other Case is `UNKNOWN`: one RED Case is enough to show that the Defect exists. It is `answered` only when it has Cases, every applicable Case is `GREEN` with complete evidence, and every part of its claimed reach is covered (see defect/F5). Without a RED and without complete GREEN evidence it is `unknown`, including when no Case points at it. `UNKNOWN` is never read as `RED` or `GREEN`.

Several Cases that point at one Defect are different manifestations, contexts or conditions of the same undesirable condition. They do not make several Defects and do not make several fix locations. Each Case's own outcome is kept alongside the derived state and is never merged into it. The state is evidence: whether it allows a merge is the consumer's policy. It does not classify a Finding, does not select a CARE treatment (Contain, Accept, Ratchet, Eliminate) and does not authorize a release.
