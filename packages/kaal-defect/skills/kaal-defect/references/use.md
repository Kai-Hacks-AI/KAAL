# Use

The caller says where things are: it hands over a JSON file `--places`, a list of `{context, defects, architecture, cases}`: the place a Defect was found, the folder with its Defect records, the folders with its Architecture elements, and the folders with its Test Cases. The Skill knows no folder name or number. `node scripts/known-defects.mjs --places <file> --records <file> --revision <revision>` prints `<state> <defect>` per Defect record, then one indented `<case> <outcome>` line for each Case that points at it. Add `--list` for the unresolved inventory: Defect records that are not answered, grouped by the context of the Architecture element that addresses them, or by the holding context while none does. It is an input to planning, not an order to fix and not a release veto. The script runs no Test Case. A location handed over that cannot be discovered (missing, not a folder, unreadable) is not an empty one: the script prints `incomplete <role> <path> (<reason>)`, still reports what it found, never reports `answered` from a partial Case inventory, and exits 2. An existing empty folder is a verified empty inventory and exits 0. A scope you do not hand over is yours and no failure.
