# kaal-core

KAAL Core as an npm package. It carries KAAL's artifacts as files, in `artifacts/`, laid out as they deploy: the Kernel, the Nodes and one empty seal `seals/<ID>` per sealed Node. The files are the authority. Its public API is `payload()`, which returns them as files keyed by path relative to the KAAL directory, `registerSkill()`, which registers a capability's KAAL Skill contribution (Nodes and their own seals) with an installed KAAL directory under `skills/<capability>/`, and `installedSkills()`, which answers which Skills an installed KAAL directory holds: the admitted Nodes typed, by name and ID, by its admitted `Skill` Node, as `{ name, id }` references. `registerExtension()` and `installedExtensions()` are the same for KAAL Extensions: typed by Core's `Extension` Node and placed under `extensions/<capability>/`. Core carries the `Skill` and `Extension` types and these registrations, never a Skill or an Extension; registration uses the Node machinery internally, which is not part of the public API. Core also holds private bootstrap sealing (`src/bootstrap.ts`): only what it needs to check the Kernel's genesis seal and to record and verify the seals of the Nodes it carries, before any Skill exists. It covers Core's own artifacts alone, cannot seal or verify a Skill's Node, is not exported and is not a general sealing capability; sealing KAAL artifacts after bootstrap is the Sealing Skill's, which Core never depends on.

Core also ships a default Core configuration, `artifacts/core/config`, deployed to `<kaal-dir>/core/config`: self-documenting, every setting commented out, and not a Node and not sealed. It is born with the KAAL and then belongs to the instance, which may edit it. A commented or missing setting means Core's default applies; an uncommented one overrides it for that instance. The one setting today is `capability-prefix` (default `kaal-`), the prefix of capability delivery names, which sealed identity leaves free. Core's private checker (`src/config.ts`, not public API) reads the target instance's own config and reports each `skills/<name>/` that does not start with the prefix; it observes and never renames or repairs.

Build and test from this directory alone: `npm ci && npm test`.

Verification, sealing and the acceptance suite live outside the package, in `engineering/kaal-core`.
