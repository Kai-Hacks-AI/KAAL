## Why this cannot be a standalone Core Change on the current collector

`kaal/core`'s workspace Foundation is still 0.0.1. An exact 0.0.2 pin would be
unsatisfiable there: npm would nest a registry copy or fail `npm ci`, which is the
failure #848 diagnoses. So the pin edit is only green together with Foundation's
0.0.2 version bump (C16, #838) in one coherent state. Ordering therefore needs
Engineering's admission route; Core does not ask to be integrated first or alone.
Compatibility with Foundation 0.0.1 for ordinary bootstrap and inspection is
unchanged (Core's code imports only `./sha256` and the existing public data).
