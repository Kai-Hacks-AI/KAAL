# Identity and numbering: Requirements

Each Requirement names, in brackets, the Intents it serves.

## Nonfunctional

- **core/N33** [core/I46, core/I47]: A judgment is pure and independent of the order of the claims it is given. An identifier or claim Core cannot read is a finding, never skipped, and `nextID` refuses to answer past it. Absent is not empty: a namespace or kind Core does not know is reported as unknown, never as "the first number is free".

## Functional

- **core/F125** [core/I46]: An instance statement in a Registration states `guid`, its technical identity: non-empty opaque text that its creator gives once and nobody changes. Core checks nothing else about it. A kind definition may state `numbered`, a prefix of capital letters, and only the kind's owner does (core/F51).
- **core/F126** [core/I46]: A claim is the technical identity, the namespace, the identifier and the kind of one instance. An assembly holds one claim for each technical identity. Two claims of one `guid` are a `guid-claimed-twice` finding naming both, which is what a copied file or two competing renumberings look like.
- **core/F127** [core/I46, core/I47]: `assembly.checkID(claim)` judges one proposed claim, replacing any claim the assembly holds for the same `guid`. It returns `{ ok: true }` or `{ ok: false, findings }`. The findings are `unnumbered-id` when the identifier is not the kind's prefix and a positive decimal without a leading zero, `id-taken` naming the other technical identity that holds that namespace and identifier, and `unclaimed-namespace` when no Registration claims the namespace. A renumbering, the same `guid` with another identifier, is no finding by itself: Core judges the claims it is given and knows no history.
- **core/F128** [core/I47]: `assembly.nextID(namespace, kind)` proposes `{ id }`, the prefix and one more than the highest number the namespace holds under that prefix, or the prefix and 1 when it holds none. A gap is never reused. It returns `{ id: null, reason }` when the namespace is not claimed, the kind is not defined or not numbered, or the namespace holds an unnumbered identifier of that kind. It reserves nothing: two callers given the same claims get the same proposal.
- **core/F129** [core/I47]: The verdict on a union of claims does not depend on how the union was built. When two proposed claims take one identifier with different `guid`s, the verdict on the union names both technical identities, in the finding that one identifier is stated twice, so the one that is judged second fails, whichever it is. Core states the verdict. Putting it in CI, on the union a merge queue holds, is Engineering's and Release's Change.
- **core/F130** [core/I48]: A trace target may state `{ guid }`. It resolves through the current claim of that technical identity, so a renumbering changes no reference that states it. A target that states a namespace and an identifier is a weak reference: after a renumbering it is the unresolved finding it already is (core/F52), and Core guesses nothing.
- **core/F131** [core/I48]: An instance that states no `guid` is unadopted. Core judges it by its namespace and identifier as it does today, reports it as `unadopted`, and `kaal verify` does not fail on it. `adoptGuid(namespace, id)` gives the same `guid` on every branch and every run, so two branches that adopt one instance agree. It is the name-based UUID version 5 (RFC 9562) of the string `<namespace>/<id>` under one fixed KAAL namespace UUID, `f921a66e-44ed-5bfb-9b19-61545c92442a`, defined once as a constant in Core. It refuses an empty namespace and a namespace that contains `/`, so two different pairs can never give one string, and so never one `guid`. Adoption writes the `guid` into the instance's record once, changes no identifier, and renumbers nothing.
- **core/F132** [core/I46]: `newGuid()` gives a new technical identity: a random UUID version 4 (RFC 9562), made once when an instance is created and written to its file. It needs no coordination, so parallel branches cannot collide. Both functions use the platform's crypto and add no dependency.
