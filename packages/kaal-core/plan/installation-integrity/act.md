# C53 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it.

## Liked

The verdict is a pure function over two inventories, so every outcome (aligned, differs, unknown) and every reason code became a small Case. Making completeness an affirmative statement of the observer, and an unreadable source `unknown` rather than empty, closed the two false-aligned paths the CPO found. The PLAN amendments for the negative Cases kept the Cases immutable to the DO.

## Learned

Absence of evidence must never become positive proof: "not false" is not "true", and "found nothing" is not "verified empty". Each such gap needed its own Case before it needed code. A selected variant that is not defined is unknown, and the lookup must use own properties, or a name like `constructor` slips through. Core's boundary tests also steer a DO: the hash comes from Core's own Node support, not `node:crypto` or another package.

## Lacked

A real adopter. Nothing yet supplies authoritative evidence and an observation to the verdict, so the check is proven on fixtures only and stays unrun. Nothing proves the exit status inside a wired control either.

## Longed For

The control that runs `verifyInstallation` and takes identity, selected variant and lifecycle from its evidence, delivered by Release or Controls, with a WIRE only on the Owner's go. Core's C52 check then takes its instance and lifecycle from that same evidence.
