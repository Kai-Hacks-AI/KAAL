# C150 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it.

## Liked

The CPO's reviews moved the Change from a ban on words to a check of named patterns, and the Change got smaller and more honest for it. PLAN, DO and ACT stayed product vocabulary. Only repository delivery instructions are flagged. "Pull request" became a separate hosting rule, and its allowance is the adopter's, never a Skill's own claim. Saying plainly that a clean verdict supports the Skill's setup-agnostic promise and does not prove it kept the check from over-claiming.

## Learned

A check that cannot see something must not report it clean. A published verdict with no files, an empty list or a partial list passed at first, and the fix was to compare against the applicable inventory and list what was not read. Case wording matters too: my own Case asserted a `conformance` value that an earlier Requirement already gave to the lifecycle, and Cases are immutable to the DO, so it took a PLAN amendment to correct it.

## Lacked

The adopter that establishes the authoritative inventory, the justified binary exclusions and the Git or GitHub adapter identity. Without it the check is proven on fixtures only. Review's judgement of whether a consumer can use a Skill without the repository is also still missing, and no Skill has been run through this check. The license Change (core/C151) touches the same files on its own collector, so one of the two needs a SYNC before promotion.

## Longed For

The adopting control, with identity and lifecycle taken from C53 evidence, that runs `kaal skill check --lifecycle published` over each published Skill. A Review that reads each Skill as a consumer would, and a baseline of today's offenders so the ratchet can start.
