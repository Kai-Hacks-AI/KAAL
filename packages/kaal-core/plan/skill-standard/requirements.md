# Skill Standard: Requirements

Each Requirement names, in brackets, the Intents it serves, and says what verifies it.

## Nonfunctional

- **core/N25** [core/I27]: The standard is capability-agnostic. Core's check takes only the files it is given, names no capability, reads no registry, and gives the same result for the same input, whichever path the Skill takes. Verified by core/T106.
- **core/N26** [core/I28, core/I29, core/I30]: Core judges and reports. It does not decide what a verdict allows. A gate, WIRE or a control owns the policy and the baseline file, and Controls only runs the check. Verified by core/T106 (exit status and data) and core/T108.
- **core/N27** [core/I27]: No Core rule contradicts the Agent Skills standard. Core's rules are stricter, never different. Verified by core/T105 (a Skill of `SKILL.md` alone, the Agent Skills minimum, passes clean) and by the Owner's review of the DO against agentskills.io, a judgement.

## Functional

- **core/F92** [core/I27]: Core's payload carries a `Skill Standard` Definition, typed by `KAAL Definition`, beside `CASE` and `LOVE`. It states the vocabulary and conventions, that agentskills.io is the floor, the router and `lane` rules, that the frontmatter is reviewed separately, and that capabilities own their content. It changes neither the Kernel nor the id of any existing Node. Verified by core/T107.
- **core/F93** [core/I29]: `judgeSize` counts the words of a `SKILL.md` body: the whitespace-separated tokens after the frontmatter. The frontmatter is the block from a first line `---` to the next line `---`, found without reading its fields; a leading byte order mark is ignored, and a file with no such block, or an unterminated one, counts whole. Line endings do not change the count. It returns one level: `ok` up to 200 words, `soft` above 200, `medium` above 400, `hard` above 600. Exactly 600 is `medium`, and passes. Verified by core/T103.
- **core/F94** [core/I29]: Every `soft`, `medium` and `hard` result carries a warning as data: the Core rules that apply (`size`, `router`, `detail` and `lane` at every stage), the three remedies (review the whole router, consolidate, move detail to references), a `response` stage, and the actions the stage requires. The required actions of a higher stage include all of those of the lower one and more: `review-router` at `soft`, plus `restructure` at `medium`, plus `correct-before-delivery` at `hard`. Trimming words is never a remedy. Only `hard` blocks. Verified by core/T104.
- **core/F95** [core/I27]: `judgeLayout` takes the paths of a Skill directory and finds: no top-level `SKILL.md`, and any top-level entry that is not `SKILL.md`, `references/`, `scripts/` or `assets/`. `SKILL.md` alone is a complete Skill. Anything below the permitted folders is free. Verified by core/T105.
- **core/F96** [core/I27, core/I28]: `kaal skill check <dir> [--json] [--baseline <file>] [--enforce alignment] [--as installed|engineering|deployed] [--of <source dir>] [--version <v>] [--source <label>] [--from kaal|engineering] [--tag <name> --tag-of <dir>] [--owner <capability> --declared <file> --id <variant id>]` judges a Skill directory and reads only `<dir>`, the baseline and the directories and files the options name. Without `--as`, `<dir>` is the owning capability package's Skill at N+1. Its exit status is what a gate relies on: 0 when nothing blocks, 1 when something does, 2 when it cannot judge (no such directory, an unreadable file or baseline, a missing or contradictory option), which a gate treats as unknown and never as clean. With `--json` it prints the verdict as data. The directory is the candidate as data, so a gate may run Core from its base or default branch. Verified by core/T106.
- **core/F97** [core/I30, core/I31]: The `skill-size` ratchet. A baseline is a JSON object from a canonical Skill's name to `{ "owner": <capability>, "words": <recorded body words> }`; an entry without both is an unreadable baseline. Against it, a `hard` canonical Skill is `known` when its words equal the entry and passes; `grew` when above it and blocks; `new` when it has no entry and blocks. An entry whose Skill is now below its recorded words is `stale` and blocks until the entry is lowered or removed, so the allowance only shrinks and a resolved finding leaves it. With no baseline, `hard` blocks. An unreadable baseline is exit 2. The key is the Skill's name, never a path, so the Skill has one entry wherever it is deployed. Verified by core/T108.
- **core/F99** [core/I33, core/I34]: Alignment is a detective finding. With `--as` and `--of`, the check compares `<dir>` with its source by the tree digest (SHA-256 over the sorted relative paths and the exact bytes of every file) and reports `alignment` as data: the role, the source label, the version, the status `aligned` or `differs`, and the differing paths. A discrepancy is a finding: the exit status stays 0 for it, and it is 1 only with `--enforce alignment`, which a control uses once the Owner has made it preventive. A comparison that cannot be made is exit 2, never clean. Verified by core/T109 to core/T111.
- **core/F100** [core/I32]: Variants. With `--owner`, `--declared` and `--id`, an instance that differs from its source is a variant: `declared` when `--declared`, the owning capability's declaration, names the same owner (and the baseline's entry does) and lists the id, `unauthorized` when the declaration's owner differs, `undeclared` when the id is not listed. `<file>` is a JSON object from the Skill's name to `{ "owner": <capability>, "variants": { <id>: { "transformation": <text> } } }`. A declared variant has no `differs` finding. The other two are findings under `core/F99`. The instance's own files are never read as a declaration, and without all three options an instance that differs is `differs`. Verified by core/T109.
- **core/F101** [core/I33, core/I34]: `.kaal/`. A directory under a `.kaal/` path is always judged `--as installed`, and any other role for it is exit 2. `--as installed` requires `--of <the npmjs artifact's Skill directory>` and `--version <the published version>`, and takes `--tag <name> --tag-of <the Skill directory at that Git tag>`. It reports `.kaal/` against the artifact, and the artifact against the tag, each as `aligned` or `differs` with the paths and the version. Without the artifact or the version it cannot judge. Core does not fetch an artifact or a tag: the control that runs it supplies them. Verified by core/T110.
- **core/F102** [core/I34]: Engineering. `--as engineering --of <the package's Skill directory> --version <the package version> --source <label>` compares Engineering's copy with the current owning package, N+1, and names both, `{ source, version }` and the package's. It is never compared with a published version unless that is the source given. Verified by core/T111.
- **core/F103** [core/I34]: Deployed copies. `--as deployed --from kaal|engineering --of <the selected source's Skill directory> --version <v> --source <label>` compares `.agents/skills/` or `.claude/skills/` content with the source it was selected from, respecting `core/F100`. Verified by core/T109.
- **core/F104** [core/I35]: Lifecycle. The package at N+1, an Engineering copy and a deployment `--from engineering` are of the development lifecycle: `core/F93` to `core/F97` apply to them. The package is judged as the canonical, `stale` included, and a copy has the canonical's entry as a ceiling, never `stale`, never an entry of its own. An installed instance and a deployment `--from kaal` are as published: their level, warning and layout are reported with `conformance: "published"` and never block, whatever the baseline. A baseline whose allowance shrinks changes the development lifecycle's verdict only. Verified by core/T112.

## Amended

- **core/I14** and **core/N13** (see Intent): Core defines no Skill file format and never rewrites a `SKILL.md`. It states the KAAL standard, finds where the frontmatter ends and counts words.
- **core/F7** stands: a `SKILL.md` follows the Agent Skills standard and is deployed unchanged.
