# C52 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it.

## Liked

Counting only the body, and turning a warning into data (rules, remedies, required actions by stage), made the standard checkable without Core judging meaning. The shrink-only ratchet, with a byte-identical copy never stale and a variant holding its own recorded words, gave existing oversized Skills a way forward without a blanket exemption. Core judges and reports, and a control keeps the policy.

## Learned

Restructure, never trim: the remedies point at the router, consolidation and references, and the check never asks for fewer words. Exactly 600 words must pass, so the boundary needs its own Case. A DO that adds a payload file or entry point touches many lists (contract asset, catalogue, counts, README, architecture, `verify.json`, publisher test and Engineering's acceptance lists), and the counts in Acceptance are the first to break.

## Lacked

Compatibility with agentskills.io was not verified: the host was unreachable from the environment, and the CPO requires it before promotion. The ratchet's baseline file and the instance, variant and lifecycle for each Skill, taken from C53 evidence, have no owner yet either.

## Longed For

The adopting control, with a baseline and an instance and lifecycle taken from authoritative C53 evidence, and the agentskills.io check run once the host is allowed or the spec is provided. The KAAL-repo-free rule (core/C150) then extends the same check to published Skills.
