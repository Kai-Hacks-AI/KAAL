# Id claims: Intent

This is `core/C251`, a PLAN Change. It ships no code. A DO turns its planned tests GREEN. The id is provisional until Release confirms it.

Change, Case and other ids keep colliding across capabilities. On 28 November C166, C167, C175, C176, C200 and T1740 were each taken twice in one morning, and earlier T1571, T1581, T1597 and T1580 to T1582 clashed the same way. The cause is always the same: a thread takes the next number after the highest one it can see, it sees main and the open pull requests but not the other collectors, and it finds the clash only when real content already carries the number, which costs a renumbering of finished work.

The Owner decided that Core owns the one concept of identity that every capability shares, that an id is claimed before its content, and that the claim travels to main ahead of the content, on Backlog's fast lane. The claims are exact. There are no blocks and no stopgap. Change's draft (change/C250, #3020) is the starting point, and its pure judge and its claim file are reused here.

- **core/I49.** A number of a numbered kind, such as a Change or a Case, is claimed before any content uses it. A claim is a fact of its own: one file for one id, which lands on main ahead of the content and which every capability reads before it takes a number. Core owns the concept and every capability claims against it.
- **core/I50.** A claim is exact. It names one id, never a range or a block, so no capability holds numbers it does not use and nothing is set aside as a stopgap. A number that is claimed and never used stays a gap, and is never reused.
- **core/I51.** Core judges what it is given and holds no list of branches. A second claim of a number cannot land, because the file name is the number and the lane refuses a name that is already there. Core's judge says whether the content used what was claimed, by whom, and whether the claims themselves are well formed.

Not in this Change: the fast lane, its table row, its branch kind, ruleset or workflow (Backlog's and Release's own Changes, and activating the lane is the Owner's go), the folder the claims live in for this repository and its write area (Engineering's adaptation), the control that runs the judge on a Change and the Skill guidance that tells a thread to claim first (Change's), the claims for ids already in use, and withdrawing or renumbering a claim, which is not an addition. Each is named in `core/C251`'s change graph and none is done here. It also decides nothing about the technical identity and the renumbering of `core/C164`: a claim is the durable form of the proposal `nextID` makes there, and the two fit without either waiting for the other.
