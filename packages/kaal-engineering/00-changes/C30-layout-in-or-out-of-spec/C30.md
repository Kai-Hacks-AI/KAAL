# engineering/C30 layout in or out of spec

Makes the layout check (control engineering/CTL2, `verify Layout`) answer in or out of the specification in both directions: it flags what is missing (a part the template marks required) and what is too much (an unnumbered folder or a root file the template does not name). Today it reads only numbered folders, so a folder with the wrong or missing parts can still pass. The template gets a `required` flag on the parts that must be there; the check follows it. The check stays detective: nothing runs it in a job, so no pull request fails, and the first run over every package is the baseline a later ratchet tightens against. No package is migrated and no folder is moved.
