# engineering/C32 CodeQL gate, declared and required

SECURITY.md says that missing or failed CodeQL analysis, and findings above the security threshold, must prevent integration. Today the ruleset rule "Code scanning results / CodeQL" is meant to do that, and it does not: on #2313 it completed after the first upload (javascript-typescript), saw a missing configuration for `actions`, stayed neutral, and the merge rule kept waiting. Nothing declares which configurations are expected; they are implicit in the matrix of `codeql.yml`.

This Change gives the gate one declared, complete check: a job `verify CodeQL` in the `codeql.yml` source, run after every upload, that answers in or out of the specification for the merge-result sha. It then migrates the gate into that check and retires the legacy rule. It is staged so that nothing is enforced before the Owner says so.
