# engineering/F96 workflow-names judge from the default branch

The `verify Workflow names` workflow runs the judge and `judge-mode` from the default branch and not from the base of the pull request, so a pull request into a collector that predates the judge still gets a verdict. It has one checkout, of the default branch, without persisted credentials. The base commit and the head are fetched as Git data and never run. The accepted baseline is the baseline file of the base commit, and the default branch's file where the base holds none, and the step says which one it used. A judge absent on the default branch is UNKNOWN.

**Done when** `13-source/workflows/verify-workflow-names.yml` has one `actions/checkout` with `ref: ${{ github.event.repository.default_branch }}` and `persist-credentials: false`, fetches the base commit and the head as refs, lays the head out with `git worktree add`, writes the base's baseline with `git show` into a file under the runner temp folder with the default branch's file as fallback, passes that file as `--previous`, and runs nothing from the head folder.

This does not stop a pull request from editing the workflow file itself; that is the Inspector's.
