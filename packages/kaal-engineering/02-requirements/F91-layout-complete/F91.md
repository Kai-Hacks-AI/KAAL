# engineering/F91 layout complete

The layout check answers in or out of the specification, in both directions. It flags what is missing: every root file and every folder the template marks `required`. It flags what is too much: every tracked file at the root and every folder that the template does not name, numbered or not. A folder with none of these faults is PASS, and a folder with one is FAIL and names that fault and nothing else. What the template marks required is data in the template, so the check follows it and a change of the template needs no change of the check. A package with no tracked file in a folder the template does not mark required is not faulted for it.

**Done when** a folder that holds `AGENTS.md`, `README.md`, `package.json` and the folders `10-intent` to `14-operations` is PASS, with or without `00-backlog`, `01-changes`, `02-learnings`, `15-defects` and any `*.kaal.json`; a folder that lacks one required root file or folder is FAIL and names it; an unnumbered folder or a root file the template does not name is FAIL and names it; and a template that marks one more folder required makes its absence FAIL with no change of the check.

This amends engineering/F52 and F57 where they say a folder with none of the layout's folders, or with no `14-operations`, is not faulted for it, and where they say an unnumbered folder is not judged.
