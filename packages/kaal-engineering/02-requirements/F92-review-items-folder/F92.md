# engineering/F92 review-items folder

The layout names a folder `review-items` as a child of every folder that holds reviewable subjects: `10-intent`, `11-requirements`, `12-architecture`, `13-source`, `14-operations` and `15-defects`. A Review item sits beside the subject it validates, as a Case sits beside the subject it verifies. The folder holds the Review items `V<n>.md` of that folder's subjects. It is optional: a package with none is not faulted, and no folder becomes required. It is never the `verifiedBy` of anything. `package-layout.md` says what it holds and that a review result worth persisting (`RV<n>`, kept at review's choice, not every review) sits in `02-learnings/reviews`.

**Done when** the template lists `review-items` among the children of those six folders; a package that holds `review-items/V1.md` in each of them is PASS, and so is one with none; and `package-layout.md` names `review-items`, the Review item and `02-learnings/reviews`.
