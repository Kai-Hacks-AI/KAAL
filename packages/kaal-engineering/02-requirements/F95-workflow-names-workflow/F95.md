# engineering/F95 workflow-names workflow

The source of the `verify Workflow names` workflow runs the judge of release's CTL36 on the head of a pull request or a merge queue entry, with the base as the trusted source of every command. It runs on plain `pull_request` and `merge_group` only, with `contents: read`, no token and no secret. It checks out the base commit once, fetches the head as Git data and lays it out in a folder it never executes. It runs the judge, then `judge-mode` in ratchet mode, with the head's baseline as the candidate and the base's baseline as the accepted one; a judge that cannot tell exits 2, and no step makes UNKNOWN pass.

**Done when** `13-source/workflows/verify-workflow-names.yml` has the one job `verify Workflow names` with those triggers, permissions, one base checkout and head as a worktree, the judge step then the ratchet step with `--baseline` under the head folder and `--previous` under the base checkout, and nothing executed from the head folder.


Amended by C35 (F96): the checkout is of the default branch, not the base, and the accepted baseline is the base commit's file with the default branch's as fallback. T1416 no longer pins the checkout (T1423 does) and T1417 no longer pins the `--previous` path.
