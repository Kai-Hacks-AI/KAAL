# engineering/F101 ci workflow runs once per change and cancels superseded pull request runs

The source of the KAAL workflow runs on `pull_request` and `merge_group` only, and its `concurrency` group cancels a run only for a pull request, never for a merge queue entry. Nothing else of it changes.

**Done when** `13-source/workflows/ci.yml` has no `push` trigger, its group is `ci-${{ github.event.pull_request.number || github.sha }}`, its `cancel-in-progress` is `${{ github.event_name == 'pull_request' }}`, and outside those two blocks it equals `.github/workflows/ci.yml`.
