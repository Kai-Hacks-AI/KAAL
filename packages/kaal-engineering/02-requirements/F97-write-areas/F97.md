# engineering/F97 write areas as data

`skills/kaal-engineering/references/write-areas.json` states, for a capability root in the newest layout, which phase (PLAN, DO or ACT) writes which path. It holds rows `{ path, phase }` and a legacy alias list. A path belongs to the phase of the longest row it lies under, matching whole segments with `*` standing for any characters of one segment; a path no row names belongs to no phase. Every folder of the layout and its children resolves to exactly one phase, except `dist` and `14-operations/runs`, which are named as unassigned. Cases in a concern folder (`test-cases`) are PLAN and never DO; the Change folder rows are interim and owned by kaal-change (the folder PLAN, `do.md` DO, `act.md` ACT) until its layout replaces them; a control's `baseline.json` is DO and its record PLAN. A legacy name resolves like its alias.

The file also lists the pull request TYPEs (PLAN, DO, ACT, SYNC, PROMOTION, HOTFIX, WIRE) with the areas each may carry and how it is recognised.

**Done when** the file exists with those rows, aliases and types and T1550 to T1553 are GREEN.
