# engineering/F97 write areas as data

`skills/kaal-engineering/references/write-areas.json` states, for a capability root in the newest layout, which phase (PLAN, DO, CHECK or ACT) writes which path. It holds rows `{ path, phase }` and a legacy alias list. A path belongs to the phase of the longest row it lies under, matching whole segments with `*` standing for any characters of one segment; a path no row names belongs to no phase. Every folder of the layout and its children resolves to exactly one phase, except `dist` and `14-operations/runs`, which are named as unassigned. Cases in a concern folder (`test-cases`) are PLAN and never DO; a Change folder is split by phase: its record `<id>.md` and `plan/` are PLAN, `do/` is DO, `check/` is CHECK and `act/` is ACT, and the flat `do.md` and `act.md` of a Change in flight are two rows marked legacy; a control's `baseline.json` is DO and its record PLAN. A legacy name resolves like its alias.

**Done when** the file exists with those rows and aliases and T1550 to T1552 are GREEN.
