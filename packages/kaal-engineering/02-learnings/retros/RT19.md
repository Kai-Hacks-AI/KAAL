## Proposal: a preventive control for the Cases a DO affects

Follow-up to the CPO's review of the amendment (#2854), where the Owner named the opportunity: a DO must not integrate with affected existing Cases RED. This is a proposal, not a built control; the Owner decides whether and where.

- **What happened:** on the DO (#2849) every check was green, `run Cases` and `observe Cases` included, while T1412 and T1417 were RED. `run Cases` (`controls-act.yml`) runs the Cases of the Changes the pull request carries, here C45's F102. T1412 and T1417 belong to the earlier codeql-gate and workflow-names Changes, which the DO did not carry. Hold Act reads the observation only on an ACT. So nothing judged the Cases the DO affected until the ACT.
- **The gap, in one line:** the Cases that run are the ones the PR carries, and the Cases that can break are the ones that pin what the PR changes.
- **Proposed control:** Preventive, at DO integration. A DO pull request into a collector is judged on the Cases of every capability whose files it touches (all Cases of Engineering for a change under `packages/kaal-engineering/`), and all must be GREEN, except Cases whose expectation a PLAN amendment merged earlier changed. A Case may be RED on the collector's base only if the base is already RED: that is a defect for its own Change, not this one.
- **Cheapest sound version:** no new link from a Case to the sources it reads is needed. Run all Cases of the touched capability. Engineering's Cases ran here in about a minute locally.
- **Who:** Testing owns running and observing Cases; Release owns the wiring and any ruleset change (the Owner's, never the workflow's). Engineering would supply nothing but the rule that a DO into its collectors is covered.
- **Would it have caught this:** yes. Running every Engineering Case on the head of #2849 shows exactly T1412 and T1417 RED, as I found by hand.
- **Not verified:** the cost on the largest capability, and whether Testing already has a runner for a whole capability. I read `controls-act.yml` and not the Testing runner's source.
- **Not asked for:** a ratchet. There is no baseline of accepted RED Cases; a RED affected Case blocks.
