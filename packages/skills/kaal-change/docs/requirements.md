# Requirements

- **change/F38 [change/I19]:** `alters` is a nonempty unique list of owner
  identities matching `namespace/LETTERS<number>`; `scope` is a nonempty unique
  list of capability namespaces. Malformed statements are refused whole.
- **change/F39 [change/I19]:** Use Graph's incoming traversal from altered
  elements for potential impact. Keep selected scope distinct, name impacted
  surroundings and follow outgoing traversal for dependencies. Concern kinds
  include Intent, functional/nonfunctional Requirements, Defects, Architecture,
  Cases and realizations; their meanings stay with their owners.
- **change/F40 [change/I19]:** Inventory both interface directions. Each boundary
  names owned endpoints and exact interface/contract references. Owner-declared
  semantic cross-references remain visible without being invented runtime calls.
- **change/F41 [change/I20]:** Emit incoming-driver, outgoing-controlled-
  collaborator and real-subject obligations. The assessment executes none.
- **change/F42 [change/I20]:** Emit architecture-conformance, capability-acceptance
  and implementation obligations separately, including Defect regressions and
  independent contract/real-integration evidence.
- **change/F43 [change/I19, change/I21]:** Missing sources, owners, elements,
  traces, interfaces or conversion evidence remain named unknowns. Compare
  source-declared relations and actual Graph edges in both directions. No
  authority/completeness flag upgrades source authority.
- **change/F44 [change/I19, change/I20]:** Return deterministic explained
  `isolated`, `violated` or `unknown` model-scoped assessment with findings,
  selected elements, impact, dependencies, boundaries, obligations and source
  digest. Execution is always not assessed; repository authority is unestablished.
- **change/F45 [change/I21]:** Deliver public `/isolation`, its declarations,
  contract, limitations, runnable verification and clean packed-consumer cases.
- **change/N9:** Change orchestrates isolation. Other capabilities retain meaning
  and relationship ownership; Graph alone traverses.
- **change/N10:** The semantic core is pure and deterministic. It reads no files,
  process, clock, Git state, CI jobs, branch names or registry.
- **change/N11:** Complete controlled examples prove model-scoped behaviour.
  Source authority and real integration require independently obtained evidence.
  A matching inventory is not provenance.

- **change/F46 [change/I22]:** Deliver a Core-admitted Change Practice Skill Node
  and a discoverable, relocatable `kaal-change` Agent Skill with BASS guidance
  for supplied-model isolation. Follow the Agent Skills standard through Engineer
  Skill's checker; let Core alone decide Node admission.
- **change/F47 [change/I22]:** Guide the agent through proposal, concern tracing,
  boundary analysis, multi-loop TDD and calibrated evidence reporting. Supply a
  runnable controlled example using the public isolation API, including omission
  and new-dependent challenges. Examples establish no target repository coverage.
- **change/F48 [change/I22]:** Deliver version 0.0.1 for exactly the documented
  isolation/skill contract; inventory and verify every shipped skill resource and
  demonstrate installed Embed registration and External operator use. This does
  not declare completion of the older full Change release programme.
- **change/N12:** The host chooses discovery and authorized target interfaces.
  External use keeps KAAL in the operator environment and does not install it in
  or alter the target. No instruction or example upgrades source authority,
  unexecuted obligations, Owner approval or CI/release authorization.

- **change/F49 [change/I23]:** Declare Foundation, Graph and Hosting at their
  exact required production versions. A fresh consumer requesting only Change
  must obtain verification providers through dependency resolution and run every
  declared delivered Case. Independently checked local-tarball overrides may
  qualify artifact transport; registry availability remains a separate gate.
- **change/N13:** Verification installs no dependencies and never weakens its
  required Case inventory to compensate for an unavailable provider. The pure
  isolation module still imports only Foundation and consumes a caller-supplied
  Graph view. Required package dependencies do not confer source authority.
