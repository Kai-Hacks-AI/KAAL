# Limitations

Version 0.0.1 delivers Change Practice and supplied-model isolation. The broader
lifecycle/delivery programme remains outside this version.

- Source completeness and provenance are unestablished. A self-consistent partial
  model cannot prove no omitted repository dependency exists.
- Source projection and interface classification are supplied by owners. Change
  cannot mechanically prove the owner's semantics or that an external adapter
  read every relevant source.
- Graph's public provider is trusted for graph mechanics. Passing an arbitrary
  forged provider does not establish Graph conformance.
- Unknown owner view/Graph failures remain findings. No parser for arbitrary
  prose, npm metadata, paths or CI workflows is included.
- All testing obligations are unassessed references. The API executes no subject,
  double or test and authenticates no run record.
- Delivered charging/provider fixtures demonstrate discrimination in a controlled
  example. They establish no compatibility with actual external services.
- Verification manifests are unsigned consistency inventories, not publication
  provenance. Installed verification needs the declared required Graph/Hosting providers.
- Architecture inspection reports its exclusions and undecidable constructs;
  clean mechanical findings do not establish semantic responsibility conformance.
- Testing's acceptance ledger reports physical containment and absence of
  unrecorded installations as unknown under its existing contract.

Engineering retains repository/CI admission. No selective CI, workflow, branch
protection or release authorization follows from this package.

- The rudimentary Agent Skill is guidance plus a controlled runnable example. It
  does not acquire a real repository model, generate mocks, execute target tests,
  or mechanically enforce that an agent follows the workflow. Installed resource,
  relocation and admission checks are narrower than real-agent effectiveness.

- Exact Foundation, Graph and Hosting versions must be available before a public
  registry-only install can succeed. Local-tarball installation evidence is not
  registry acceptance or a substitute for the release readiness gate.
