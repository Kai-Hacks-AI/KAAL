# Intent ownership and the traceability chain: Architecture

- **intent/A1. One direction.** The chain is a set of one-way references, each stated at the source side by the owner of the relationship: Requirement → Intent in the Requirement's Node, and so on. Intent holds no outgoing reference. Incoming views are derived by Graph's `traverse(…, { direction: "in" })`, never stated [intent/I5].
- **intent/A2. Instances stay with their consumers.** Intent defines the type and the name rule. A capability's Intents live under that capability. The map in `requirements.md` lives here only as documentation; it is not a registry, index or store, and no script reads it [intent/I4].
- **intent/A3. Registration is the discovery route.** If the chain is ever to be reported rather than documented, the route is Core's Registration (kinds with owner-defined outgoing rules, derived incoming views), through each owner. Intent registers its own kind and rule only when a DO needs it, and Core stays semantically empty [intent/I3].
- **intent/A4. Where the work lands.** This PLAN is a pull request from a working branch into `kaal/intent`, squash-merged. It claims one Change Record, `.kaal/changes/intent/26/11/02/01/`. It touches only Intent's paths and that record [intent/I3].
