# Intent elements as Nodes: Requirements

- **intent/F1. An Intent element is a Node** [intent/I1]. Each Intent element a capability states, such as `graph/I7`, can be held as a Node typed by Intent's existing Definition, `Intent` (`payload/Intent-Definition.md`). Its body is the Intent's own text, self-contained as the `Intent` Skill Node requires. It has no Edges out: an Intent exists without any Requirement, Change or conversation, so it never points at them.
- **intent/F2. Intent identification** [intent/I1]. An Intent element's Node name is `<capability>/I<n>`, where `<capability>` is the owning capability's short name and `<n>` a positive integer. The owning capability assigns `<n>` and never reuses it for another Intent. The name is valid under Graph's Node name rule. It is unique within an Engine. Its id is the Node's content identity, as for every Node.
- **intent/F3. The owning capability holds the instance** [intent/I1]. An Intent element's Node belongs to the capability whose Intent it is, under that capability's location, as Requirement instances belong to their consuming capability. Intent defines the type and the identification. It holds no other capability's Intents.
- **intent/F4. Incremental, not at once** [intent/I1]. An Intent element becomes a Node when a Change first states it as changed, or when a `Serves` Edge first needs it as a target, whichever comes first. Until then, its bracket citations stay as they are. Nothing is migrated in bulk.
- **intent/F5. An edit re-pins its servants in the same Change** [intent/I1]. An Edge is pinned to its target's id, so editing an Intent gives it a new id. A Change that edits an Intent re-pins the `Serves` Edges of the Requirements that serve it. Those Requirements lie in that Change's computed impact anyway. Graph's `check()` reports any Edge left pinned to the earlier version, which is drift detection, not an error in traversal. Engineering computes impact on the target's Nodes, where the pins agree.
- **intent/F6. Intent's location is claimed** [intent/I2]. `packages/skills/kaal-intent/ownership.kaal.json` claims `packages/skills/kaal-intent/` for Intent. It names Intent's Skill Node `Intent` by name and id, in the format the other capabilities use and #609 kept (machine-oriented JSON, no migration).
- **intent/N1. No deriver, no scripts** [intent/I1]. No script parses bracket citations into Edges. The trace is stated once, as an Edge in the Requirement's Node, and Graph reads it.
