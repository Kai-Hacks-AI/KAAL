# Intent product plan: Intent

> PLAN (`intent/C4`). It ships no code, Node or test, and authorizes no synchronization, promotion, version change or npm publication. It gives Intent the product plan the Owner's work rule asks of every capability, so that Intent's next changes are known and a blocked PR is not mistaken for a blocked capability (a capability is blocked only when every change in its plan is). It follows `intent/C3` (#892) and starts none of the implementation in it.

- **intent/I6.** Intent states its own next changes, in order, each with what it needs from other owners, so at any time Intent is working on a PR, waiting for review, or fully blocked, and the reason is visible on the PR.
- **intent/I7.** Readiness is not authorization. Each change below is a candidate; the Owner or CPO releases it. Nothing here publishes `kaal-intent`.

## Where Intent stands

Delivered on `kaal/intent`, not on main: the `Intent`, `IDEA` and `I WON` Definitions, the Skill, the Node form for an Intent element (`intent/C1`, `C2`) and the ownership claim. In review: the ownership and traceability PLAN (`intent/C3`, #892, CPO-approved). The package ships Nodes and an Agent Skill, with no runtime dependency beyond its dev dependencies.
