# Contracts and coverage

Branching is a KAAL product capability. Engineering consumes it when engineering KAAL. The approved product Intent, Requirements, Architecture and 38 planned Cases are recorded in [PLAN #797](https://github.com/Kai-Hacks-AI/KAAL/pull/797) and [External clarification #801](https://github.com/Kai-Hacks-AI/KAAL/pull/801).

The installed pure implementation is authoritative for configuration and classification. Skill prose, scripts and test adapters do not choose transaction policy independently.

This candidate verifies configuration structure and classifies supplied commit observations. It does not authenticate those observations or the selected runtime, establish consumer policy authority, prove merge-tree preservation or provide a live enforcement gate. Existing repository CI remains authoritative during product migration.

Package, Configuration and Boundary are separate assurance contracts. Input and runtime-source digests identify observed bytes; they do not establish trusted provenance or the integrity of the full dependency graph.

Skill Node admission through Core and the complete release acceptance remain pending. Passing Engineer Skill's Agent Skill format checker is narrower than either of those obligations.
