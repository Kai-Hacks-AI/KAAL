# Hosting Usage Skill: Requirements

Each requirement traces to hosting/I14. Existing operation semantics remain owned by hosting/F1–F14 and F45–F55; this Change does not redefine them.

- **hosting/F57** [hosting/I14]: **Discoverable usage Skill.** The package ships `skills/kaal-hosting/SKILL.md`, named `kaal-hosting`, with an Agent Skills description identifying selection and use of Hosting operations, their failures, installation verification and boundary results. It identifies Hosting as an Extension and directs agents to the installed product's authoritative contracts. It requires no repository, pre-existing Engine, global installation or particular agent host. No new Skill Node, Engine mutation or registration protocol is introduced by this Agent Skill.
- **hosting/F58** [hosting/I14]: **Choose an operation.** Guidance distinguishes tree reads (`read`), single-file reads (`readFile`), path inspection (`kind`, `within`), initialization of missing/empty directories (`initialize`), whole-directory publication (`update`), guarded file changes in an existing directory (`reconcile`), installed-command execution (`execute`) and the Extension contribution (`contribution`). It explains how a consumer finds the package's ESM exports and declarations, with executable examples of initialization/readback, guarded reconciliation and command execution. Examples use the scoped public package, take caller-supplied scratch roots and leave unrelated content intact. No OS decision or direct filesystem replacement of a Hosting operation is taught.
- **hosting/F59** [hosting/I14]: **Preserve failures and authority.** Guidance distinguishes a stale precondition, a refused path, observed apply failure with rollback, `UNRESTORED` recovery, and reported `leftovers`. It does not turn a stale result into unconditional replacement, silently retry an uncertain write, remove kept recovery originals or claim crash atomicity, physical containment or protection against uncooperative writers. A requested mutation still needs the consumer's authorization; the Skill supplies no additional authority. Recovery instructions preserve evidence and use PREACH when judgment or authority is missing.
- **hosting/F60** [hosting/I14]: **Calibrated verification.** The Skill uses the existing installed command `npm explore @kaihacksai/kaal-hosting -- npm test` and preserves `verified`/0, `failed`/1 and `cannot verify`/2. It distinguishes successful deterministic boundary cases from open review requests and the boundary command's separate exit vocabulary. It routes review to the existing boundary Skill by its discoverable name. Manifest consistency is not provenance; skipped/unrun cases are not passes; repository tests, installed tests, promotion and publication are separate facts.
- **hosting/F61** [hosting/I14]: **Portable package resources.** Every relative file reference in the general Skill resolves inside its own directory. Required examples and references ship with it and remain usable after the Skill directory is copied to another location. Locate authoritative package docs through the installed package identity, not a relative escape from the relocated Skill or a repository path. No new export, bin, runtime dependency, filesystem guarantee or Core requirement is added.
- **hosting/F62** [hosting/I14]: **Evidence for the delivered Skill.** Publisher checks validate the packaged and relocated Skill with the existing Engineer Skill checker. Consumer cases execute examples extracted from the actual shipped resources against the installed Hosting package; a separately rewritten example is not evidence for the shipped one. Installed verification includes the new delivered Cases and hashes the new resources. Structural validation, deterministic workflow execution and review of agent guidance are reported separately; none alone proves an arbitrary agent will choose correctly.
- **hosting/N8** [hosting/I14]: **Preserved assurance.** Retain existing planned assertions, operation tests, publisher regressions, verification outcomes and all mandatory CI. Record assertion RED before implementation GREEN and designated negative challenges. The new examples and Cases run on Linux, macOS and Windows with no new platform skips. Existing contracts explicitly allocated to publisher tests or unverified remain so; do not relabel them as covered by prose.
