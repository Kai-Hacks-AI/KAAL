# hosting/C118 Hosting states the revisions of a run

Release/D20 recurred in three checks: the evidence of check 1, check 2 and check 4 named `GITHUB_SHA`, which on a `pull_request` run is the test merge commit, and not the head the pull request names. Each caller repaired its own line, and nothing common stops the next one. Kai asked that evidence identify what was examined and not what triggered execution, as a common contract and not each caller's responsibility. Testing owns the meaning and the check (testing/C84, #2881: `checkRevision({ recorded, judged, trigger })`).

The Owner's boundary for this Change: Hosting provides facts; someone else checks. Hosting states, as distinct facts, the head the event names, the revision of the trigger, the commit the checkout actually holds and the relations between them. It does not infer what was examined from the event, and it does not declare a merge checkout equivalent to the head of the pull request for evidence. What was examined, and whether evidence is about it, is established by the consumer and checked by Testing. The CTO side owns the implementation.

Hosting owns it because reading the event of a run and a working copy is platform mechanics (the layers: platform mechanics are Hosting's, shared semantics Foundation's, and a capability such as Controls never implements them). This Change starts no implementation and changes no record of Release, no check of Testing, no workflow and no ruleset.
