# hosting/C174 Hosting approves a pull request as an App at a named commit

The KAAL Approver App (Review, C8) approves exactly one kind of pull request: a `SYNC:` pull request whose `verify Sync` passes at its head. Today the Sync bot approves it with the shared workflow token, which draws on the one installation budget and acts with the permissions of the whole workflow. Hosting's C114 maps the ability `approve-pull-requests` to the permission Pull requests: write, but offers only reads and the raise: no call posts a review, so the Approver's workflow would have to write the request, the headers and the reading of the answer itself. This Change plans the one call that is missing. It succeeds hosting/C117 (the same shape: one POST under a grant, GitHub's answer verified, a fact Hosting made) and starts no implementation.

Hosting decides nothing here: whether to approve is Review's rule (review/F40, F41 and A5), the Approver's key and the App's installation are the Owner's, and the Sync approval's workflow is Release's (release/C173).

Provisional ids: C174, hosting/F114, A51, and T356 to T359 (serving hosting/I22). They are checked against `main` and every remote branch: the C118 collector holds I25, F113, A50 and T349 to T353, the C169 collector T354 and T355; Release's C172 and C173 are not Hosting's.
