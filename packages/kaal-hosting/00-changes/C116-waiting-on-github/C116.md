# hosting/C116 Hosting owns the mechanics of waiting on GitHub

Kai ruled on 27 November 2026 (relayed by the Controls thread) that Hosting owns the mechanics of waiting on GitHub: a bounded retry with growing backoff, detection of a refused read (a 403 for the rate limit, a 429, a 5xx), honouring the time GitHub gives, and a rate-limit log before and after a job. The seed is Release's C164 script (`wait-for-checks.mjs` on the collector `kaal/release/merge-group-review-events`), which holds `schedule(n)`, the refusal test and the retry loop. Release keeps the judgment (`groupState`) and calls Hosting's library; Controls exposes it.

This Change plans the first three: a pure poll schedule, a refusal test and a retry wrapper over a read function. They need no grant and no GitHub account, so they do not wait on C114. The rate-limit log reads GitHub through a grant and therefore follows C114 on main; it is a separate Change planned then. This Change starts no implementation and moves no code out of Release.

Provisional ids: C116, hosting/I24, F108 to F111, A48, and T341 to T344. They are checked against `main` and every remote branch (highest on `main` today: C115, I23, F105, A46, T335; the C114 collector holds F106, F107, A47 and T336 to T340).
