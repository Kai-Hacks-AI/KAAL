# hosting/C118 Hosting resolves the revision a run judges

Release/D20 recurred in three checks: the evidence of check 1, check 2 and check 4 named `GITHUB_SHA`, which on a `pull_request` run is the test merge commit, and not the head that was judged. Each caller repaired its own line, and nothing common stops the next one. Kai asked that evidence identify what was judged and not what triggered the run, as a common contract and not each caller's responsibility. Testing owns the meaning and the check (testing/C84, #2881: `checkRevision({ recorded, judged, trigger })`). It takes the judged revision and the trigger as input and reads neither Git nor the environment. This Change is the other half: the one place that says what a run judged, and where that came from. It reads the event of the run and not the variable of the trigger, and it can tie the answer to the checkout, so that no caller reads `GITHUB_SHA` for evidence.

Hosting owns it because reading the event of a run, and a working copy, is platform mechanics (the layers: platform mechanics are Hosting's, shared semantics are Foundation's, and a capability such as Controls never implements them). It starts no implementation and changes no record of Release, no check of Testing, no workflow and no ruleset.
