# hosting/C118 Hosting states the content and provenance of a run

Release/D20 recurred in three checks: the evidence of check 1, check 2 and check 4 named `GITHUB_SHA`, which on a `pull_request` run is the test merge commit, and not the head the pull request names. Each caller repaired its own line, and nothing common stops the next one. Kai asked that evidence identify what was examined and not what triggered execution, as a common contract and not each caller's responsibility. Testing owns the meaning and the check (testing/C84, #2881: `checkRevision({ recorded, judged, trigger })`).

The Owner's boundary for this Change, in two steps. First: Hosting provides facts; someone else checks. Second, from the CPO's review: content identity takes precedence over Git commit identity. Hosting provides the actual content and its identity, plus the provenance (Git commits, paths, events and their relationships) as separate facts. A commit or parent relationship alone does not establish that two examined contents are identical, and a Git SHA does not substitute for content identity. The consumer and Testing determine what content was examined and check evidence against it; Hosting does not judge. Git is an adapter detail of the provenance. The CTO side owns the implementation.

Hosting owns it because reading the files of a working copy, the event of a run and the Git of a checkout is platform mechanics (the layers: platform mechanics are Hosting's, shared semantics Foundation's, and a capability such as Controls never implements them). This Change starts no implementation and changes no record of Release, no check of Testing, no workflow and no ruleset.
