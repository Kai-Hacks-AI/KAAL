# Architecture and the choice

## Options

1. **Keep consumers on 0.0.1** (workspace 0.0.2). Rejected. npm cannot satisfy an
   exact 0.0.1 from a 0.0.2 workspace, so it installs a nested registry 0.0.1
   beside the workspace copy. That breaks C15's single-candidate guarantee and the
   Core "no nested node_modules" assertion, and is the "Missing from lock file"
   failure observed in the earlier #838 run.
2. **Move the three pins to exact 0.0.2** with the workspace, update the two
   assertions, and regenerate the root lock. Recommended. The workspace link
   satisfies 0.0.2 locally, so `npm ci` does not depend on the registry. This is
   not circular: published Core/Change/Testing then require Foundation 0.0.2, which
   matches the already agreed publish order (Foundation reaches npmjs first, and
   Core/Hosting need not be published first for Foundation).

## Constraints that remain (decision needed)

- The version bump (C16) and the pin bump must land on `main` together, or `main`
  breaks between them. Core travels alone under the trusted-main isolation checker
  today, so a combined Foundation + consumers delivery needs Engineering's
  independently accepted admission route (or an explicitly governed bounded
  sequence). #833 does not by itself authorize it.
- Root lock: generated by Engineering's accepted dependency route; never
  hand-edited.
- Core's bootstrap behaviour and its regression tests stay unchanged. Nothing
  weakens the nested-copy assertion or the acceptance ledger.
