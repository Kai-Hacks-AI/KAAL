# Architecture tree: Requirements

Each Requirement names, in brackets, the Intents it serves.

## Functional

- **foundation/F38** [foundation/I15]: **Architecture is a tree with two branches.** `03-architecture/architecture.md` has exactly two top-level branches, `## Solution` and `## Delivery`. Every Architecture element (`foundation/A<n>`) is defined under exactly one of them. An element defined under both, under neither, or twice is refused. Each element states the Requirements and Intents it answers. Elements are the leaves: an element is Solution or Delivery and never both.
- **foundation/F39** [foundation/I15]: **A Case's branch is derived, never declared.** A Case verifies a target, and the target is answered by Architecture elements. A target answered only by Solution elements makes the Case Solution; only by Delivery elements, Delivery. A target answered by elements in both branches is a **cross-cutting Requirement or Intent**, and it is listed as such. A Case that targets leaves in both branches without such a listed target must be split, one Case per branch. A target answered by no element is an orphan. A Defect names the one Architecture element it is found against and takes that element's branch, and its Cases sit beside it in `06-defects/`. Every Case has an id and targets in the title form `foundation/T<n> [<targets>]: <what it checks>`, wherever it lives.
- **foundation/F40** [foundation/I15]: **Cases sit beside what motivated them, and suites hold none.** A Case file sits in the folder of the Node it verifies. Delivery Cases sit in a `delivery/` folder beside that Node; Solution Cases do not. No `04-test/*-check/` folder holds a Case. They hold mechanisms (the build, the collector, the verification runner, the scan) and by-reference lists. A planned RED Case may stay in `04-test/engineering-check/plan/` until its DO moves it beside its Node.
- **foundation/F41** [foundation/I15]: **The build ships the Solution branch only.** A folder named `delivery` is never copied into `dist/`, and a Delivery Case never ships.
- **foundation/F43** [foundation/I15]: **Pointers are data, and suites are computed from them.** What a Case verifies is declared in YAML by the Case, as the id of the Intent, Requirement, Defect or Architecture element it points at, and is not parsed out of a title. A suite is the answer to "which Cases point at the elements of this branch?". The manifest's `cases` and `model` are generated from the same pointers. The Owner's ruling of 2026-11-09: each Case carries a `tests` edge in its own YAML front matter, pointing at the Defect, Requirement, Intent or Architecture element it verifies (defect <- test case). Suites are derived backwards from these edges. A Case file holds the front matter itself (a JavaScript Case in a leading comment block), and a Case without a resolvable edge is refused.
- **foundation/F42** [foundation/I15]: **Suites pull by branch.** The shipped verification (`npm test`) runs the Solution Cases found beside the Nodes. The engineering suite (`npm run test:publisher`) runs the Delivery Cases found in the `delivery/` folders, collected by the same collector and not by a hand-kept list of files.

- **foundation/F44** [foundation/I16, foundation/I15]: **Misplaced things are named, not hidden.** The Architecture has a section "Placed here, belongs elsewhere". Each entry names an element, or a Case, that is implemented in this package but belongs to an outside package, the package it belongs to, and, the Packaging Case or Requirement it relies on, which a suite in Foundation's `04-test/` collects by reference. The reference points from Foundation to Packaging and never the other way: no Packaging element names Foundation. The suite is Delivery: it never ships, and the package declares no dependency on Packaging (foundation/N2). The entry stays until the owner lands, and the Case keeps its Delivery branch meanwhile. No entry is a Foundation Requirement.

## Non-functional

- **foundation/N23** [foundation/I15]: **Either/or, with nothing silent.** An orphan Case, an untitled Case, an element in no branch, a Case that verifies leaves in both branches without a listed target, and a Requirement or Intent answered in both branches but unlisted each fail the check. The `## Cross-cutting` section of the Architecture lists those Requirements and Intents, each with the reason both branches answer it. It lists no Case and no element.
- **foundation/N24** [foundation/I15]: **No new reach.** The tree check and the collector use only Node's built-in modules. Nothing ships beyond what the Solution branch already ships.
