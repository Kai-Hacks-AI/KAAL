# architecture/F18 placement-check

Inside the observation boundary of architecture/F15, Architecture checks each placement and gives each reference one verdict. A `places` entry that is not a well-formed Defect id, a `fixOwner` that is not a well-formed capability name, and a Defect with two placements are INVALID. A Defect id whose namespace is observed and holds no such Defect is INVALID; one whose namespace is not observed is UNKNOWN and is never reported as invalid. The check is detective: it reports and does not block. It resolves nothing across packages and does not judge whether the place is the right one.
