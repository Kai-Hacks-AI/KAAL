# architecture/F15 addresses-a-requirement

The check works inside a stated observation boundary: the A-records and Requirement records present in the files it is given, grouped by capability namespace. A namespace is observed when its Requirement records are among those files. Every reference in an A-record's `addresses` gets one verdict:

- **resolved**: the id names a Requirement (an F or an N) in an observed namespace.
- **INVALID**: the id is malformed, or its namespace is observed and holds no such Requirement. An A-record whose `addresses` is empty or missing is INVALID as a whole.
- **UNKNOWN**: the id is well formed but its namespace is not observed, so the available evidence cannot say. Capabilities can be deployed independently, so this is not an error.

The check reports INVALID and UNKNOWN separately, each by the A-record's id and the reference, and never reports an UNKNOWN reference as invalid. It is detective: it reports and does not block. It judges form and resolution only, not whether a placement is a good one: whether a Requirement is met is Testing's conformance loop and Review's judgement. Resolving across packages is not required in this Change.
