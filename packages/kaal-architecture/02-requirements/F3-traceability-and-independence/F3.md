# architecture/F3 traceability-and-independence

The order is requirements, classification, target-state placement, gap identification, Change planning. A target-state element has a Gap where the baseline differs from it, and each Gap has exactly one closing Change.

A dependency is an edge between Changes that still travel separately, never a reason to merge independent concerns into one Change. **Invariant:** Solution and Delivery travel independently through their own Changes. A Delivery Change cannot weaken or redefine the Solution contract it delivers, so it leaves the Solution's requirements, verdicts and Cases unchanged. If delivering seems to need otherwise, a Solution Change lands first.
