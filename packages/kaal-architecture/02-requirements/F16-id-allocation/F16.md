# architecture/F16 id-allocation

Given the A-records observable in the files it is given, Architecture suggests the next A-number of a capability as one more than the highest observed in that namespace, or 1 when none is. The suggestion rests on what is observed only. It does not promise that an id is never reused after retirement, deletion, migration or correction, and it does not judge a correction or migration that changes an id. Stable identity over the lifecycle (allocation, retirement, migration and correction made explicit and traceable, referential integrity, fail-safe handling) is a separate concern for a later Change and is not claimed here.
