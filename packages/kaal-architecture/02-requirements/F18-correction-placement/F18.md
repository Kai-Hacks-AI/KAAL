# architecture/F18 correction-placement

A Defect has four dimensions, in this order. **Found** is where it showed up, for example in operations: the Defect record with its Test Cases, owned by Defect and Testing. **Born** is the level on the V where it originated, from intent, requirements, architecture, code, test or operations, and is judged by Review, not by Architecture. **Placed** is the architecture component or building block, a KAAL component or an external one, where the correction happens. **Fixed** is that same place: where a Defect is fixed follows from where it is placed and is not a separate choice.

The Architecture record that addresses a Defect is its placement. It is informed by Born and is not an assignment to where the Defect was found. If the Defect was born in code, the architecture stands and the placed component's code is corrected to it. If it was born in architecture, the placing record is itself re-judged and changed, and the code is then judged against it again. If it was born further up, in requirements or intent, the correction starts there and the placement follows it. Architecture records no Born and no Fixed.

From a Defect, the records that address it are found by a derived reverse lookup over the records observed; the Defect carries no pointer and is not rewritten. A Defect that no observed record addresses is unplaced: no place is assumed for it. Whether the placement is the right one is for review, not for this check.
