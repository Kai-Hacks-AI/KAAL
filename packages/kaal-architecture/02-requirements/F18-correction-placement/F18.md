# architecture/F18 correction-placement

A problem has four dimensions, in this order, each held by its own object. **Found** is the finding, where it showed up, for example in operations: external input raised by Review, not a KAAL artifact. **Born** is the level on the V where it originated, from intent, requirements, architecture, code, test or operations: it is what the accepted Defect and the Test Case that proves it establish, and both are owned by Defect and Testing. **Placed** is the architecture component or building block, a KAAL component or an external one, where the correction happens: the Architecture record that addresses the Defect. **Fixed** is the Change, with whatever else is needed, that makes the correction at the placed component; where it is fixed follows from where it is placed and is not a separate choice.

The placing record is informed by Born and is not an assignment to where the problem was found. If the Defect was born in code, the architecture stands and the placed component's code is corrected to it. If it was born in architecture, the placing record is itself re-judged and changed, and the code is then judged against it again. If it was born in requirements or intent, the correction starts there and the placement follows. Architecture records no Born and no Fixed.

From a Defect, the records that address it are found by a derived reverse lookup over the records observed; the Defect carries no pointer and is not rewritten. A Defect that no observed record addresses is unplaced: no place is assumed for it. Whether the placement is the right one is for review, not for this check.
