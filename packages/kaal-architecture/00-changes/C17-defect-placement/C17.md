# architecture/C17 defect-placement

Lets Architecture do for an accepted Defect what it already does for a Requirement: address it, so that the record is the functional placement of the correction.

## Baseline

`main` holds the record mechanics (F14 to F16, `lib/records.mjs`): an A-record's `addresses` may name only a Requirement, an F or an N. A Defect today is a record of the capability that found it, for example `hosting/D14`, with its Test Cases.

## The four dimensions and their objects

| Dimension | Object | Owner |
| --- | --- | --- |
| **Found**: where it showed up | the finding, external input from a human, an agent or a control | raised by Review; not an instruction, not a KAAL artifact |
| **Born**: the level where it originated (intent, requirements, architecture, code, test, operations) | the accepted Defect and the Test Case that proves it | Defect and Testing; only an accepted Defect becomes a subject of KAAL |
| **Placed**: the architecture component, KAAL or external, where the correction happens | an A-record that `addresses` the Defect | Architecture |
| **Fixed**: where the correction happens, which is where it is placed | the Change, with whatever else is needed | Change |

Born comes before Placed. Born in code: the architecture stands and the code is corrected to it. Born in architecture: the placing record is re-judged and changed, then the code is judged against it again. Born in requirements or intent: the correction starts there and the placement follows. The lifecycle and the authority boundaries are the same in a hotfix, which can carry PLAN and DO in one pull request, and in a collector, which can split them across pull requests.

## PLAN

Adds I3, F17, F18 and N3, and the Cases T27 to T29. F17 widens what `addresses` may name to an accepted Defect. F18 states the order Found, Born, Placed, Fixed, that Born is what the Defect and its proving Test Case establish, that the addressing record is the placement and Fixed follows it, and that a Defect addressed by none is unplaced. The special `places`, `origin` and `fixOwner` fields and `placement.mjs` of the earlier head are dropped. The Cases are red: T27 fails because `checkAddresses` rejects a Defect id, T28 and T29 because `addressing` is not yet exported. The DO changes `lib/records.mjs` only: accept a Defect id in `addresses`, and add `addressing(id, records)`, the derived reverse lookup.

## Open questions for the CPO

None open. Where Born is recorded is settled: it is the Defect and its Test Case. This Change reads no Born and checks no consistency between Born, Placed and the Change that fixes it.

## What this Change does not do

It changes no Defect record in any package, raises, judges or proves no finding and accepts no Defect, does no fixing, execution, CI or workflow orchestration, adds no Control and no gate, and resolves nothing across packages.
