# architecture/C16 record-mechanics

Gives Architecture the first mechanics of its own records: the form of an A-record, the check that it addresses a Requirement that exists, and the allocation of the next id. Today no capability owns them: A-records live in each package's `03-architecture` folder and are numbered by hand, and nothing validates that they address a Requirement.

## Baseline

`kaal/architecture/classify` at `f4e3797` holds the Skill that classifies statements as Solution or Delivery (I1) and no mechanics for records. `controls/A5` and `foundation/A7` show the form this Change makes explicit. The metamodel Change in review (#1975) defines Architecture as an object with relations, but only as a definition.

## PLAN

Adds I2, F14 to F16 and N2, and the Cases T23 to T26. The Cases are red. They wait for the DO: `lib/records.mjs` with the reader, the check and the allocation, and a thin command.

## Open questions for the CPO

1. Does the check read `addresses` itself, or does Architecture wait for Graph to interpret it as an Edge? This PLAN reads it itself, so the package stays standalone (N2), and leaves the move to Graph for later.
2. Which Requirement records count as resolved when the target is in another capability's package: only those in the same repository, as F15 says. Cross-package resolution through an installed package is not planned.

## What this Change does not do

It rewrites no A-record in any package, introduces no Control and no gate, and does not judge whether a placement is good. It does not change the classification Skill.
