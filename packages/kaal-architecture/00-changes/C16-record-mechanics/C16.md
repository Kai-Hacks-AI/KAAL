# architecture/C16 record-mechanics

Gives Architecture the first mechanics of its own records: the form of an A-record, a detective check that it addresses a Requirement, and a suggestion of the next id. Today no capability owns them: A-records live in each package's `03-architecture` folder and are numbered by hand, and nothing validates that they address a Requirement.

## Baseline

`kaal/architecture/classify` at `f4e3797` holds the Skill that classifies statements as Solution or Delivery (I1) and no mechanics for records. `controls/A5` and `foundation/A7` show the form this Change makes explicit. The metamodel Change in review (#1975) defines Architecture as an object with relations, but only as a definition.

## PLAN

Adds I2, F14 to F16 and N2, and the Cases T23 to T26. The Cases are red. They wait for the DO: `lib/records.mjs` with the reader, the check and the suggestion, and a thin command.

## Boundaries this Change states

- **Observation boundary (F15).** The check sees only the files it is given. A reference is resolved, INVALID (malformed, or its namespace is observed and the Requirement is absent) or UNKNOWN (its namespace is not observed). An absent Requirement in an unobserved namespace is never reported as invalid.
- **Next id is not stable identity (F16).** The suggestion is derived from the observed records. It does not promise that an id is never reused. Stable identity over retirement, migration and correction, with referential integrity, is a separate lifecycle concern and is not decided here. An explicit, traceable change of an id is not an error; a silent change of meaning is what that later concern must prevent.

## Open questions for the CPO

1. The check reads `addresses` itself so the package stays standalone; moving it onto Graph Edges is left for later.
2. Ids I2, F14 to F16, N2, C16 and T23 to T26 are the next free on this collector. They are not yet checked against the parked package; Case T22 does that in the DO.

## What this Change does not do

It rewrites no A-record in any package, introduces no Control and no gate, resolves nothing across packages, promises no stable identity, and does not judge whether a placement is good. It does not change the classification Skill.
