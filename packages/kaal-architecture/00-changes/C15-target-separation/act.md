# C15 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it. It claims no validation of the Skill and no promotion.

## Liked

The CPO's distinction between Target Cases and Change Cases. It turned a vague unease about a red Case into a rule I could test: T21 fails if a Target Case reads a trial, the key or a file under `00-changes`. Keeping the historical T3 as a file the runner cannot pick up, with its red output beside it, let me make the Target green without rewriting what happened.

## Learned

My first T21 would have failed on itself, because its own source names the files it forbids. I only saw it when running the Cases, not when reading them. The Skill's three rules (Mixed, Constraint across the line, Ambiguous) and the next move had no Case of their own; the key had been standing in for them. T18 to T20 now check that the Skill says them. They cannot tell whether an agent follows them.

## Lacked

A cheap way to see which Cases a collector's tree relies on before moving files. I found the imports by reading them. I also lacked the owner of the parked package's identifiers: I avoided T2, T3, F5 and C7 by choosing numbers above its maxima, not by asking anyone.

## Longed For

A runner that tells Target Cases from experimental ones, so the Target can be run alone. The runner now walks both and they are told apart by folder only. Several runs per arm of the trial, so that a future Change can move what has been learned into the Target on evidence.

## Open

The Target Cases are static contract and structure checks. They do not show that an agent classifies well, and nothing here shows the Skill beats a baseline. The three files on main that cite the parked package's ids are untouched, since they belong to other capabilities. The ids T2, T3, F5 and C7 of the parked package remain unresolved there. This ACT claims no acceptance and no closure.
