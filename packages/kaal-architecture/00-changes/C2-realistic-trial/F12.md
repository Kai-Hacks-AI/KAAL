# architecture/F12 realistic-trial

The Skill is tried on five realistic requests of this project, on agent hosting, Review installation, Pull Promotion, incident reporting and Testing and Review integration, at least two of which deliberately mix an architecture concern with an instruction to move from one state to another. An agent with the Skill and an independent agent without it are asked the same questions: which parts are Solution, which are Delivery, which are about the architecture description itself, which are mixed, which decisions are unresolved, and which work belongs to Change. The Solution and Delivery themselves are not architecture: Solution Architecture and Delivery Architecture are the descriptions of them, and a request can speak of either. At least two requests also speak of the architecture description itself, so that the trial can show whether an agent keeps the description apart from the thing it describes. The architecture boundary is stated to both arms in the same words. Raw outputs and provenance are preserved. There is no answer key, and the author does not change the requests after the run. Evidence integrity and observable behavior are verified by Cases; fitness for purpose and the comparison are left to independent Review.
