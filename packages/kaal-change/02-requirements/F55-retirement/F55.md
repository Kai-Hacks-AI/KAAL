# change/F55 retirement

A derived, detective control judges the deletion of a Change's `kaal-guard.json`. It applies only when a diff deletes one. It fails unless the folder holds `act.md`, no file of the folder is removed, and every element folder the Change touched holds a Case that tests that element. The touched elements are the element folders that differ between the state before the Change and the ACT. It reads the element Cases from the state after the deletion, so a diff that removes an element's Case together with the registration does not pass.

The control also derives the **retiring checks**: the commands of the deleted registration, read from the state before the deletion. Its wrapper can replay them at the head (`--replay`), so the check being retired is green in the ACT pull request's own final CI, which no longer selects it. This asks nothing new of ACT admission: it neither re-judges the rest of CI (that is admission's, which requires green checks before an ACT merges) nor adds a status, an evidence file or a Guard lifecycle; `act.md` stays the closure signal.
