# change/C14 declare pr types

Kai ruled on 26 November 2026 that kaal-change owns the Change folder and its PDCA, and with it the chapters and content of the four request types that carry a Change: PLAN, DO, ACT and HOTFIX. Hosting (hosting/C113) owns the format of a declaration and renders the templates and bodies from it. Release's C138 DO waits on this declaration. This PLAN makes kaal-change declare the four types in Hosting's form. It starts no implementation, installs nothing and touches no delivery file.

## Baseline

The four templates exist only as hand-written text under `.github/PULL_REQUEST_TEMPLATE/` (and as Release's sources under `engineering/release-management/05-src/wiring/templates/`; `plan` and `do` have none). No capability declares them as data. Their text holds host words: a "pull request" noun, "comments", and for HOTFIX a visible envelope line that is not a comment. Release owns both the text and the installation today.

## PLAN

Adds I31, F59, F60, N17 and the Cases T1553 to T1556, all RED on `main`. Adds the draft `declaration.json` in this folder: the four types in the form of hosting/C113 (`type`, `intro`, `chapters` of `{ name, guidance }`, `raise`). The DO delivers it unchanged at `packages/kaal-change/13-source/pull-request-types/kaal-change.json`, the path hosting/C113 names.

- **F59.** The declaration names exactly PLAN, DO, ACT and HOTFIX and, for each, the chapters of today's template in the same order (PLAN: Change, From, To, Because. DO: Change, Implement, Refactor. ACT: Change, Records. HOTFIX: Change, Defect, Urgency, Approach), each with its guidance.
- **F60.** The `raise` rules are the owner's: no Change id in a title, a declared draft flag, and squash auto-merge for PLAN, DO and ACT. No head or base: routes stay in Engineering's C37 as route eligibility, and the declaration holds chapters and fixed text only.
- **N17.** The declaration is KAAL data only: no host word, no file name, no comment syntax, no recognition rule. Where the templates say "pull request" or "comments" the declaration says "this body" or "outside this body".

The chapters, their order and the guidance are today's templates, with the host words taken out. This Change does not change what a type asks for.

## Questions

1. **Path in a legacy package.** Settled by Engineering on this PLAN: `13-source/pull-request-types/kaal-change.json` is the right path, the first target-layout folder of the package and not a migration.
2. **HOTFIX envelope line.** Today it is visible text above the first chapter. The form's `intro` is rendered as a comment, so the line moves into the intro and is no longer shown to the author. Hosting may prefer a visible-line field.
3. **Routes.** Settled by Engineering on this PLAN: head and base patterns stay in C37 as route eligibility, so no type here declares a head or a base.
4. **Format not merged.** hosting/C113 is a merged PLAN; its DO (#2613) is open. The Cases here read the declaration as plain JSON and do not call Hosting's validator. When the validator merges, the DO adds one Case that passes the file through it.

## DO
