# change/A26 folder-control

One pure module in the Skill, `skills/kaal-change/scripts/folder-control.mjs`: `closed`, `stateOf({ base, head }, folder)`, `verdict({ state, counts })`, `ratchet({ phase, base, head })`, `named`, `scope`, `judgeNaming`, `judgeFolders(view)` and `judgeClosing({ base, head, from, evidence })`, where each view is `{ files, read }`, counts are `{ red, green, unknown }` and `evidence` is `{ by, evaluations }`, all supplied by the caller, as `isolate` takes its Graph view and `assess` its evidence. It imports nothing but `node:path`, writes nothing and executes nothing. A thin script, `change-check.mjs`, is the one check a Change registers: it builds the views from Git through Hosting's execution, runs the Testing runner it was given (`--runner "<command>"`) at base and at head through Hosting to get the counts, takes the PR type as `--phase` (release's envelope knows it; Guard does not), reads evaluations with `--evidence <file>` and prints findings, or "closed, nothing to run". It depends on no Testing package: the runner is a command. The change kinds are one constant, C and G, that the Change Record Definition states. The package depends on Foundation and Hosting only; it names Guard's file `kaal-guard.json` as data and imports nothing from Guard, which never reads closure.
