# change/A26 folder-control

One pure module in the Skill, `skills/kaal-change/scripts/folder-control.mjs`: `closed`, `judgeFolders(view)`, `judgeRetirement({ before, head, from, evidence })` and `retiring({ before, head })` (the check names of each deleted registration, from `before`), where each view is `{ files, read }` and `evidence` is `{ by, evaluations }`, all supplied by the caller, as `isolate` takes its Graph view and `assess` its evidence. It imports nothing but `node:path`, writes nothing and executes nothing. A thin wrapper, `folder-control-cli.mjs`, builds the views from Git through Hosting's execution, reads the evaluations a run already produced (`--evidence <file>`) and prints findings; it runs no test. The change kinds are one constant, C and G, that the Change Record Definition states. The package depends on Foundation and Hosting only; it names Guard's file `kaal-guard.json` and Guard's check names as data and imports nothing from Guard, which never reads closure.
