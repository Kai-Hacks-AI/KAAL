# change/A26 folder-control

One pure module in the Skill, `skills/kaal-change/scripts/folder-control.mjs`: `closed`, `judgeFolders(view)` and `judgeRetirement({ before, head, from })` and `retiring({ before, head })` (the commands of each deleted registration, from `before`), where each view is `{ files, read }` supplied by the caller, as `isolate` takes its Graph view. It imports nothing but `node:path`, writes nothing and executes nothing. A thin wrapper, `folder-control-cli.mjs`, builds the views from Git through Hosting's execution and prints findings; with `--replay` it also runs the retiring commands at the head, through Hosting. The change kinds are one constant that the Change Record Definition states. The package depends on Foundation and Hosting only; it names Guard's file `kaal-guard.json` as data and imports nothing from Guard, which never reads closure.
