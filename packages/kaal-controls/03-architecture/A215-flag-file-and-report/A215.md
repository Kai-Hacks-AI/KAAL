# controls/A215 flag-file-and-report

Three owners. The package owns the file format and the reader (`scripts/flags.mjs`) and the report (`scripts/flag-status.mjs`), both pure and free of any adopter. The adopter's controls instance owns the file and its values (in KAAL `engineering/14-operations/controls/flags.json`, beside the control records) and its changes. Hosting owns reading a file at a base revision, which is platform mechanics (controls/A213 and the layers rule), so the library takes the text. The flag file is the first flag source behind a seam of one function (`of(control)`); a source from Hosting would be a second, built only when the Owner decides it. The flag is applied by `runControl` as in controls/A213 and the adapter is not changed: `toBoundary` turns the declared state into the `on` or `off` the adapter already reads, or tells the adopter not to run a Stopped control. STAMP is judged in `scripts/stamp.mjs` from the flag chosen in the file and the runs the adopter established, so that Stopped, Advisory and Preventing are chosen and Torn and Mute are found, never chosen. The report reads the effects of the flag in the runs instead of asking the platform. Rejected: flags as repository variables only (no history, no review, platform bound); a report that reads the platform itself (it would put hosting into controls); a flag per mode (the flag says whether, the declared type says which).
