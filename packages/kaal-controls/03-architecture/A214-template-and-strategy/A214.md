# controls/A214 template-and-strategy

The pattern is Template Method with Strategy, held together by Dependency Inversion.

```
            scripts/lib/contract.mjs         base: verdict, revision (nothing imported)
             ^                    ^
             |                    |
 controls library            ratchet library
 lib/judge-mode.mjs          lib/ratchet/{run,step,strategy}.mjs
 lib/run-control.mjs         ratchetStrategy = { name, judge(input) }
 fixed steps + slot                  ^
             ^                       | filled by (handed in by the caller)
             |                       |
 composition root: scripts/adapter.mjs, the command at scripts/judge-mode.mjs
 specific controls: sit on the controls library
 specific ratchets (adapter-ratchet, ratchet-use-ratchet): sit on the ratchet library
```

- Template: `runControl` fixes the steps of every control. Strategy: a preventive control names a strategy and the caller passes it in. The ratchet is the first strategy; no other is added (YAGNI).
- Dependency inversion: the controls library depends on the contract's idea of a verdict, not on a strategy; the ratchet library depends on the same contract; the composition root, the one place that knows both, wires them.
- The two enforcement rules (F219 item 5, F222) keep the layers honest: nothing outside the composition root and the specific ratchets imports the ratchet library, and a control declared as a ratchet is found if it computes its own allowance.
- The evidence collector (`lib/collect-evidence.mjs`) is a pure reader of the run lines every control prints. It stands on the contract only, so it serves specific controls and specific ratchets alike, and it judges identity with the rule of `lib/contract.mjs`.
- The libraries live in the controls Skill, under `scripts/lib/`, as C160 made `lib/` the library folder. References keep teaching only.
