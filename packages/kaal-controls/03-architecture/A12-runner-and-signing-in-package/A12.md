# controls/A12 runner-and-signing-in-package

In the package, the Skill gains three scripts beside the finder, `registry.mjs`, `judge.mjs` and `sign.mjs`, each with a pure exported function for its Cases and a command that takes every location and name as a parameter. The finder reads `stations`. `sign.mjs` is the only script that talks to GitHub: it takes a token from its environment and posts the checks; its pure part builds the payloads.

Beside the Skill, `enforcement/` holds the workflow template (`workflow.yml`: the judge job, then the sign job) and the manifest template of the App (`app-manifest.json`), both without a name that belongs to one project. `package.json` ships them. The Skill gains one pointer line and the reference `references/enforcing-controls.md`, which says when a control should be preventive at a station and how to judge a lack of a signed run; `references/judging-status.md` says that Running at a station needs a signed check. Skill independence holds: no KAAL path, no dependency beyond the foundation and the hosting. Developing, the hook, is not part of this slice.
