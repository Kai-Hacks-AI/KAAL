# controls/A12 stations-in-finder-and-registry

The finder `skills/kaal-controls/scripts/find-controls.mjs` reads the optional `stations` line and lists `stations` for every control, reporting a bad line as a problem of `stations` with a recovery. The script `scripts/registry.mjs` takes a repository, a Git ref and a station, reads the files of that ref with Git, runs the finder on them and prints the valid controls registered at the station with their mode and status. It reads no working tree. The Skill gains one pointer line in `SKILL.md` within its 600 words and the reference `references/enforcing-controls.md`, which says what a station and a mode are, why the registry is read from the base, and when a control should be preventive at a station. The scripts stay in the Skill's `scripts/` folder, know no KAAL path and need nothing beyond the foundation and the hosting.

Later slices of the Control Enforcement Unit (judge, sign, workflow and App, KAAL's instance) build on this one and are listed in `design.md`.
