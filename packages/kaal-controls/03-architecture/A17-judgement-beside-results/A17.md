# controls/A17 judgement-beside-results

`scripts/evidence.mjs` keeps `judgeEvidence` and adds the `without` rule and the `unnamed` count to it, then exports `readJudgements(path)` (valid judgements and a list of problems), `digestOf(texts)` (a digest of the control file and its Case files) and `judgementOf(control, judgements, digest)` (for each of verification and validation, the latest verdict and whether it is stale, or `none`). `readRecords` skips files named `*.judgement.json`. The state line of controls/C16 gains the judgement beside the result. A new reference `references/judging-criterion.md` tells the agent how to read the criterion beside the Cases (verification) and beside the Intent (validation), what `covered`, `partly`, `not-covered` and `unresolved` each need, that the one who wrote the Cases is not the one who judges them, and that a judgement is evidence of a reading and not a proof, and carries the expectation of each control type (directive, preventive, detective, corrective) as the question the agent answers. `judgeEvidence` also reads `shows` on a `:fail` head record against the control's type and its stations, and reports `unshown` and `boundary unnamed` counts in its verdict, which the state line shows. The control carries neither edge: a Case verifies it by pointing at it and a judgement judges it by pointing at it, and `judgeEvidence` and `judgementOf` are the two lookups by control id that a report joins. `SKILL.md` gains one pointer line within its 600 words. The scripts stay in the Skill's `scripts/` folder, know no repository path and need nothing beyond the foundation and the hosting. Where KAAL keeps its judgements, beside the run records, is for Engineering.
