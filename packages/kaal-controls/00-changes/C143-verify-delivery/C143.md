# controls/C143 verify Delivery finds that something is delivered and no control declares it

One small control with one property, built on the library of controls/C141 (the adapter and `compareClaims`). Asked for by Kai: small, meaningful controls, each following the change protocol until it blocks.

**The control.** `controls/CTL2`, `verify Delivery`, type detective, status designed. It compares two independently established inventories, the controls declared and the entries found in the actual delivery, each `{revision, scope, complete, entries}` for the applicable revision and scope. For every delivered entry that is neither the id nor the path of a declared control, the finding is `unrecorded:<entry>`. Discovery is the adopter's; the evidence contract is Controls'. It stays detective and non-blocking, and activation is a separate Owner decision.

**The check.** `scripts/verify-delivery.mjs` exports `findUnrecorded({declarations, delivered, revision, scope})`, pure. It returns a sorted list of unique `unrecorded:` names. A failed, partial, stale, missing or malformed inventory makes it throw, so the adapter fails closed with `UNKNOWN`, which never passes and is never filtered by a ratchet allowance; an empty inventory is clean only when `complete` is `true`. It reads no file and knows no repository.

## Revised after the CPO clarifications

Both inventories are established independently and must be complete for the revision and scope; incomplete discovery is UNKNOWN, never clean and never baselined. This follows the four independent facts of controls/C141.
