# C15 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it. It closes C15 in the collector. What `main` teaches can only be recorded after the promotion, and is not claimed here.

## Liked

Kai's frame, that evidence is the control's own Test Cases run against an X, kept the Change small: no new kind of test, only a record of what a Case ran against and a judge that counts it. The CPO's one objection to the PLAN was right and sharpened the contract.

## Learned

A label proves nothing. `provoked:1:fail` only says a run was called provoked, so a `:fail` X is shown the way the runner already shows a change, a RED base and a GREEN head on distinct runs (`compareReports`), and the negative Cases (a label alone, a GREEN base, a missing base, a run as its own base) keep it so. Missing evidence is UNKNOWN, never a pass.

## Lacked

Records. No KAAL control declares a minimum, no runner writes records, and without `--records` the check still reads declarations only. A `tested` claim means nothing in KAAL until Engineering passes its records.

## Longed For

The separate Engineering Change: KAAL's numbers in each control's front matter, where records live and how the ACT links them, a converter from a `kaal-testing` report to records, and the flag and WIRE that flip a control only when Tested is shown (the dispatcher go-hot gate among them). Wherever `tested` admits something, records must be required.
