# controls/C140 the Skill teaches a ratchet so that an agent finds and applies it, and is judged on three agents

Kai asked for this after research E1 (#2435): "do we need to improve the controls Skill in the context of ratchet? I think so." The evidence is the E1 trial: the Skill moved the answers toward its model (fail-closed UNKNOWN, a removable filter, accepted-state provenance) but every run skipped `SKILL.md`, no run reached full marks on control type against strategy, four of five missed the contrast with a passive check, and every answer leaked workspace links and unexplained tokens.

This Change is part of the planned restructure of the controls Skill, built on the Core Skill standard (core/C52, #2453). The vocabulary, the layout, the size thresholds and the generation of references belong to Core and to the owners of intent, requirements, defect and architecture. This Change adds none of that. It states only what the Skill must teach about a ratchet, and how that is judged.

1. **Findability.** The description of `SKILL.md` and its routing name a ratchet, a baseline and non-regression, so a search for any of them leads to the Skill and from the Skill to the ratchet text.
2. **The contrast.** One short passage sets a report, a plain gate and a ratchet side by side: what each does when someone adds a violation and when someone fixes one, and which fits a system that starts with violations.
3. **A worked example.** One small example in setup-agnostic words: a baseline of a few named findings, a new one fails, an old one passes, a fix shrinks the baseline, a baseline that grew fails, a missing baseline is unknown, and the end at zero.
4. **The declaration moves.** The fields that declare a ratchet (`strategy`, `baseline-source`, `owner`, `exit`) are taught only where declaring is taught. The ratchet text stops repeating them.
5. **Baseline, history and retirement (C24, C25).** The text teaches the accepted baseline read from the base, the history that only grows, and retirement that keeps the history, in generic words and with no file path or tool name.
6. **A judged trial, not a Case.** Whether an agent learns this is judged by `trial/trial.md`: one portable prompt set and one rubric that Kai runs on Claude, Codex and Antigravity in parallel with his own tooling. If the Skill works on all three, the Owner accepts that as sufficient, although the research was limited. A plain Case checks the structure of the Skill and the shape of the trial record. It never decides whether the teaching works.

## Not here

Nothing is implemented before core/C52 merges. The size cap, the layout of `references/`, the generation from intent, requirements, defects and architecture, and the migration of the controls tree belong to the restructure and to the owners named in the earlier requests. Running the trial is the Owner's. No WIRE, no ruleset, no change to any other capability's Skill.
