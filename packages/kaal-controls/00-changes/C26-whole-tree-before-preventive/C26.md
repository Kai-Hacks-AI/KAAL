# controls/C26 a control is proven on the whole tree before it is preventive

A new control starts as a detective control and becomes preventive when it is trusted. Today nothing says what trusted means. A trial on 280 commits of main (thread "trial - scope-independent control checks", scripts in `/mnt/project-files/controls/scope-independent-trial/`) found that the file-judging controls (verify Triggers, verify Workflow names, verify Layout) satisfy one property, and that the property can be the test of the move.

**The property.** A file-judging control exposes `findingsOf(tree)`: the set of stable finding ids in a tree. Its judgement of a change is exactly `findingsOf(head) − findingsOf(base)`: what the change adds. The trial held it for all three, and it catches relational bugs that are bound to the diff (a duplicate name). Whole-tree findings on main: Triggers 5, Workflow names 5, Layout 199 (Layout's findings need stable ids first). Controls about the pull request itself (isolate Changes, verify Delivery, verify History, the sync and ACT judges) have no tree to scan and stay diff-bound.

1. **A generic Case on every file-judging control.** `scripts/scope.mjs` (in the Skill, pure) exports `holdsProperty({findingsOf, judge, base, head})`: it says whether the control's own judgement of a change equals the findings the head adds over the base, and names the differences. The control's Cases call it on fixture trees. The brittle hand-fixture Cases (T1129, T1406, T1244: wording and placement) are not changed by this Change; they can be replaced by the generic Case later, per control.
2. **A gate from detective to preventive.** `decideAdoption({property, provoked, scan})` in the same file says what a control may become and how, from three facts the caller gathers: the property holds; a provoked RED was seen (a seeded violation is found, and the finding clears when the seed is removed); and a whole-tree scan of main. Zero findings: plain preventive. N findings: a ratchet with baseline N, and the history starts at line 1 (C24, C25). A control whose findings have no stable ids (a name twice, a non-string) is not ready. The Owner's go is still needed: the function returns the proposal, never the switch.
3. **The same facts verify that a detective control is built right.** The property and the provoked RED are not about the preventive move: they check any file-judging detective control against its own findings. Relation to the paused C18 and C19: those judge Case runs (a provoked run lacking `without` or `shows`); this is the control-level counterpart and uses the same provoked evidence, so C18/C19 stay paused and are not changed here.

## Not here

Running the scan, writing the baseline and history, and the switch itself are the adopter's (release's) and the Owner's. Abstracting the brittle Cases of existing controls is each control's own Change.
