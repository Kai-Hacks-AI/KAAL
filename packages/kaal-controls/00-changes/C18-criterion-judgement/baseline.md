# C18 baseline

The baseline is `main` after the C17 promotion. `judgeEvidence` says PASS when each declared kind has enough GREEN runs and a `:fail` kind has a base run that is RED and different from the head run. A control can therefore show Tested on a Case that checks something nearby and on a provoked failure that withheld a fixture.

- Kai (20 Nov 2026): whether a control's Cases test its stated criterion is a kaal-controls, judgement-based game. Where it is deterministic, check it and go with it. Where it is not, review and challenge. The core is the control type (directive, preventive, detective, corrective): each carries semantics its Cases must prove. Go as deterministic as we can, and run the rest through judgement. Keep result for scripts and judgement for agents. Every control can be verified (a script's result: does it do what it says) and validated (a review: is what it says right for its Intent, and do the Cases cover it).
- Kai (20 Nov 2026): kaal-testing verifies any element and kaal-review judges any element, which is why both are target-agnostic. A Test Case verifies the control and a review validates it, both pointing at it, nothing stored on it, and a control report uses both.
- The C16 state line (collector `kaal/controls/state-beside-claim`, not yet on `main`) is where the review is shown beside the result in the DO.
