# controls/C164 the flags are in a file and the library says where every control stands, per place, in STAMP

Kai's decisions, recorded: the detective or preventive flag of a wired control lives in a file, and the library reports where every control stands. Kai's lifecycle decision is folded in: Running of a control in a place is STAMP (Stopped, Torn, Advisory, Mute, Preventing), D, I and T of DIRT unchanged. Stopped, Advisory and Preventing are chosen by the flag; Torn and Mute are found by the library; Torn blocks under a Preventing flag; Mute is never read as Stopped or Advisory; escalation is stepwise. This Change records the intent I32, the Requirements F224 (the flag file per control and place), F225 (the status report) and F226 (STAMP states), the architecture A215 and the Cases T1723 to T1727. The package owns the format, the reader and the report and ships no flag and no adopter name. The adopter's controls instance owns the file and its values, and a flip is a reviewed pull request to that file. The flag source is a seam of one function, and the file is the only source built (YAGNI). It builds on C158 (the flag in the run and judgeRunning) and authorizes no DO, WIRE, flag, workflow, required check, ruleset or publish.
