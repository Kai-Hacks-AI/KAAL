# controls/C141 every control runs through one thin adapter that leaves the evidence of its execution

Asked for by Kai after release found that five Act controls still record `status: designed` although they are installed and have run. This Change is the **library** only, and no control. The controls that use it are separate Changes, each one property and each one moving detective, advisory, preventive on its own (C142 to C146, below).

## The adapter

A control is a pure check plus a declaration. The adapter is the one thin function between the check and the world. A control does not apply a mode, read a baseline, decide what to do when it could not judge, log or write evidence by itself. The adapter does, for every control, and only these five things:

1. **Mode.** It applies the mode the caller resolved (detective, preventive or ratchet) to the findings, through the existing `judgeMode`. Which flag or ruleset chose the mode is the adopter's.
2. **The ratchet filter.** In ratchet mode it applies the allowance (C24), with the base's baseline as given, never the change's own.
3. **Fail closed.** A check that throws, or returns something that is not a list of unique names, is `UNKNOWN`, and `UNKNOWN` never passes.
4. **The log.** One structured line per run: control, mode, verdict, number of findings, run, revision. No date.
5. **The record.** One record of the run: `{control, x, run, sha, verdict, by}`, `by` being `adapter`: the line that shows the control ran, on which kind of X (a fixture, a real pull request, a provoked failure), with what result. A run that cannot say its `run` and `sha` produces no record.

The checks stay pure. The adapter reads no file and calls no service. It stays thin by a rule: a concern joins it only when every control needs it and it can be said in one sentence.

## Four independent facts

Defined, implemented, running and tested are four independent facts, not ranked stages of maturity. Each has its own point of proof, for the specific control and the applicable revision: a valid declaration, the corresponding implementation as delivered, an actual execution, and applicable Test Case evidence. None implies another. `compareClaims` compares each declared claim with its own fact alone, and answers `<fact>:overclaims` or `<fact>:lags`; a fact with no proof is UNKNOWN, never proof of absence and never a finding. The adapter supplies execution evidence only (`executed`, for this control and revision), and is no authority for the other three facts. A script never edits a claim.

## Where the evidence lives

Judges read files only, and CI must not push. So the adapter writes nothing into Git. The record is printed, and the Change that claims a status commits it as a line in `records.jsonl` beside the control, as the history of a ratchet is written by the pull request that shrinks it (C25). Records are written only by a normal Change of the capability that owns the control, never by a WIRE and never by CI. A record is a recorded claim that a run happened for this control at this revision; whether the run exists is checked by whoever holds the service, not by this pure library.

## The controls that use it, each its own Change

Kai's line: small, meaningful controls, each following the change protocol until it blocks. Each is one property, one check, one collector, and declares its own `evidence` minimum.

- **C142 verify Adapter**: a control with a station, or delivered, that does not run through the adapter.
- **C143 verify Delivery**: something is delivered and no control declares it.
- **C144 verify Record**: a declared claim that lags or overclaims its own fact (compared fact by fact). It is the backstop on a promotion into main.
- **C145 demand Record**: the record of an installed control is due on the owning capability's next pull request into its collector.
- **C146 demand Evidence**: a pull request that raises a control's mode carries the evidence for the new mode.

Migrating the Act controls onto the adapter and wiring each control as a station are release's.

## Not here

Nothing is implemented before the Owner's go on this PLAN, and no control of C142 to C146 is part of it.
