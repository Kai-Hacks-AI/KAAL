## CI steps

1. **Check out the PR and fetch main.**
   - Responsible: the GitHub Actions workflow.
   - Trusted if the workflow file is read from main's version and the checkout is the PR head.
2. **Get the controls and the registry from main's files, not the PR's.**
   - Responsible: the repository owner (who registers the control at the Integrating station), plus the skill's `registry.mjs --base origin/main --station Integrating`.
   - Trusted if the skill, its scripts and the workflow are committed on main and branch-protected. Today `.claude/` is untracked, so the skill isn't in the repo and nothing here is trustworthy yet.
3. **Run the lint.**
   - Responsible: the repo's `npm run lint` (`scripts/lint.mjs`), which is detective only.
   - Trusted if the lint script comes from main, because a PR that edits it can choose what it finds. It must also exit non-zero on a crash. Finding names must be stable and fine enough to matter; they are file:rule, so a second `no-var` in the same file passes under the same name.
4. **Read the accepted baseline from main with `git show origin/main:lint-baseline.txt`.**
   - Responsible: the workflow.
   - Trusted if it never reads the PR's copy. If main has no baseline, the answer is unknown and blocks.
5. **Convert findings and baseline to JSON lists.** `judge-mode.mjs` takes JSON, but the lint script prints lines.
   - Responsible: a small script the repo owner writes and keeps on main.
   - Trusted if it is tested and fails on malformed input.
6. **Judge with the skill's script.** Run `judge-mode.mjs --mode ratchet --findings … --baseline <main's> --previous <main's>`.
   - Responsible: the skill's script.
   - Trusted if it exits 1 for blocked, and exit 2 or a missing file is treated as a stop. I haven't observed it run on this PR.
   - It also fails a stale allowance, so a PR that fixes a finding must delete that line.
7. **Make the verdict stop the merge.**
   - Responsible: the repository owner, who sets the job as a required status check, with branch protection and no admin bypass.
   - This is the only preventive part; the lint and the script only detect. It covers merges into main via PRs, not direct pushes by someone who can override.
8. **Set the exit.**
   - Responsible: the repository owner, who declares `exit:` in the control, for example "when the baseline is empty, delete it and run in preventive mode".
   - Trusted if someone notices the empty baseline. The ratchet doesn't force that.

The ratchet only claims that new findings are stopped. It doesn't claim the rule holds.
