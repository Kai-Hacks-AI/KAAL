## CI steps (GitHub Actions, PR into `main`)

The check is a ratchet. It is a preventive control that, for now, blocks only findings that are new compared with the baseline.

| # | Step | Responsible | Must be true to trust it |
|---|---|---|---|
| 1 | Check out the PR head, and fetch `main` as the base ref. | The repository owner, in the workflow file. | The workflow file and the Skill scripts run from the base, not from the PR. Otherwise the PR could change what judges it. |
| 2 | Read the last accepted baseline with `git show origin/main:lint-baseline.txt`. | The repository owner. | It comes from main, never from the PR's copy. If it is missing or unreadable, the result is UNKNOWN and the job blocks. |
| 3 | Run `npm run lint`. It writes `findings.txt`, one stable name per line, such as `src/a.js:no-var`. | `scripts/lint.mjs`, owned by the repository owner. | The linter is real and exits cleanly. Today it prints a hardcoded list, so it is not evidence about the code. The finding names must be fine enough that "new" means something. |
| 4 | Convert `findings.txt`, the PR baseline and the main baseline to JSON lists. | The repository owner (a small script). | The conversion is lossless. A malformed file stops the job. |
| 5 | Run `node .claude/skills/kaal-controls/scripts/judge-mode.mjs --mode ratchet --findings … --baseline <PR baseline> --previous <main baseline>`. | The Skill's script does the comparison. The repository owner makes sure its exit code fails the job. | The script comes from the base ref. Exit 1 (blocked) or 2 (could not judge) fails the job. It also fails if the baseline grew or still holds a resolved finding. |
| 6 | Make the check a required status check on `main`, with the PR's changes unable to alter the workflow. | The repository owner, in branch protection. | The setting is on and admins cannot bypass it. Without this, the job only reports. |
| 7 | Exit: when the baseline is empty, delete `lint-baseline.txt` and the ratchet steps, and run plain `npm run lint` as a blocking check. | The repository owner. | The `exit:` line is declared, and someone notices the baseline is empty, because nothing forces the change. |
