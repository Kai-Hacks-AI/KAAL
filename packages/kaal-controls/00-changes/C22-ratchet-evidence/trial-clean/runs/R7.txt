**What it is.** `npm run lint:ratchet` (`scripts/lint-ratchet.mjs`) is a gate that joins two controls.
- `scripts/lint.mjs` is detective. It prints findings and always exits 0, so it blocks nothing.
- The ratchet is preventive for one action. It exits 1 when a finding isn't in `lint-baseline.txt`.
- The README says CI runs it on every pull request. That statement is directive, so it is a claim and not something I observed.

**What it stops.** If the ratchet runs in CI, and a failing check blocks merging, it stops a pull request that introduces a finding not in the baseline. The ratchet script is the only part I have read.

**What it does not stop.**
- Existing baseline findings stay.
- Anyone who edits `lint-baseline.txt` by hand can add a new finding to it. The script's own comment says the baseline is hand-edited, and nothing guards that file.
- The ratchet only compares strings. `lint.mjs` is a stub that prints a hardcoded list and reads no files.
- It doesn't catch rules the linter doesn't implement.
- It doesn't catch pushes that skip pull requests.

**What I can claim.** I read the code. I did not run it, because the run needed approval, so I have not seen it operate or fail. I found no CI config. `.github` is absent, so the README's claim that CI runs it is unverified, and so is any branch protection that would make it blocking. What I see in the code:
- The baseline has `src/old.js:no-var`, which the linter no longer reports.
- The linter's current output, `src/a.js`, `src/b.js` and `src/c.js`, is all in the baseline.
- So I'd expect it to pass today with zero new findings. That is a reading of the code, not an observation.

**What is missing or wrong.**
- There is no CI workflow in the repo and no evidence of required status checks.
- The baseline can be edited by hand with no review rule, such as CODEOWNERS.
- The ratchet allows the baseline to stay stale. A stale entry like `src/old.js` is not flagged, and a fixed finding can reappear unnoticed under its old entry. Baseline entries that no longer occur should fail the check, or be removed automatically, so the baseline can only shrink.
- `lint.mjs` is a placeholder, so the check currently says nothing about real code. The `test` script is also just `echo ok`.
- Keying findings by `file:rule` means a second violation of the same rule in the same file is invisible.

**When the goal is reached (zero findings).**
- Empty the baseline, or delete the file.
- Make the plain linter fail on any finding, with a non-zero exit, and run it in CI.
- Retire the ratchet, because the exception list it enforces would no longer exist.
- Update the README to match.
- Keep the gate required in branch protection, and review any later addition of a baseline or suppression entry.
