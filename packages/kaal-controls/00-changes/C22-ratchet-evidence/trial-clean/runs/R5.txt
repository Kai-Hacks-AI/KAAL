I didn't run the check. The harness blocked my attempts, so everything below comes from reading the files.

**What it is and how it runs**
- `npm run lint:ratchet` runs `scripts/lint-ratchet.mjs`. It's a detective control with a blocking gate on top: a baseline-diff ratchet.
- The README says CI runs it on every pull request, but the repo has no CI config. There's no `.github` directory, and `.claude/skills` is empty. I can't confirm it runs in CI, or that a failure blocks a merge.

**What it stops and what it doesn't**
- **Stops:** a pull request that adds a finding (a `file:rule` line) that isn't in `lint-baseline.txt`. In that case it prints `new:` and exits 1.
- **Doesn't stop:** any of the existing baseline findings. Those pass indefinitely.
- **Doesn't stop:** anyone editing `lint-baseline.txt`. The script says the baseline is "edited by hand", so adding a line silences any new finding.
- **Doesn't stop:** a line moving to a different file. Entries are `file:rule`, so extra violations of the same rule in an already-listed file are invisible.
- **Doesn't stop:** a broken linter. `scripts/lint.mjs` is a stub that prints three hardcoded findings and always exits 0. It never reads `src/`. It would report the same output on any code.
- **Doesn't stop:** a failing linter run. `execSync` throws on failure, which also fails the check, but an empty output would silently pass.

**What I can claim from what I saw**
- The ratchet logic is simple and does what the code says: new findings fail, baseline findings pass.
- The "lint" it ratchets against is fake, so a pass tells you nothing about the code. The code has `var a=1` in `src/a.js`, which matches the stub's output only by coincidence.
- I can't claim that CI enforces it.

**What's missing or wrong**
- The linter is a stub, not a real one such as ESLint.
- There's no CI workflow and no branch protection in the repo.
- Nothing protects the baseline from hand edits. It needs a CODEOWNERS rule or a check that it only ever shrinks.
- The baseline is stale. `src/b.js`, `src/c.js` and `src/old.js` don't exist, and `src/old.js` is listed but isn't in the stub's output. Nothing flags a stale entry, and a fixed finding isn't removed, so the ratchet can't tighten.
- The stub emits three findings but the baseline holds four lines, so the two have already drifted apart.

**When the goal (zero findings) is reached**
- Empty `lint-baseline.txt`, or delete it.
- Make the ratchet strict: fail on any finding, or just run lint directly with a non-zero exit.
- Fail if a baseline entry is no longer found, so the baseline can only shrink.
- Make the real linter exit non-zero on findings.
- Then drop the ratchet script and update the README, so the control can't be quietly loosened again.
