I couldn't run the check, so everything below comes from reading the files.

**What it is:** `scripts/lint-ratchet.mjs` (`npm run lint:ratchet`) is a preventive control run as a ratchet. It compares the output of `scripts/lint.mjs` with `lint-baseline.txt`. A finding that isn't in the baseline makes it exit 1, which should fail CI. The README says CI runs it on every pull request.

**What it stops:** it should block a new `file:rule` finding. In the current files, `src/b.js:no-var` and `src/c.js:no-eval` are both in the baseline, so they pass.

**What it doesn't stop:**
- Existing findings pass, and so does a known finding that gets worse under the same name.
- It doesn't judge a failed or empty lint run. If `lint.mjs` printed nothing, the ratchet would pass.
- Anyone who edits the baseline by hand can excuse a new finding. The script comments say the baseline "is edited by hand".
- Merging while the check fails, or changing the CI config, isn't covered.

**What I can claim:**
- The design is preventive, in ratchet mode, and I've read it.
- I haven't seen it run or block anything.
- I haven't seen CI invoke it. The repo has no `.github` directory or any other CI config, so "CI runs it" is only the README's statement.
- Nothing shows that a failure blocks a merge.

**What's wrong or missing:**
1. **No CI wiring in the repo.** There's no workflow and no branch protection that I can see, so it may not be enforced at all.
2. **`lint.mjs` is a stub.** It prints a hard-coded list and never reads `src/`, so the check doesn't examine any code. `src/a.js` contains `var`, and that happens to match the list.
3. **The baseline never shrinks.** `src/old.js:no-var` is in the baseline, but the file doesn't exist and the lint doesn't report it. This is a stale allowance, and the ratchet rules say it should fail. If that finding came back, it would be excused. The script only checks for new findings.
4. **No comparison with the last accepted baseline.** Nothing stops the baseline from growing, and a missing or unreadable baseline file isn't handled as "unknown, so block".
5. **No exit statement.** The README doesn't say what the control becomes when the baseline is empty.
6. **`exit` is ignored for failures.** `execSync` throws if `lint.mjs` itself fails, which blocks by accident. The real `lint.mjs` always exits 0, so a crashing or misconfigured lint would pass.

**When the goal (zero findings) is reached:**
- Delete `lint-baseline.txt` and the ratchet script.
- Change CI to run `lint` as an ordinary preventive check, where any finding fails.
- Make `lint.mjs` exit non-zero on findings.
- Say in the README that the ratchet has ended.
- Confirm that the check is required before merge.
