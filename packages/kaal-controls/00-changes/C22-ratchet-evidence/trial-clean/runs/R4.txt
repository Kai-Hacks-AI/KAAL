**What it is.** `npm run lint:ratchet` (`scripts/lint-ratchet.mjs`) is a detective control with a gate on top. It runs `scripts/lint.mjs`, compares the findings to `lint-baseline.txt`, and exits 1 if any finding isn't in the baseline. The README says CI runs it on every pull request. A failing exit blocks a merge only if CI is required for merging, and I can't see that setting.

**What it stops and what it doesn't.**
- It reports findings that are new compared with the baseline, and fails the step.
- It ignores the baselined findings: `src/a.js:no-var`, `src/b.js:no-var`, `src/c.js:no-eval` and `src/old.js:no-var`.
- It does not fix anything.
- Anyone can edit the baseline by hand, and the script's own comment says so. That is a bypass, and nothing checks it.
- It only fails on findings in the `file:rule` format that `lint.mjs` prints. Two findings of the same rule in the same file look identical to it, so a second `no-var` in `src/a.js` passes.

**What I observed and what I didn't.**
- I read the scripts, the baseline, the README and `src/a.js`. The repo has a single commit.
- I did not run the ratchet, because the run needed approval I didn't have. So I have not seen it pass or fail.
- I saw no CI config. There is no `.github` directory, so the README's CI claim is unverified, and so is whether CI is required before merging.
- `lint.mjs` is a stub. It prints a hard-coded list and always exits 0, so it never inspects the code. The ratchet therefore only compares a fixed list with the baseline. Nothing shows that it would catch a real new violation.

**What's missing or wrong.**
- **No CI evidence.** There is no workflow file or branch protection in the repo, so the claim that CI runs it is unverified.
- **Fake linter.** `lint.mjs` doesn't lint. The baseline also doesn't match reality. `src/old.js` doesn't exist, and `src/a.js` has `var` while `src/b.js` and `src/c.js` don't exist either.
- **Hand-edited baseline.** Nothing stops new entries being added, so the ratchet can loosen.
- **Stale entries.** Fixed findings never have to leave the baseline, so room for regressions builds up.
- **No count.** There is no tracking of the baseline size over time.

**When the goal (zero findings) is reached.**
1. Empty the baseline, or delete it.
2. Make plain `lint` fail on any finding, with no baseline exemption. The ratchet then no longer has a job, so retire it.
3. Replace the stub with a real linter, and require it before merge.
4. Until then, make the ratchet fail on stale baseline entries, so the baseline can only shrink.
