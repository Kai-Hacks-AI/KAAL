**What it is.** The lint check is `npm run lint:ratchet`, which runs `scripts/lint-ratchet.mjs`. It is a preventive control running in ratchet mode. It exits 1 on any finding not listed in `lint-baseline.txt` and passes the listed ones. The underlying `scripts/lint.mjs` is detective only. It prints findings and always exits 0.

**What it stops, and what it doesn't.**
- It stops a new `file:rule` finding, but only when the ratchet is run and its exit code is honored.
- It doesn't stop the baselined findings: `src/a.js:no-var`, `src/b.js:no-var` and `src/c.js:no-eval`.
- It doesn't stop a known finding that gets worse under the same name.
- It doesn't stop edits to `lint-baseline.txt`, which is hand-edited. Anyone can add an entry to excuse a new finding.
- It doesn't stop a stale allowance. `src/old.js:no-var` is in the baseline but isn't found, and nothing flags it.

**What I can claim.** I only read the files. I didn't run the script, so I haven't seen it operate. Reading the code, it should fail on a finding that isn't in the baseline. `lint.mjs` is a stub that prints a hardcoded list, so it examines no source files, and "no new findings" means nothing yet. The README says CI runs the ratchet on every PR, but the repo has no CI config (no `.github`). I can't confirm it runs, or that a failure blocks a merge.

**What's missing or wrong.**
- **Baseline growth is unchecked.** There's no comparison against the last accepted baseline, so the allowance can grow.
- **Stale entries pass.** Resolved findings stay in the baseline, and `src/old.js:no-var` is one now.
- **No "unknown blocks" rule.** If `lint.mjs` crashes, `execSync` throws, which happens to fail. An empty or missing baseline file isn't treated as a stop.
- **The linter is a stub.** It checks nothing real.
- **The ratchet has no stated exit.**
- **Enforcement isn't visible.** There's no CI config or branch protection in the repo.

**When the goal is reached.** Zero findings means an empty baseline. At that point:
- Delete `lint-baseline.txt` and the baseline logic in `lint-ratchet.mjs`.
- Run `lint` itself as an ordinary preventive check: any finding exits 1, with no allowance.
- Make that check a required gate in CI.
- Declare that exit in the README as one sentence, and require the baseline to shrink and never grow until then.
