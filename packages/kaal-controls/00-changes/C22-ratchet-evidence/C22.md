# controls/C22 ratchet lifecycle verified

A follow-up to C21 on the same collector, narrowed to what the CRO assessment of the merged DO asks to be defined and verified. Research-method improvements are deferred to their own scope (below).

1. **The accepted-baseline lifecycle is defined and verified.** C21 compares one run to the baseline last accepted. C22 defines the lifecycle across runs: the first accepted baseline at adoption, a run that is judged against it, what is stored after an accepted run (and only then), what is kept after a rejected one, how an improvement advances it, and how it ends. Requirement F36, Case T1117, and `lifecycle.md`.
2. **The CLI contract is covered.** The command's JSON output and exit codes 0, 1 and 2 are checked on valid input and on every input it cannot judge: a missing or unreadable file, malformed JSON, JSON that is not a list of names, no findings file, no mode. Requirement F35, Cases T1115 and T1116.
3. **The selected Cases are shown to detect the intended weakenings.** The exact patches of the four weakenings of C21 and a runner are kept (`mutations/`), and were run on the final head of C21: the baseline is GREEN and each weakening is RED on a named Case. The DO adds the weakenings of the new behaviour (a blocked run that still advances the baseline; the command's exit code not following the verdict) and runs all of them on its own head. It is a runner and patches, not a framework.
4. **Misleading evidence claims are corrected where they appear.** In C21: the sensitivity preview is marked superseded, and judgment J3's evidence is restated so that the author-run trial is observation and not evidence that the Skill teaches the split (`judgments.md` of C21). `controls/RT1` is corrected in the same way in the ACT.

## Deferred: research method

The trial bundles (prompts, fixtures, rubrics, anonymised answers, keys, scoring records), durable raw transcripts, whether a run opened the Skill, an end-to-end agent exercise of accept, store and judge-next, and a trial harness with a true no-Skill arm scored by someone other than the author are research-method improvements. They are not part of this Change and need their own scope. Until then the trials of C21 are reported as author-reported observations that are not retained beyond the pull request.

The PLAN adds no script, Skill word or workflow: documents, F35, F36, Cases T1115 to T1117, and the patches. Rollout of any ratchet and the authorization to switch mode remain consumer work.
