# controls/C14 Control Enforcement Unit

Closes a gap between a declared control and an enforced one. Today a preventive control such as release/CTL8 runs as a workflow job with the repository's own token, and a ruleset can only require a check by its name, which any workflow of the repository can post. This Change adds the Control Enforcement Unit to kaal-controls: a control declares at which stations it judges and in which mode, a runner judges with the code of the base and holds no secret, and a separate step signs one check per control on the exact head as a GitHub App, so a ruleset can require the check pinned to the App. In KAAL the App is "KAAL Inspector": it fills the Reviewer role of WORK next to the CPO (the CPO judges content, the Inspector judges controls) and never opens or merges a pull request. UNKNOWN never passes. The package holds the generic parts (declaration, scripts, workflow template, App manifest template) and knows no project. Engineering holds KAAL's instance, "KAAL Inspector", as a map in code. First slice: the unit and the Integrating station, with no second control and no generic registry beyond what one station needs. Registering release/CTL8, the ruleset requiring its check, and `verify Stages` reading the registry are release's Changes, listed as dependencies.
