# controls/C147 the library judges the adoption line of a ratchet

Found by release while adopting the ratchet history for CTL20 and CTL36 (release/C134, DO #2481). C25 states the adoption line, and `judgeProgress` only judges a shrinking step. This is a defect in the library's coverage of C25, not a new concept. It stays small: one new pure function beside the existing two, and `judgeProgress` is not changed.

**The function.** `judgeAdoption({base, head, change, window})` in `scripts/ratchet.mjs`, pure, like `judgeProgress`. The caller reads `base` as Git data of the base and `head` from the merge result, and passes the Change the pull request carries and the time window it ran in.

**What it checks.**
1. The base has no history: a ratchet that already has history is not adopted again (`already-adopted`).
2. The head's history is exactly one line, and it is the adoption line: `from` is `null`, `to` is the size of the head's baseline, `removed` is empty (`line-mismatch`).
3. The line names the Change the pull request carries, and that Change exists (`change-mismatch`, `change-unknown`).
4. The line's time lies inside the window (`time-out-of-window`).
5. The baseline is a list of unique names. When the base already holds a baseline file, the head's baseline does not exceed it (`baseline-grew`); when the base holds none, the pull request creates it, and that is the adoption.
6. A missing or malformed input is `UNKNOWN`, never a pass.

It says `PASS` when all of these hold. The reasons are the names `judgeProgress` already uses where the property is the same.

## Not here

Where the history file lives, how the base is read as Git data, the window and the wiring are the adopter's, as for `judgeProgress`. `judgeProgress` and `judgeRetirement` are not changed. Release keeps its Case T1522 until it chooses to use the library's. Nothing is implemented before the Owner's go on this PLAN. See `change.md`.
