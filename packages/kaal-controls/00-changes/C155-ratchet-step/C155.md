# controls/C155 one judge tells the step of a ratchet from the files

The library judges the three steps of a ratchet (`judgeAdoption`, `judgeProgress`, `judgeRetirement`), but it takes them as three functions with parsed inputs. Whoever wires a ratchet must therefore read the baseline and the history, parse them, decide which step the change is, and choose the function. That decision is a rule of the ratchet and not of the wiring, and release already hit it twice: it could not judge its own adoption (G113), and its CTL20 and CTL36 histories wait for a judge that knows which step it sees (release/C134, `do.md`).

**The function.** `judgeRatchetStep({base, head, carried, window})` in `scripts/judge-ratchet.mjs`, pure. `base` and `head` are each `{baseline, history}`: the text of the baseline file and of the history file at that revision, or `null` when the revision has no such file. `carried` is the list of Changes the step carries, each `{id, exists}`. `window` is `{from, to}`. It parses the texts, tells the step from them, calls the library's judge and returns its verdict with the name of the step: `adoption`, `progress`, `retirement` or `unchanged`.

**How it tells the step.**
1. Both files are the same text on both sides: `unchanged`, PASS, and no Change is needed.
2. The head has no baseline and the base has none: `unchanged`, PASS. The head has none and the base has one: `retirement`, judged by `judgeRetirement`.
3. The base has no baseline, or has one and no history while the head has a history: `adoption`, judged by `judgeAdoption`. The base baseline is `null` only when the base has no baseline file.
4. Anything else is `progress`, judged by `judgeProgress`.
5. `adoption` and `progress` need exactly one carried Change. Zero or more than one is UNKNOWN.
6. A text that is not a JSON list of unique names (baseline) or whole JSON lines (history), a missing `window` or `carried`, or a missing side is UNKNOWN. A file that is absent is `null`; a file that cannot be read is not `null`.

The reasons are the library's, unchanged.

## Not here

Reading the files at the base and the head, which Changes the diff carries (taken from the changed paths, never from a title or a body), the window (the times of the base and head revisions), the workflow, the flag and the report are the adopter's: release's wiring. `judgeAdoption`, `judgeProgress` and `judgeRetirement` are not changed. Nothing is implemented before the go on this PLAN, and nothing is wired by this Change. See `change.md`.
