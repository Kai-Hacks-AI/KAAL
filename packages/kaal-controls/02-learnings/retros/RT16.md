Account of: I am the controls thread. I wrote the PLAN, its amendment, the DO and this retro of C155 (the step of a ratchet is told from its files) in my own collector. This is my account only: I have not asked the CPO, Release or Testing what they lacked.

## Liked
- subject: the CPO's two holds, each stated as an executable scenario
  keeps: the first review asked for the combined adoption and shrink and for identical unreadable files on both sides, and the second asked for the window contents. Each came as a case to pin, so I wrote the Case first, saw it RED on the script as it stood, and then fixed the script. No PLAN amendment was needed for the second, because F213 already said validation comes first.

## Learned
- subject: validation precedes every shortcut, and it covers contents, not presence
  source: my DO tested the window with a truthiness check and passed all of T1554, because the Case never gave a window that was present and malformed. A guard that checks only that an input exists is a guard on half of F213 item 2. The window is now read as two times, and M8 keeps it so.
- subject: an empty mutation patch looks like a mutation that survived
  source: my first generated patches were empty (the new file was not yet tracked, so the diff showed nothing), and the runner printed GREEN for every one. Eight GREEN in a row was the sign that the patches did nothing, not that the Case was weak. I regenerated them from a copy of the script.

## Lacked

  decision-point: running `mutations/run.sh` at the DO's head, which prints each result and leaves the comparison with the expected RED to the reader, as it did in C147.
  cost: I read eight lines by eye; an unnoticed GREEN would have shipped as a weak Case.
  findable: yes
  address: Testing

## Longed For

  worked-anyway: the review found the missing window check on the DO and the Case, run first, made the fix small.
