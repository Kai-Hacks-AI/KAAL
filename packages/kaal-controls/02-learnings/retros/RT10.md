Account of: I am the controls thread. I wrote the PLAN and the DO of C143 (verify Delivery) and this retro of my own collector. This is my account only: I have not asked the CPO or Testing what they lacked.

## Liked
- subject: the two inventories judged by one rule
  keeps: `declarations` and `delivered` go through the same test (complete, this revision, this scope, an entries list), so the Case's nine bad inventories exercise both sides with one table.

## Learned
- subject: an empty list is a fact only when completeness is established
  source: F207 item 4 and T1518 keep an empty delivered clean only with `complete: true`; the DO therefore checks completeness before it looks at the entries, so an empty but unproven inventory can never read as clean.
- subject: a declared control matches a delivered entry by its id or by its path
  source: the Case names both (`c/CTL1` and `a/CTL2.md`) as declared, so the DO builds one set of ids and paths and tests membership.

## Lacked
- subject: the shape of what a delivered entry may be beyond a string
  decision-point: writing the DO, where a delivered entry that is an object had no stated meaning.
  cost: I made any non-string entry throw, which is stricter than F207 says; the Requirement does not name it.
  findable: yes
  address: controls/F207

## Longed For
- subject: one place that says what a malformed entry is for every inventory-shaped input of C142 to C146
  worked-anyway: each check states its own rule in its own script and Case.
