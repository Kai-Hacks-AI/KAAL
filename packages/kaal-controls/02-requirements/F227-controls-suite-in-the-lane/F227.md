# controls/F227 controls-suite-in-the-lane

1. `packages/kaal-controls` is a workspace of the repository root (`workspaces` of the root `package.json`), so the Workspaces lane (`engineering/lanes/workspaces.mjs`, which runs the `npm test` of every workspace but Hosting) runs `node --test test/*.test.mjs` of the package, on a pull request and in the merge group. No lane, script or required check is added: the package joins the lane by being a workspace (`engineering/lanes/workspaces.mjs`).
2. The lock file of the root names the workspace, so that `npm ci`, which every lane runs, installs the tree it describes: an entry `packages/kaal-controls` and the link `node_modules/@kaihacksai/kaal-controls`.
3. The package has a `test` entrypoint (it already has one, so the lane does not report it as not verified), and it stays free of KAAL: joining the workspaces adds no dependency, no script and no file to the package, and `private: true` stays as the lock against a publish.
4. Nothing about which checks are required changes. The required name is the existing Workspaces lane; the ruleset is not edited.
