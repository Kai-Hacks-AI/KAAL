# controls/F208 verify-record

1. `scripts/verify-record.mjs` exports `assessRecord({controls, facts, revision})` and `findDisagreeing({controls, facts, revision})`, both pure. A control is `{id, claimed}`, `claimed` being `{defined, implemented, running, tested}`, the booleans its record declares. `facts` maps a control id to `{revision, defined, implemented, running, tested}`: each fact `true`, `false` or `null`, established by that fact's own proof for the applicable revision (the adapter's `executed` for running, the declaration check, the implementation as delivered, the Test Case evidence).
2. `assessRecord` compares each claim with its own fact (`compareClaims`, C141), both directions, with no exemption for `implemented`, and answers `{findings, unknown}`. A finding is `<fact>:lags:<id>` (claim `false`, fact `true`) or `<fact>:overclaims:<id>` (claim `true`, fact `false`). `unknown` lists `<fact>:<id>` for every fact that is `null`, missing, unverified, or stale (the entry's `revision` is not the applicable one, which makes all four of its facts unknown). No fact implies another, and unknown is never a finding and never proof of absence.
3. `findDisagreeing` is the check the adapter runs. It returns the sorted list of confirmed findings when no fact is unknown. When any fact is unknown it throws an `UnknownEvidence` error that carries `confirmed` (every confirmed finding, kept) and `unknown` (the list), so that the adapter fails closed with `UNKNOWN`. `UNKNOWN` never passes, is never filtered by a ratchet allowance and never hides a confirmed discrepancy; only a confirmed finding can be baselined. A control with no entry in `facts`, or malformed input, throws too.
4. The answer is empty only when every fact of every control is established and agrees. It is the backstop on a promotion into main, and judges correctness only; when a correction is due is controls/C145's.
5. It reads no file and writes nothing, and knows no repository, path, flag or service. It stays detective and non-blocking; whether a finding blocks is GitHub configuration, and activation is a separate Owner decision.
