# controls/F208 verify-record

1. `scripts/verify-record.mjs` exports `findDisagreeing({controls, facts})`, pure. A control is `{id, claimed}`, `claimed` being `{defined, implemented, running, tested}`, the booleans its record declares. `facts` maps a control id to the same four keys, each `true`, `false` or `null`, established by that fact's own proof for the applicable revision (the adapter's `executed` for running, the declaration check, the implementation as delivered, the Test Case evidence).
2. Each fact is compared alone with its own claim by `compareClaims` of the library (C141). The finding is `<fact>:lags:<id>` when the claim is `false` and the fact `true`, and `<fact>:overclaims:<id>` when the claim is `true` and the fact `false`. A fact that is `null` is UNKNOWN: never a finding and never proof of absence. No fact implies another.
3. A control with no entry in `facts`, or malformed input, makes the check throw, so that the adapter fails closed with `UNKNOWN` and no clean result is given from missing evidence.
4. The answer is a sorted list of unique names, empty only when every compared fact agrees. It is the backstop on a promotion into main.
5. It reads no file and writes nothing, and knows no repository, path, flag or service.
