# controls/F28 minimum-evidence

A control may declare `evidence`, an optional list of `<x>:<runs>` entries, such as `evidence: [fixture:3, merge:2, provoked:1:fail]`. An x is a lower-case word the control chooses for a kind of X its own Test Cases run against, each x once. runs is a whole number from 1. At least one entry ends `:fail`: an X that is a real failure, so a Case that passed on it shows the control rightly caught it. A list that does not fit leaves the control in the inventory, makes it invalid, and its problem names `evidence` with a recovery (controls/F20). A control without `evidence` is valid and states no minimum.

Evidence is a run of a Case that tests the control (its first line `// Case <id> tests: <control id>`) against an X. A record is `{ case, x, run, outcome }` with the outcome GREEN, RED or UNKNOWN as a Case runner reports it. The minimum is met when every declared x has at least `runs` distinct runs with outcome GREEN. A run of a Case that does not test the control, an x the control did not declare, a RED or UNKNOWN run and a repeated run id add nothing, and the RED and UNKNOWN runs are listed. A script judges a control from its declaration and the records and says PASS or UNKNOWN, with the reason (no minimum, no records, below minimum) and what is missing: it never says PASS on missing evidence.

Given records, the check fails every control that claims `tested` and is not PASS, and names `status` and what is missing. Without records the check reads declarations only, as before.
