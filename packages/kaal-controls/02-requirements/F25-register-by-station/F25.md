# controls/F25 register-by-station

A control may declare `stations`, an optional list of `<Station>:<mode>` entries, such as `stations: [Integrating:preventive]`. A Station is one of Developing, Collecting, Integrating, Hotfixing, Wiring, Promoting or Publishing, spelled as written. A mode is `detective` or `preventive`. A control with no `stations` is valid and is registered nowhere. An entry outside the lists, an entry without a mode, or the same station twice leaves the control in the inventory, makes it invalid, and its problem names `stations` with a recovery that lists the stations and the modes (controls/F20).

The finder lists each control with `stations` as `[{ station, mode }]`. The registry of a station is read from the base of a pull request only: a function given the files of a Git ref and a station lists the controls registered there, with their mode and status (`registryAt` in `scripts/lib/registry.mjs`), and reads nothing from the working tree. Reading the ref is hosting's work: the command line that does it (`node registry.mjs --repo --base --station`) is a deprecated shim that is not published (controls/N8). A candidate cannot register a control, move one to another station or remove one from the registry that judges it.
