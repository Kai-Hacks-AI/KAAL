# controls/F34 modes-judged

1. A station mode is one of `detective`, `preventive` and `ratchet`. A control that has a ratchet at any station declares `exit`, one sentence on what it becomes when its baseline is empty; a control with a ratchet and no `exit` is listed with the problem `a ratchet has no exit`. A mode outside the four stays refused.
2. A script applies a mode to the answer of a check. A check's answer is a list of findings, each a name that stays the same from run to run, or no list when it could not judge. Detective reports the findings and blocks nothing. Preventive blocks when there is any finding. A check that could not judge is `UNKNOWN`, never a pass, and blocks in the blocking modes.
3. **Ratchet, preservation.** The baseline of a run holds nothing that the reference baseline did not hold. A baseline that holds a finding the reference did not is a failure, reason `baseline-grew`, and names what it added.
4. **Ratchet, advancement.** The baseline of a run is the reference baseline minus the findings no longer found. A baseline that holds a finding that is no longer found is a failure, reason `stale-allowance`, and names it. The script says the baseline the next run must hold (`next`). A finding that was resolved and removed from the baseline and appears again is new and blocks, and putting it back into the baseline is growth.
5. **Ratchet, comparison.** A finding that is not in the baseline blocks and is named as new. A finding that is in the baseline passes and is named as known. When the baseline is empty the ratchet is spent: the script says so and that the next mode is preventive, and an empty baseline needs no baseline machinery.
6. **Ratchet, uncertainty.** A ratchet with no findings list, with no reference baseline, or with a reference or a baseline that is not a list of distinct names is `UNKNOWN` and blocks, with the reason `could-not-judge`, `no-reference` or `incompatible-reference`. Missing evidence is never success.
7. **Ownership.** The script owns the comparison and the verification of the transition from one accepted baseline to the next, and computes the next baseline. Getting the reference, writing the next baseline, making the verdict stop an action and deciding when a station changes mode are the adopter's, and the Skill says what an adopter inherits and what it supplies.
8. The Skill teaches the ratchet lifecycle and nothing station-, repository- or pipeline-specific: what a ratchet is (an allowance for existing findings, no new regression, an allowance that shrinks as findings are resolved) and how it ends (at an empty baseline the baseline and the ratchet-only machinery are removed and the control continues as an ordinary preventive control). The type of a control stays distinct from its operating mode: a ratchet is a temporary, special mode of a preventive control, not a type. This is judged by an agent trial, not by a Case.
9. The package ships no development instructions. An instructions file for consumers is produced by the layout of engineering/C30 when the package adopts it, and is not part of this Change.
10. Testing and judgment are defined before they are executed. Each Test Case states what is verified and the expected result, and each judgment definition states what must be assessed, by which criteria and from which evidence, and each points at the elements it examines. A required judgment receives an explicit disposition in CHECK; a general approval of a pull request is not one. The definition of a judgment is not its execution, and neither is its result.
