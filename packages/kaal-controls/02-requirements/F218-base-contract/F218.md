# controls/F218 base-contract

1. `scripts/lib/contract.mjs` is the base contract of both libraries. It imports nothing, reads nothing and knows no repository, tool or service.
2. It exports exactly `VERDICTS` (`PASS`, `REPORT`, `FAIL`, `UNKNOWN`), `isVerdict`, `isIdentity` and `sameIdentity`.
3. `isVerdict(v)` is true for an object whose `verdict` is one of `VERDICTS` and whose `blocked` is a boolean, and false for anything else.
4. An identity is the opaque identity of the content examined (testing/C84, hosting/C118): a string with at least one character that is not whitespace, and nothing more. No format is assumed, no source is named, and no case is folded. `isIdentity(x)` is true only for such a string; an empty or blank string and a value that is not a string are not identities. `sameIdentity(a, b)` is true only when both are identities and the strings are equal.
5. **End state (the guarantee).** Every ratchet comparison and every evidence record of Controls is bound to the identity of the content actually examined (testing/C84, hosting/C118), never to a Git revision, a trigger or an arbitrary label. A record or comparison with no identity, or with one that is not the examined one, is UNKNOWN and never counts, never passes and never becomes an allowance. Git is provenance and none of Controls' concepts.
6. **Transitional, not the contract.** Until the strict adoption below, `executed`, `findEvidenceDue` and `runAdapterRatchet` still take `revision` as a non-empty string and existing Cases pass labels. That compatibility is transitional, named as such, and nothing new is built on it: every function this Change adds (F222, F223) takes and returns an identity. The record line keeps its field name `sha` for compatibility, and what it holds is read as the identity.
7. **Path to strict identity.** A separate Change, planned after this one and gated on hosting/C118 (the provider of the identity) being on main: (a) `executed`, `findEvidenceDue` and `runAdapterRatchet` take `identity`, check it with `isIdentity` and `sameIdentity` and make a record with another identity UNKNOWN; (b) the Cases that pass labels move to identities; (c) a ratchet over the raw trigger revision (`GITHUB_SHA`) in evidence writers, release/D20, on the Owner's go. Acceptance: no function of Controls that reads or writes evidence accepts an unnamed or non-matching identity, shown by a Case for each, and the revision-named parameters are gone or deprecated shims. This Change is not npm-ready until that Change is on main; the publish stays a separate Owner go.
