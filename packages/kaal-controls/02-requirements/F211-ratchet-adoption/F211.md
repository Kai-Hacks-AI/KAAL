# controls/F211 ratchet-adoption

1. `scripts/ratchet.mjs` exports `judgeAdoption({base, head, change, window})`, pure, taking the values of `judgeProgress`: `base` and `head` each `{baseline, history}`, `change` `{id, exists}` and `window` `{from, to}`. The base's baseline is one of three things and the three are never confused: `null` when the base authoritatively has no baseline (absent), a list when it has one, and the empty list when it has one that is empty (present, at zero). Anything else, or a base whose baseline is not stated at all, is unknown. The head's baseline is always a list of unique names.
2. It says `PASS` when the base's history is empty, the head's history is exactly one line `{at, change, from: null, to, removed: []}` with `to` the size of the head's baseline, `change` the id of the Change the pull request carries and `exists` true, and `at` inside the window.
3. It fails with a reason, each its own: `already-adopted` when the base's history is not empty; `line-mismatch` when the head's history is not exactly one line, or `from` is not `null`, or `to` is not the size of the head's baseline, or `removed` is not empty; `change-mismatch` and `change-unknown` as in `judgeProgress`; `time-out-of-window`; `baseline-grew` when the base's baseline is a list (present, even empty) and the head's has a name it does not. Only an absent baseline permits an initial allowance of any size; a baseline that exists, at zero or not, can only be adopted as a subset of itself.
4. A base baseline that is neither `null` nor a list of unique names (so a missing or malformed discovery of it), a head baseline that is not a list of unique names, a missing `base`, `head`, `change` or `window`, or a time that cannot be read is `UNKNOWN`, never a pass.
5. An adoption at zero (`to: 0`, an empty head baseline) is accepted from an absent baseline and over an existing empty one, and leaves a ratchet that `judgeRetirement` can retire at once. It writes nothing, and `judgeProgress` and `judgeRetirement` behave as before.
