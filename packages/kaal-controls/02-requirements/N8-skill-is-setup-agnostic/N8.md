# controls/N8 skill-is-setup-agnostic

The Skill and its scripts know nothing of the KAAL repository. They name no KAAL path, scope, capability, id or folder layout, and work in any setup. Anything specific to a setup, such as the directory to check, comes in as input. The check is copied alone out of the repository and still runs on controls in any folder layout. The Skill may name the declaration it defines (`<capability>/CTL<n>` and the four DIRT values) and nothing of where a repository keeps them.

The Skill is also a package that works on its own. It depends on no other Skill or package, and in particular it does not point at the `kaal-testing` Skill. The only dependencies it may have are the foundation, for shared semantics, and the hosting, for OS-specific execution. Its own text says what it needs of verification, validation and a finding.

The Skill names no station and no flag of an adopter. The stations a control may declare come in as input.

Engineering carries what is specific to KAAL: which folder it checks and where its migration note lives (controls/A11).
