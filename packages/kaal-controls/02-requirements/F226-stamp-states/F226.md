# controls/F226 stamp-states

1. **Declared decision.** `flagState(value)` in `scripts/stamp.mjs` reads what the flag chooses: `PREVENTING` for `preventing` and the legacy `on` (controls/F216), `ADVISORY` for `advisory` and the legacy `off`, `STOPPED` for `stopped`. Anything else, including `null`, the empty text, another case and a missing flag, is `UNKNOWN`. `UNKNOWN` is not a state of STAMP and is not Mute: it says the authorized decision cannot be determined, which is a configuration error (controls/F224 item 4). Stopped never blocks. Advisory runs and reports and never blocks delivery. Preventing allows a pass and blocks a fail or an unknown result (Torn and Mute included). An unknown decision (this item) and an unknown result (a run without a verdict, item 4) are different: the first blocks CI as a configuration failure (controls/F224 item 7), the second is judged by the known decision.
2. **Boundary.** `toBoundary(name, value)` gives what the adopter hands to the adapter as `boundary.flag`: `{ name, value: 'on' }` for `PREVENTING`, `{ name, value: 'off' }` for `ADVISORY`, `null` for `STOPPED` (the adopter does not run the control), and it throws for `UNKNOWN` and for a name that is not non-empty text. An unknown flag is never converted into off or into on. The adapter is not changed.
3. **Runs.** `runs` is the list of the established runs of one control in one place, for the content examined, oldest first, each `{ run, verdict, applied, blocked }`: `verdict` is `PASS`, `REPORT`, `FAIL` or `UNKNOWN` from the record, `null` when the adopter established the run and has no record; `applied` is `true`, `false` or `null` as the record tells it; `blocked` is `true`, `false` or `null` (not known) and is what the run actually did to delivery, from the adapter's answer.
4. **Observed signal.** For a declared `ADVISORY` or `PREVENTING` control: `MUTE` when there is no run (reason `no-trace`), `TORN` when the latest run has a verdict `UNKNOWN` or none (reason `no-verdict`), else `OK`. A declared `STOPPED` control expects no run, so its `observed` is `N/A` and absence is never Mute.
5. **Blocking by the decision.** `blocking` is what the declared decision and the observed signal call for: `false` for `STOPPED` and `ADVISORY`; for `PREVENTING`, `true` when the signal is `TORN` or `MUTE` and, when it is `OK`, when the latest verdict is anything but `PASS` (Preventing permits a pass only). A `REPORT` there is an anomaly, because the adapter gives a pass or a fail in a preventive run: it blocks and the finding `unexpected-verdict-while-preventing` is named. `blocked` is the evidence of the latest run (`null` without a run). The two are always both shown.
6. **Mismatch.** The library names a mismatch and never conceals it: `ran-while-stopped` (a Stopped control has a run for the examined content), `blocked-while-stopped` (it blocked), `blocked-while-advisory`, `blocked-unexpectedly` (blocked where the decision did not call for it), `not-blocked-while-preventing` (the decision called for blocking and the run did not block), `unexpected-verdict-while-preventing` (a `REPORT` under Preventing). Runs are scoped to the examined content, so an old run from before a stop does not trigger a finding.
7. **STAMP.** `judgeStamp({ declared, runs })` gives `{ declared, observed, stamp, blocking, blocked, reasons }`. `stamp` is `STOPPED` for a stopped decision, `TORN` or `MUTE` when the signal is, and else the declared decision. For `UNKNOWN`, `declared`, `observed`, `stamp` and `blocking` are `null`, `reasons` has `config-error`, and `blocked-without-flag` is added when the latest run blocked: a caller that passed no flag at all is a legacy caller that the adapter still runs as asked (controls/F216 item 3), so it may block, and the report shows it. `reasons` also has `unproven-preventing` for a Preventing decision with no earlier Advisory run that gave a verdict (an `applied` of `false` and a verdict other than `UNKNOWN`): a finding, not a change of state, and a rule over changes of the file is the Owner's decision. Reasons are sorted and unique.
8. Anything that cannot be read as above (a `declared` that is not one of `STOPPED`, `ADVISORY`, `PREVENTING`, `UNKNOWN`, `runs` that is not a list of whole runs) throws, and a caller treats it as unknown. Nothing here blocks anything by itself: the adopter's gate acts on `blocking`.
9. Authorization. The first entries and each escalation are separate Owner decisions. This Change defines the vocabulary, the validation and the report; it enables nothing.
