# controls/F39 ratchet-history

1. `judgeProgress({base, head, change, window})` in `scripts/ratchet.mjs` is pure and says PASS, FAIL with one reason, or UNKNOWN when `base`, `head`, their baselines or histories, `change` or `window` is missing.
2. A head baseline with the same names as the base's adds no history line (`history-without-change`).
3. A head baseline that lost names adds exactly one line, `history-missing` otherwise, whose `from`, `to` and `removed` equal the sizes and the difference of the two baselines (`line-mismatch` otherwise).
4. The history of the base is a prefix of the head's (`history-rewritten` otherwise).
5. `change` of the new line equals the id of the Change the pull request carries (`change-mismatch`), and that Change exists (`change-unknown`).
6. `at` is not before the last earlier line (`time-before-previous`) and lies inside the window (`time-out-of-window`).
7. A head baseline with a name the base's lacks fails `baseline-grew`, whatever the history says.
8. `judgeRetirement({base:{baseline, history}, head:{history}})` is pure. It says PASS when the base's baseline is empty and the history of the head equals the base's and ends in a line with `to: 0`. It fails `retired-early` when the base's baseline is not empty, `history-invalid` when the kept history is not a sound chain (every line whole, each line starting at the size the one before ended at, shrinking by exactly the names it lists, times not going back; the judge sees only the lines, so whether a line is true was judged when it was added by `judgeProgress`, and the adopter supplies the base's history as Git data), `history-removed` when the head's history is missing, shorter or different, and `history-incomplete` when the history does not end in `to: 0`. It says UNKNOWN when an input is missing. The history of a completed ratchet is kept after the baseline and the strategy are removed.
