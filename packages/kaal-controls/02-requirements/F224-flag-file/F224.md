# controls/F224 flag-file

1. The flag file is `flags.json`, kept in the folder that holds the adopter's control records, and its text is `{ "schema": "kaal-controls/flags@1", "flags": [ { "control", "place", "name", "value" } ] }`. `control` is the id of a control, `place` the place it runs in (a station, an opaque non-empty text of the adopter's), `name` the name of its flag (non-empty text) and `value` text or `null` (read and not set). One entry for each control and place. The adopter reads the file and hands the text over; the library reads no file, environment or variable (controls/F216).
2. `scripts/flags.mjs` exports `parseFlags(text)` and `flagSource(entries)`, pure. `parseFlags` returns the entries sorted by control and place, or throws and returns nothing: text that is not JSON, another schema, a `flags` that is not a list, an entry that is not whole, a control and place twice. A partly read file is never used.
3. `flagSource(entries)` returns `{ of(control, place), controls() }`. `of` is `{ name, value }` for an entry and `undefined` for none, so that a missing flag is passed on as missing and never as off. `controls()` is the sorted list of the `control@place` keys with an entry.
4. The source is a seam: anything with `of(control, place)` giving `{ name, value }` or `undefined` is a flag source, and `controls()` is optional. The file is the only source built. A source from Hosting is a later decision and no script of the library names one.
5. Ownership. The library (the package) owns the format, the reader and the report and ships no flag file and no adopter name. The adopter's controls instance owns the file and its values. In KAAL it is `engineering/14-operations/controls/flags.json`, beside the control records, and a flip is a pull request that changes that file, reviewed as a change. The library never writes it. The format is open to a later schema version with more fields (a history line, a reason) because an entry is an object and `parseFlags` refuses a schema it does not know.
6. Which text is read is the adopter's: the file as it is at the base of the pull request, never the pull request's own copy, as for a baseline (controls/F211), so a pull request cannot switch off the control that judges it. The library cannot tell and says so; it does not read.
7. Authorization. The first entries of an instance's flag file and each escalation of a control in a place are separate Owner decisions, each a reviewed change of the file. The library enables nothing and a missing or unknown flag never authorizes enforcement (controls/F226 item 4).
