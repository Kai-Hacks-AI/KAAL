# controls/F209 demand-record

1. `scripts/demand-record.mjs` exports `findRecordDue({controls, observed, revision})`, pure. A control is `{id, claimed}`, `claimed` being `{defined, implemented, running, tested}`.
2. `observed` is the list of observations `{control, revision, installed}` made of the actual implementation or delivery of each control, `true` or `false`, independently of the declaration. An observation counts only for its own control and the applicable `revision`. A list the adopter merely supplies is not an observation.
3. For every control observed installed at the revision whose record does not claim `implemented`, the finding is `record-due:<id>`. Installing is a WIRE, which cannot write package files; the record is therefore due on the owning capability's next pull request into its collector. This is one fact only: running and tested are other facts, compared by other controls, and none implies another.
4. A control with no observation for the revision, or malformed input, makes the check throw, so that the adapter fails closed with `UNKNOWN` and no clean result is given from missing evidence.
5. The answer is a sorted list of unique names and is empty only when every observed control agrees. It reads no file and writes nothing, and knows no repository, path, flag or service.
