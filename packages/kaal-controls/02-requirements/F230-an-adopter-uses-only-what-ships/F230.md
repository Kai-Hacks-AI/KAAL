# controls/F230 an-adopter-uses-only-what-ships

1. The shipped files are those the package's `files` select: `skills`, less the `!` entries. A consumer is a temporary directory outside the repository, holding the shipped files as `node_modules/@kaihacksai/kaal-controls/` and nothing else of the repository. It imports the package by name, by the paths of the shipped files, and by no other.
2. Every relative import of a shipped `.mjs` file resolves to a shipped file (a shipped file never imports a deprecated shim, a Case, or a path outside `skills`).
3. The consumer has its own stations (`Merging`, `Shipping`), its own control records, its own flag file and one ratchet, and goes through the cycle with the public functions: `findControls` with its stations, `registryAt` for a station, `parseFlags`, `flagSource`, `validateFlags` and `decideOutcome` for its flags, and `runControl` for a control in detective, preventive and ratchet mode. Each answer is the one the controls say: a valid declaration is listed, an invalid one is refused with a recovery, a preventive finding blocks, a detective finding reports, a ratchet blocks only above its baseline, a missing or unknown flag is a configuration failure (exit 1).
4. A declaration of a station that the consumer did not give (here a name of KAAL's own) is invalid, and nothing the package returns names a station other than the consumer's own: not in a finding, a recovery, a reason or a log line.
5. The fixture adds no file to the shipped set and edits no script; it only reads them, from a copy.
