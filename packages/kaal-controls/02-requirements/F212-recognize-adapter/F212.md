# controls/F212 recognize-adapter

1. `scripts/recognize-adapter.mjs` exports `recognizeIntegration({control, entry, adapter, revision})`, pure. `entry` is `{path, text}`: the delivered entry of that control as the adopter read it at the revision. `adapter` is the path of the adapter module of the package, in the same root as `entry.path`.
2. It recognizes an integration only when all of this holds in the text after comments are removed: an `import` of `runControl` (aliased or not) whose specifier, resolved against `entry.path`, is exactly `adapter`; and a call of that binding that is outside comments and string or template literals and outside a branch that cannot run (`if (false)`, `if (0)`, `if (null)`, `if (undefined)`). It then returns `{control, revision, integration: 'recognized'}`.
3. It is structure, not execution. A recognized integration is no claim that the entry ran, that the call is reached or that its result is used. A string, a comment, an unused import, a call of another function of the same name, and an adapter module that is not `adapter` give no recognition.
4. It never returns a finding. What it does not recognize is unknown and the function throws, whatever the reason: no entry, empty or not text, an import without a recognized call, a call without the import, an unrelated adapter module, or `control`, `adapter` or `revision` that is not a non-empty string. Nonconformance is never inferred from the absence of a pattern; it comes from other evidence and is not in this Requirement. Evidence of execution is a run record (controls/F203), separate from this.
5. A declaration of the control is never read and cannot make the answer true.
6. It reads no file and writes nothing, and knows no repository, path, flag or service. Which file is the delivered entry of a control, and where the check runs, is the adopter's: release owns the delivery map, the station and the flag.
