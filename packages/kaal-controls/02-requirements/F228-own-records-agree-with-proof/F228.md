# controls/F228 own-records-agree-with-proof

1. For each control of the package under `14-operations/controls` (CTL1 to CTL5, and any later one), the four facts are derived from the package's own files only:
   - `defined`: the control's record is a valid declaration (the finder lists it without a problem);
   - `implemented`: the check it names exists as a file of the Skill's scripts. A control sits in a folder `CTL<n>-<name>`, and its check is `skills/kaal-controls/scripts/<name>.mjs`;
   - `running`: false for a control that no station registers and that no run of the adapter observed, which is every control of the package today (the package observes no runs of its own);
   - `tested`: a Case of the package names the control itself in its `tests` list.
2. The record of a control is its `status`, read as the ladder `designed`, `implemented`, `running`, `tested`: a status claims its own fact and every fact before it.
3. `assessRecord` (controls/CTL3) applied to these claims and these facts finds nothing: no fact lags and none overclaims. Today it finds `implemented:lags` for each of CTL1 to CTL5, because each record says `designed` while its check exists.
4. A fact that cannot be derived is unknown and never agreement, as CTL3 does.
5. Raising a status needs the proof first: the Change that raises a record also shows the fact it claims, and `running` and `tested` are not claimed by this Change.
