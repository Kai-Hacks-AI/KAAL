# controls/F20 incomplete-stays-listed

Discovery is kept apart from validation. A control is every item whose frontmatter `id` is `<capability>/CTL<n>`. The finder lists **every** control it finds, whether its declaration is complete or not, so an incomplete declaration never disappears from the inventory.

For each control the finder reports the fields it declares, its `status` as declared when it has one, and a `problems` list. A problem names the `field` (`title`, `description`, `type`, `status`, `has`, `id` when it is a duplicate, or a field a control does not have), the `reason` and a `recovery` that says what to change and points at `references/declaring-controls.md`. A control is `valid` when `problems` is empty. Every problem of a control is named, not only the first.

This replaces the refusal of controls/F13, F14, F16 and F17. An item that was refused whole is now listed and fails validation. The finder keeps `refused` for existing readers as the controls that fail validation, each with `path`, `id` and `reason`, and they are also in `controls`. A control whose only problem is that `status` is missing is listed with `valid: false` and is not in `refused`, because declarations made before the status existed must not read as refused. A Change id such as `<capability>/C8` is still not a control.
