# controls/F200 accepted-failure

1. `scripts/accept.mjs` exports `judgeAcceptance({results, acceptances})`, pure. `results` is a list of `{control, status, failing}` where `status` is `PASS`, `FAIL` or `UNKNOWN` and `failing` lists the ids of the failing Test Cases. `acceptances` is a list of `{control, testCase, defect, owner, reason, voided?}`.
2. The answer is `{verdict, report, unused, reasons}`. `report` has one entry per result, `{control, status, accepted, uncovered}`: `status` is copied unchanged from the result (an acceptance never changes it), `accepted` is true only for a `FAIL` that cites at least one Test Case and whose cited Test Cases are all covered by an acceptance for that control, and `uncovered` lists the cited Test Cases that are not covered.
3. `verdict` is `PERMIT` when every result is `PASS` or an accepted `FAIL`. It is `BLOCK` when any result is `UNKNOWN`, a `FAIL` that is not accepted, or a `FAIL` with no cited Test Case. An acceptance covers only its own control and Test Case, so a failure with a different Test Case, or the same Test Case on another control, is not covered.
4. An acceptance missing `defect`, `owner` or `reason`, or naming no `control` or `testCase`, covers nothing and is listed in `reasons` as `bad-acceptance`. An acceptance that matches no failing Test Case is listed in `unused` and does not block. An acceptance marked `voided` (its Defect is fixed) covers nothing even when its Test Case fails again: the failure is uncovered and blocks until a new acceptance for it, with its own Defect, is given. A voided entry is listed in `unused` and stays visible for cleanup, and the judge reads no Defect state: marking an entry voided is the adopter's. `verdict` is `UNKNOWN` when `results` or `acceptances` is not a list.
5. The answer holds only those fields. It writes no file, changes no result, and activates nothing.
6. `references/acceptance.md` teaches in setup-agnostic words that a finding becomes a Test Case and a Defect, that an accepted failure stays FAIL flagged ACCEPTED, that delivery may be permitted for the named failure only, and that a new or different failure does not inherit an acceptance. `SKILL.md` points at it and stays at or under 600 words.
