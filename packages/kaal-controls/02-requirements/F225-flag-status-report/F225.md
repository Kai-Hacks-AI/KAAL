# controls/F225 flag-status-report

1. `scripts/flag-status.mjs` exports `reportFlags({ controls, source, running })` and `renderFlagStatus({ title, rows, findings })`, pure. `controls` is a list of `{ id, type }` with `type` one of `directive`, `preventive`, `detective`, `corrective` (the finder's answer). `source` is a flag source (controls/F224). `running` maps a control id to the answer of `judgeRunning` (controls/F217) with `last`, `{ run, sha }` of the last counted record in the order the adopter lists its records (newest last), or `null`.
2. `reportFlags` gives `{ rows, findings }`. One row per control, sorted by id: `{ control, type, flag, state, effective, applied, running, last }`.
   - `flag` is `{ name, value }` or `null` when the source has none; `state` is `on` when the value is exactly `on`, `off` for any other value including `null`, `UNKNOWN` when there is no flag (controls/F216).
   - `effective` is what the next run would do: for a `preventive` control `preventive` when the state is `on`, `detective` when `off`, and the type as asked when `UNKNOWN`; `detective` for a `detective` control; `none` for a `directive` or a `corrective` control, which take no flag.
   - `applied`, `running` and `last` come from `running`; with no answer they are `null`. They are never read as a pass and never as `false` for running.
3. Findings, a sorted list of unique names, each a report and never a block: `no-flag:<id>` for a preventive or detective control with no flag; `orphan-flag:<id>` for a flag of a control that is not in `controls` (only when the source can list); `flag-disagrees:<id>` when the state is `on` and `applied` is `false`, or the state is `off` and `applied` is `true`; `never-ran:<id>` for a control with a flag and no counted run. `null` is unknown and gives no `flag-disagrees`.
4. `renderFlagStatus` returns Markdown: a table with `Control`, `Type`, `Flag`, `Value`, `State`, `Effective`, `Applied`, `Running` and `Last run`, then the findings as a list. The text is built from the rows and findings only.
5. The report changes no flag and decides no verdict. Which records exist and how a run is established are the adopter's, and Release supplies them. No script of the library names an adopter, a hosting platform or a path of an adopter.
