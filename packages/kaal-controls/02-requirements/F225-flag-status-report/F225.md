# controls/F225 flag-status-report

1. `scripts/flag-status.mjs` exports `reportFlags({ controls, source, runs })` and `renderFlagStatus({ title, rows, findings })`, pure. `controls` is a list of `{ id, type, places }` with `type` one of `directive`, `preventive`, `detective`, `corrective` and `places` the non-empty list of the places the control is wired in (the stations the adopter passes, controls/C161). `source` is a flag source (controls/F224). `runs` maps a control id to a map of place to the list of established runs of controls/F226 item 5.
2. `reportFlags` gives `{ rows, findings }`. One row for each control of type `preventive` or `detective` and each of its places, sorted by control and place: `{ control, place, type, flag, declared, observed, stamp, blocking, blocked, running, last, configError }`. A `directive` or a `corrective` control takes no flag and has no row.
   - `flag` is `{ name, value }` or `null`; `declared`, `observed`, `stamp`, `blocking` and `blocked` are from `judgeStamp` (controls/F226): the declared policy, the observed signal and the evidence of what blocked are three separate fields. `configError` is `no-flag` when there is no flag, `unrecognized-flag` when the value is not understood, else `null`; the three fields `declared`, `observed` and `stamp` are then `null`, because an unknown flag is not a state.
   - `running` is `true` when a run with a verdict other than `UNKNOWN` exists, else `null`; never `false`. `last` is `{ run, sha }` of the newest run when the run has a `sha`, else `{ run }`, or `null` without runs.
3. `findings` is a sorted list of unique names, each a report and never a block: the reasons of `judgeStamp` as `<reason>:<control>@<place>`, with `config-error` replaced by the row's `configError`, and `orphan-flag:<control>@<place>` for a flag of a control and place that is not in `controls` (only when the source can list). A mismatch (`blocked-while-stopped` and the others of controls/F226 item 6) is a finding, so a declaration never conceals what ran. The report does not fail validation: `validateFlags` (controls/F224 item 4) does, before execution.
4. `renderFlagStatus` returns Markdown: a table with `Control`, `Place`, `Type`, `Flag`, `Declared`, `Observed`, `STAMP`, `Blocking`, `Blocked`, `Running` and `Last run`, then the findings as a list. The text is built from the rows and findings only.
5. The report changes no flag and decides no verdict. Which runs exist and how a run is established are the adopter's. No script of the library names an adopter, a hosting platform or a path of an adopter.
