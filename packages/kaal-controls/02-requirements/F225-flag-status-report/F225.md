# controls/F225 flag-status-report

1. `scripts/flag-status.mjs` exports `reportFlags({ controls, source, runs })` and `renderFlagStatus({ title, rows, findings })`, pure. `controls` is a list of `{ id, type, places }` with `type` one of `directive`, `preventive`, `detective`, `corrective` and `places` the non-empty list of the places the control is wired in (the stations the adopter passes, controls/C161). `source` is a flag source (controls/F224). `runs` maps a control id to a map of place to the list of established runs of controls/F226 item 5.
2. `reportFlags` gives `{ rows, findings }`. One row for each control of type `preventive` or `detective` and each of its places, sorted by control and place: `{ control, place, type, flag, declared, stamp, blocking, running, last }`. A `directive` or a `corrective` control takes no flag and has no row.
   - `flag` is `{ name, value }` or `null`; `declared` is `flagState` of its value (`UNKNOWN` without a flag); `stamp` and `blocking` are from `judgeStamp`.
   - `running` is `true` when a run with a verdict other than `UNKNOWN` exists, else `null`; never `false`. `last` is `{ run, sha }` of the newest run when the run has a `sha`, else `{ run }`, or `null` without runs.
3. `findings` is a sorted list of unique names, each a report and never a block: the reasons of `judgeStamp` as `<reason>:<control>@<place>`, and `orphan-flag:<control>@<place>` for a flag of a control and place that is not in `controls` (only when the source can list). A `Mute` or `Torn` state is itself a finding through its reason.
4. `renderFlagStatus` returns Markdown: a table with `Control`, `Place`, `Type`, `Flag`, `Declared`, `STAMP`, `Blocking`, `Running` and `Last run`, then the findings as a list. The text is built from the rows and findings only.
5. The report changes no flag and decides no verdict. Which runs exist and how a run is established are the adopter's. No script of the library names an adopter, a hosting platform or a path of an adopter.
