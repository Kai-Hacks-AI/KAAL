# controls/F215 adapter-ratchet

1. `scripts/adapter-ratchet.mjs` exports `runAdapterRatchet({controls, delivered, observed, revision, scope, baseline, previous, boundary})`, async and otherwise pure: it reads no file, runs no command and knows no repository, path, flag or service. It runs verify Adapter (`findUnadapted`, controls/F206) as the check of a control in ratchet mode through the adapter (`runControl`, controls/F203). `baseline` is the list of `unadapted:<id>` names allowed, and `previous` is the base's accepted baseline, as for any ratchet.
2. `delivered` is an inventory `{revision, scope, complete, entries}` in the shape of controls/F207, the complete map of the controls found delivered, `entries` being their ids. It is usable only when `complete` is `true`, its `revision` and `scope` are the given ones, and `entries` is a list of ids. A missing, partial, stale, other-scope or malformed inventory, a bare list in its place, a missing `revision` or `scope`, and a call without input give `UNKNOWN`, blocked, never a pass and never filtered by an allowance. A control cannot hide from the ratchet by being absent from an incomplete map.
3. Only a confirmed bypass is a finding and only a finding can be allowed (controls/F206 item 4). Unknown evidence (a delivered control with no observation, a stale or malformed one, or contradictory ones) makes the whole answer `UNKNOWN`, blocked, with the confirmed findings kept beside it as `confirmed`, even when the baseline names that control. `UNKNOWN` never becomes an allowance and nothing is baselined from it.
4. The verdict is the library's for the ratchet mode, and this adds no rule of its own. The bypasses in the baseline pass as known. A confirmed bypass that the baseline lacks fails (`new-finding`). A baseline name that is not a confirmed bypass of this run fails (`stale-allowance`), so a bypass that is fixed leaves the baseline in the same step, and a name that was never a confirmed bypass is not an allowance. A baseline larger than the base's `previous` fails (`baseline-grew`). The baseline only shrinks.
5. An empty baseline with no confirmed bypass is `PASS` and says `then: 'preventive'`: the ratchet has ended and the control is plain preventive. An empty baseline with a confirmed bypass fails.
6. The first baseline and each reduction are judged by the ratchet library on the baseline and history files (`judgeAdoption`, `judgeProgress`, told apart by `judgeRatchetStep`, controls/F213); this function judges one run. No declaration-time rejection is built: the delivered controls are what the ratchet judges.
7. It stays a library function. Adopting the baseline, the map and the workflow are release's, and making the check required and blocking is the Owner's go and no part of it.
