# controls/F31 criterion-judged

1. A `:fail` run counts toward a control's minimum only when its base run did not withhold a fixture or a Case. A base record may carry `without`, the path of the mechanism that run was missing. A `without` that names a Case file (`T<n>.test.mjs`, `T<n>.red.mjs`) or a fixture path does not count. A base without `without` still counts, as before, and the verdict reports how many counted `:fail` runs name no mechanism (`unnamed`), so the gap is shown and nothing is silently stricter.
2. Every control is verified and judged, whatever its type, and nothing is stored on it. Two edges point at it: a Test Case `-verifies->` it (the Case's first line `// Case <id> tests: <control id>`, its results the run records of controls/F28) and a review `-validates->` it. The validation is a kaal-review record whose focus is `control` and whose `subject` is the control id, and the package keeps no validation record of its own. The package reads review's records by lookup from the control id and returns the reviews of a control with whether each read what a review of a control must read: every Intent the control `has` among its reference items and every Case that tests it among its actual items, naming what is missing. A control with no review shows `none`. A review is shown beside the result and never changes a verdict: a review that read everything does not make a control Tested, and one that found it wanting does not fail it.
3. Each control type carries what its Cases must show, and as much of it as a script can check is checked. A `:fail` head record may carry `shows`, what the provoked run showed: `{ refused: <station> }`, `{ reported: <ref> }` or `{ restored: <ref> }`. Preventive: the run counts only when `shows.refused` equals a station the control declares in the preventive mode, so a preventive control that declares no such station can never show the refusal at its boundary and is shown as `boundary unnamed`. Detective: it counts only when `shows.reported` names the report or finding the provoked condition produced. Corrective: it counts only when `shows.restored` names the restored state, and the base shows the deviation (RED) as it already must. Directive: a directive cannot be broken in a way that is caught, so it asks nothing of `shows`. A `:fail` run with no `shows` still counts, as before, and is shown as `unshown`, so nothing is silently stricter.
4. What stays a review's validation is what no script can settle, and the package says what a review of a control must cover: whether the Cases cover the criterion and not a nearby one (verification), whether the criterion serves the Intent, and for each type that the refusal covers the action and not a nearby one, that the report is the one the criterion needs, that the restoration is the wanted state, and for a directive that the guidance exists and is followed. A review is by an Agent other than the one that wrote the Cases.
