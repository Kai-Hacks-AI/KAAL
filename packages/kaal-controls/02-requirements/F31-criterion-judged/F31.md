# controls/F31 criterion-judged

1. A `:fail` run counts toward a control's minimum only when its base run did not withhold a fixture or a Case. A base record may carry `without`, the path of the mechanism that run was missing. A `without` that names a Case file (`T<n>.test.mjs`, `T<n>.red.mjs`) or a fixture path does not count. A base without `without` still counts, as before, and the verdict reports how many counted `:fail` runs name no mechanism (`unnamed`), so the gap is shown and nothing is silently stricter.
2. Every control has a verify part and a validate part, whatever its type. A judgement is a record `{ control, about, verdict, reason, by, ref, of }` in a file named `<n>.judgement.json`. `about` is `verification` (do the Cases cover the criterion) or `validation` (does the criterion serve the Intent). `verdict` is `covered`, `partly`, `not-covered` or `unresolved` for verification, and `serves`, `partly`, `not-serving` or `unresolved` for validation; `reason` says in a sentence which part of the criterion the Cases do or do not exercise; `by` names who judged; `ref` names what was read; `of` is the digest of the control file and its Case files as read. A record that fails this shape is listed as a problem and never read as a judgement. Run records and judgements never mix: reading run records skips judgement files.
3. The latest judgement of a control about each of the two is shown as `stale` when the digest of the control file and its Case files now differs from its `of`. A judgement is shown beside the result and never changes the verdict: `covered` does not make a control Tested, and `not-covered` does not fail one. Without a judgement the control shows `none` for that part.
4. Each control type carries what its Cases must show, and as much of it as a script can check is checked. A `:fail` head record may carry `shows`, what the provoked run showed: `{ refused: <station> }`, `{ reported: <ref> }` or `{ restored: <ref> }`. Preventive: the run counts only when `shows.refused` equals a station the control declares in the preventive mode, so a preventive control that declares no such station can never show the refusal at its boundary and is shown as `boundary unnamed`. Detective: it counts only when `shows.reported` names the report or finding the provoked condition produced. Corrective: it counts only when `shows.restored` names the restored state, and the base shows the deviation (RED) as it already must. Directive: a directive cannot be broken in a way that is caught, so it asks nothing of `shows`. A `:fail` run with no `shows` still counts, as before, and is shown as `unshown`, so nothing is silently stricter. The verify part is as deterministic as it can be made. The validate part is always a judgement; the type sets what each part must show. What stays judgement in the verify part is only whether the shown thing is the stated criterion: that the refusal covers the action and not a nearby one, that the report is the one the criterion needs, that the restoration is the wanted state, and for a directive that the guidance exists and is followed. The judgement names the type's expectation in its `reason`.
