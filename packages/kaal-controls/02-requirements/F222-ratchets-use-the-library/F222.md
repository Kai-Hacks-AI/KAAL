# controls/F222 ratchets-use-the-library

1. `scripts/lib/verify-ratchet-use.mjs` exports `findOwnRatchets({ ratchets, observed, revision })`. `ratchets` is the list of ids of the controls that declare `strategy: ratchet`. `observed` is a list of `{ control, revision, usesRatchetLibrary }` with a boolean. It returns the sorted list of `own-ratchet:<id>` for each ratchet observed with `usesRatchetLibrary: false`. Pure.
2. A ratchet with no observation, or an observation that is malformed, of another revision, or contradicts another, is unknown: the function throws and keeps what it confirmed on the error (`confirmed`, `unknown`), as `findUnadapted` does (controls/F215). Unknown is never a finding.
3. The same file exports `recognizeRatchetUse({ control, entry, revision })` for structure: `entry` is the text of the control's entry file. `usesRatchetLibrary` is true when it imports `ratchetStrategy` from the ratchet library or from the old path of `ratchet.mjs`, false when it is text that does not, and null when it is not text. It claims nothing about execution.
4. `scripts/ratchet-use-ratchet.mjs` exports `runRatchetUseRatchet({ ratchets, observed, revision, baseline, previous, boundary })`, which runs `findOwnRatchets` as a ratchet through `runControl` with id `controls/CTL6`. Only a confirmed own ratchet can be allowed; unknown is `UNKNOWN`, blocked; an empty baseline with nothing confirmed ends in `PASS` with `then: 'preventive'`.
5. The control `controls/CTL6` verify Ratchet use is declared detective, status designed. Adopting the baseline (the ratchets that compute their own allowance today), the map and the workflow are release's. Wiring it, making it required or blocking is the Owner's go and no part of this Change.
