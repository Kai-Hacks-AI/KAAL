# controls/F210 demand-evidence

1. `scripts/demand-evidence.mjs` exports `findEvidenceDue({base, head, facts})`, pure. `base` and `head` are lists of `{id, mode}`; `facts` maps a control id to `{running, tested}`, each `true`, `false` or `null`, established by its own proof for the head's revision (the adapter's `executed` for running, the Test Case evidence for tested).
2. For every control whose `mode` in `head` is higher than in `base` (`off` below `detective` below `preventive`; a control absent from `base` was `off`), the finding is `evidence-due:<id>` unless the facts the new mode needs are `true`: for a raise to `detective`, `running`; for a raise to `preventive`, `running` and `tested`, each required on its own, because neither implies the other. A fact that is `false`, `null` or missing is not carried: missing evidence never lets a raise pass. A control whose mode did not rise is never asked.
3. The answer is a sorted list of unique names and is empty only when every raise carries its evidence. Malformed input makes the check throw, so that the adapter fails closed with `UNKNOWN`.
4. It reads no file and writes nothing, and knows no repository, path, flag or service.
