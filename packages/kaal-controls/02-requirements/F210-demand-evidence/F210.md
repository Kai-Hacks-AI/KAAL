# controls/F210 demand-evidence

1. `scripts/demand-evidence.mjs` exports `findEvidenceDue({transitions, facts})`, pure. KAAL Control types are Directive, Preventive, Detective and Corrective, with no hierarchy, and this check invents no mode ladder and no advisory type. Whether a finding is advisory or prevents delivery is GitHub configuration, outside it.
2. A transition is `{control, kind, authorized}`, a proposed change of a control's activation or enforcement. `kind` is `activation` (the control is to be installed by a WIRE) or `enforcement` (an installed control is to be made to prevent delivery). `authorized` is whether the Owner's separate authorization for this transition is given, `true` or `false`.
3. `facts` maps a control id to `{defined, implemented, running, tested}`, each `true`, `false` or `null`, established independently by its own proof for the specific control and revision. None implies another.
4. The evidence that exists before a WIRE is `defined`, `implemented` and the testing applicable before installation (`tested`). Evidence that only exists after a WIRE is the actual installation, `running` and operational testing (`tested` for the installed control). So an `activation` needs `defined`, `implemented` and `tested`; an `enforcement` needs `defined`, `implemented`, `running` and `tested`. The precise evidence is the existing protocol's, which the control's declared `evidence` states; it is not restated here.
5. For every transition the findings are `evidence-due:<kind>:<fact>:<id>` for each fact the kind needs that is not `true`, and `evidence-due:<kind>:authorized:<id>` when `authorized` is not `true`. A fact that is `false`, `null` or missing is not carried: missing evidence never lets a transition pass. A control with no transition is never asked.
6. The answer is a sorted list of unique names, empty only when every transition carries its evidence and its authorization. Malformed input, or a `kind` that is neither `activation` nor `enforcement`, makes the check throw, so that the adapter fails closed with `UNKNOWN`.
7. It reads no file and writes nothing, and knows no repository, path, flag or service.
