# controls/F239 the first flags file is inert and advisory

Enduring requirement (Cases T1742 and T1743):

1. `engineering/14-operations/controls/flags.json` is a flag file of the library (`kaal-controls/flags@1`) that its own `parseFlags` accepts.
2. Every entry names a control that has a record, carries a state the library recognizes (`stopped`, `advisory` or `preventing`), and each control has one flag name in the convention `KAAL_<CAPABILITY>_<CONTROL>`.
3. `validateFlags` over the controls the file names, at the places it names, is ok.

Acceptance of C181 (evidence of that Change, not a permanent rule, so later entries, flips and WIREs do not break the suite):

4. The first file holds exactly eight entries: `release/CTL40` and `release/CTL41`, each at `Promoting`, `Collecting`, `Hotfixing` and `Wiring`, named `KAAL_RELEASE_VERIFY_PROMOTION_ORIGIN` and `KAAL_RELEASE_VERIFY_PROMOTION_HEAD_EVIDENCE`, all `advisory`, for controls declared preventive.
5. It is inert: at its DO no workflow or hook names it or supplies `KAAL_FLAGS`.

Another control, place, value or flip is a later Change, each on the Owner's decision.
