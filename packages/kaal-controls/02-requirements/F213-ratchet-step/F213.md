# controls/F213 ratchet-step

1. `scripts/judge-ratchet.mjs` exports `judgeRatchetStep({base, head, carried, window})`, pure: it reads no file, runs no command and knows no repository, Git ref or tool. `base` and `head` are each `{baseline, history}`, the text of the baseline file and of the history file at that revision, or `null` for a file the revision does not have. `carried` is a list of `{id, exists}`. `window` is `{from, to}`.
2. It parses the baseline as a JSON list of unique names and the history as whole JSON lines (a missing history is an empty one), tells the step and returns the verdict of the library's judge with `step`: `adoption` by `judgeAdoption`, `progress` by `judgeProgress`, `retirement` by `judgeRetirement`, or `unchanged` (PASS) when both files are the same text on both sides, or when neither side has a baseline.
3. The step is `retirement` when the head has no baseline and the base has one; `adoption` when the base has no baseline, or has one and no history while the head has a history (the base's baseline for the library is `null` only when the file is absent, a list otherwise); and `progress` otherwise.
4. `adoption` and `progress` take the one carried Change as the library's `change`. A carried list that does not hold exactly one Change is UNKNOWN. `unchanged` and `retirement` need none.
5. The reasons of a FAIL are the library's, unchanged. A baseline that is not a JSON list of unique names, a history with a line that is not a JSON object, a missing side, `window` or `carried`, or a time that cannot be read is UNKNOWN (`could-not-judge`), never a pass.
6. The functions of `scripts/ratchet.mjs` are not changed.
