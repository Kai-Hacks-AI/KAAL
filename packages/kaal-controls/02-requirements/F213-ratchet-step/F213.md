# controls/F213 ratchet-step

1. `scripts/judge-ratchet.mjs` exports `judgeRatchetStep({base, head, carried, window})`, pure: it reads no file, runs no command and knows no repository, Git ref or tool. `base` and `head` are each `{baseline, history}`, the text of the baseline file and of the history file at that revision, or `null` for a file the revision does not have. `carried` is a list of `{id, exists}`. `window` is `{from, to}`.
2. **Order of judgement.** (a) Validation first: both sides, `carried` and `window` are read and checked before anything else, and a baseline that is not a JSON list of unique names, a history with a line that is not a JSON object, a file that is neither text nor `null`, a missing side, `window` or `carried` is UNKNOWN (`could-not-judge`), never a pass. This holds when both sides hold the same unreadable text. (b) Only then the shortcut: both files the same text on both sides is `unchanged`, PASS. (c) Only then the step is told and judged.
3. The step is `retirement` when the head has no baseline and the base has one, judged by `judgeRetirement`; `adoption` when the base has no baseline, or has one and no history while the head has a history, judged by `judgeAdoption` (the base's baseline for the library is `null` only when the file is absent, a list otherwise); `progress` otherwise, judged by `judgeProgress`. Neither side having a baseline is `unchanged`.
4. Adoption and shrink are two steps and are never merged. A base that has a baseline and no history, and a head that has an adoption line and a further line, is an adoption, and it is rejected by the library (`line-mismatch`), never read as progress.
5. `adoption` and `progress` take the one carried Change as the library's `change`. A carried list that does not hold exactly one Change is UNKNOWN. `unchanged` and `retirement` need none.
6. The reasons of a FAIL are the library's, unchanged. The result carries `step`.
7. The functions of `scripts/ratchet.mjs` are not changed.
