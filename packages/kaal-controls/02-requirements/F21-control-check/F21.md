# controls/F21 control-check

The package holds the permanent check of the declarations, in `skills/kaal-controls/scripts/check-controls.mjs`, the scripts folder of the Skill. No script of the check lives anywhere else in the package or in Engineering. It takes the controls the finder lists and reports the problems of each as a problem with its `path`, its `id`, the `field`, the `reason` and a `recovery` (a missing or invalid `status` names `status`). The recovery says to add or correct the `status:` line as one of the four values, as the evidence supports, and points at `references/declaring-controls.md`. The check fails an incomplete declaration, and the inventory stays whole.

- `checkControls(files)` is pure and returns `{ ok, controls, problems }`, where `controls` is the whole inventory even when `ok` is false. It exports `DIRT`, the four values in order.
- The command line, `node check-controls.mjs <directory>`, is not part of what the package publishes. It lives on as a deprecated shim at the same path (controls/N8) until its callers use hosting, and the library moves to `scripts/lib/check-controls.mjs`. The shim prints every control it found on stdout, with its status and whether it is valid, prints each problem on stderr and exits 1, and exits 0 when every control is valid.
- The check never writes to a declaration and never chooses a status. A status is a claim, and the owner of the control makes it.
- Its Cases build their own fixtures in a temporary directory and read no declaration of this repository, so the check is tested without KAAL.
