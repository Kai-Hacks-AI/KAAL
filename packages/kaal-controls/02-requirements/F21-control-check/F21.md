# controls/F21 control-check

The package holds the permanent check of the declarations, in `skills/kaal-controls/scripts/check-controls.mjs`, the scripts folder of the Skill. No script of the check lives anywhere else in the package or in Engineering. It takes the controls the finder refuses and reports each as a problem with its `path`, its `id`, the `reason` (a missing or invalid `status` names `status`) and a `recovery`. The recovery says to add or correct the `status:` line as one of the four values, as the evidence supports, and points at `references/declaring-controls.md`.

- `checkControls(files)` is pure and returns `{ ok, problems }`. It exports `DIRT`, the four values in order.
- `node check-controls.mjs <directory>` prints each problem on stderr and exits 1, and exits 0 when no declaration is refused.
- The check never writes to a declaration and never chooses a status. A status is a claim, and the owner of the control makes it.
- Its Cases build their own fixtures in a temporary directory and read no declaration of this repository, so the check is tested without KAAL.
