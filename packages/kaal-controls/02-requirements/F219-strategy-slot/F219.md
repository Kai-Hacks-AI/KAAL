# controls/F219 strategy-slot

1. The controls library (`scripts/lib/judge-mode.mjs`, `scripts/lib/run-control.mjs`) fixes the steps of every control: evaluate (the check gives findings), evidence (one log line and one record that name the revision the caller says was judged), verdict. It knows the modes `detective` and `preventive` and no other.
2. A preventive control may name a strategy. `judgeMode({ mode, findings, strategy, strategies, ...input })` and `runControl({ ..., strategy, strategies })` take the name and a `strategies` object that maps names to `{ judge(input) }`, handed in by the caller. The library imports no strategy.
3. The strategy gets `{ findings, ...input }` and must return a verdict in the sense of `isVerdict`. Anything else is `UNKNOWN`, blocked, reason `strategy-invalid`. A name that `strategies` does not hold is `UNKNOWN`, blocked, reason `no-strategy`. A strategy on a mode that is not preventive is `UNKNOWN`, blocked, reason `strategy-not-preventive`. The library adds no rule of its own to a strategy's verdict.
4. `mode: 'ratchet'` is no mode of the library: it is `UNKNOWN`, reason `no-mode`.
5. Compatibility: the public entry `scripts/adapter.mjs` (and the command at `scripts/judge-mode.mjs`) is the composition root. It wires `{ ratchet: ratchetStrategy }` and still accepts `mode: 'ratchet'`, read as `mode: 'preventive', strategy: 'ratchet'`, so release's callers and the three workflow steps keep working and every Case that calls the old paths passes unchanged.
