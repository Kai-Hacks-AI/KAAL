# controls/F26 judge-then-sign

Judging and signing are two steps. The judge step runs every control of the registry of a station at the head of a pull request. A control answers by its `judge.mjs`, beside its declaration, which prints one JSON object with `verdict` PASS or FAIL and an optional `detail`. The code that runs is the code of the base. A control that has no `judge.mjs`, crashes, prints anything else, spells the verdict otherwise or does not answer in time is UNKNOWN, and the others still run. A verdict names its control, station, mode and head.

The sign step turns verdicts into checks. One check per registered control of the registry, named `<app> / <control title> (<Station>)`, on the exact head: PASS is success, FAIL and UNKNOWN are failure. A control of the registry that has no verdict is a failure. A verdict for a control that is not in the registry, or judged at another head, is not signed as a pass. The title comes from the registry, never from the verdict. Both steps are scripts of the controls Skill, take every location and name as a parameter and print facts. Deciding whether a station should have a control is not theirs.
