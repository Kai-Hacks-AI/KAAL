# controls/F29 state-beside-claim

For a control the package computes a state: `tested` when its declared minimum evidence is shown (the verdict of controls/F28 is PASS), `designed` for any other valid control, `invalid` for a control that fails validation. Implemented and running are not observed by the package and are never computed. The state is the highest the package can show, not a verdict on the claim.

For every control that declares a minimum, whatever its `status`, the package shows one line: the control id, `claimed <status>`, `computed <state>`, the progress of each declared kind of X as `<kind> <have>/<runs>`, with `fail` after a kind declared `:fail`, and the verdict with its reason. A control that declares no minimum has no line. The command exits 1 only when a control claims `tested` and is not shown, as before; a claim below `tested` never fails. The earlier JSON output stays available.
