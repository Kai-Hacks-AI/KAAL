# controls/F206 verify-adapter

1. `scripts/verify-adapter.mjs` exports `findUnadapted({controls, delivered, observed, revision})`, pure.
2. `observed` is the list of observations `{control, revision, adapted}` or `{control, revision, integration: 'recognized'}` that the adopter made of the actual implementation or delivery: whether the delivered entry of that control runs through the adapter, `true` or `false`. It is established independently of the control's declaration. An observation counts only for its own control and the applicable `revision`; a list the adopter merely supplies is not an observation.
3. A finding is **confirmed nonconformance** only: for every control that declares a station, or whose id is in `delivered`, with an observation `adapted: false` for the revision, the finding is `unadapted:<id>`. `adapted: true` gives nothing.
4. Unknown is not a finding. For a control that declares a station, or is delivered, a missing observation, a stale one (of another revision), a malformed one (`adapted` not a boolean, or no control or revision) or contradictory ones (two observations of the same control and revision that disagree) make the check throw, so that the adapter fails closed with `UNKNOWN` (C141). `UNKNOWN` is never filtered by a ratchet allowance and never passes, so only a confirmed `unadapted:<id>` can be baselined; no name for unknown exists to be baselined.
5. The answer is a sorted list of unique `unadapted:<id>` names and is empty only when every such control is observed to run through the adapter. An input that is not as described throws.
6. It reads no file and writes nothing, and knows no repository, path, flag or service. It stays detective and non-blocking; whether a finding blocks is GitHub configuration, and activation is a separate Owner decision.
7. Amended with controls/F212: an observation `{control, revision, integration: 'recognized'}` is structural evidence and counts as an observation for its control and revision. It gives no finding and no claim of execution. A finding comes only from `adapted: false`, which structure never produces: a control whose entry shows no recognizable integration is unknown (item 4), not nonconforming.
8. Structural and runtime evidence stay apart. A recognized integration of the same revision never overrides, hides or resolves an `adapted: false` observation: a control with both is still named `unadapted:<id>`. A recognized integration with `adapted: true` gives nothing. Only observations of `adapted` contradict each other: `adapted: true` and `adapted: false` for the same control and revision are contradictory (item 4) whether or not a recognition is also present, and a recognition never settles the contradiction.
