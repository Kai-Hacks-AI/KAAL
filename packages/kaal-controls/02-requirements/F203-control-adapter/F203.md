# controls/F203 control-adapter

1. `scripts/adapter.mjs` exports `runControl({id, mode, check, input, baseline, previous, boundary})`, async and otherwise pure. `check` is a pure function of `input` that returns a list of finding names. `boundary` is `{x, run, sha}`: the kind of X the run is on, and the run and revision that identify it. It reads no file and calls no service.
2. The verdict is the one `judgeMode` gives the findings in that mode, and in ratchet mode the one `judgeRun` gives with the baseline and the base's `previous`. The adapter adds no rule of its own to it.
3. It fails closed. A `check` that throws, a result that is not a list of unique names, a missing `id` or a mode that is not detective, preventive or ratchet gives `UNKNOWN`, blocked in preventive and ratchet, and never a pass.
4. The answer is `{id, mode, verdict, blocked, log, record}` with the fields of the verdict beside them. `log` is one object `{control, mode, verdict, findings, run, sha}` with the number of findings, and carries no date.
5. `record` is `{control, x, run, sha, verdict, by: 'adapter'}`. It is `null` when the boundary lacks `x`, `run` or `sha`: a run that cannot be identified leaves no evidence.
6. The adapter carries these five concerns only: the mode, the ratchet filter, failing closed, the log and the record. The check is called once, and the adapter never changes what it finds.
