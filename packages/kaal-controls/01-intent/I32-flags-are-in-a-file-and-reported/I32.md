# controls/I32 the flags are in a file and the library says what is declared, what is observed and what blocked, per control and place

Running of a control in a place has three things that are kept apart and always visible. The **declared decision** is chosen by the flag in a file, so that a change of it is a reviewed change with a history: Stopped (deliberately not run, never blocks), Advisory (runs and reports, never blocks delivery) or Preventing (a pass allows, a fail blocks). The **observed signal** is found by the library and never chosen: Torn (a loud broken signal, the control cannot give a usable verdict) and Mute (an expected signal is absent, no trace or verdict); they are reported under Advisory and block under Preventing, and a Stopped control expects no run, so its absence is not Mute. The **actual blocking evidence** says what a run really did to delivery. A mismatch, such as a Stopped control that nevertheless blocked, is a finding and is never concealed. These make STAMP: Stopped, Torn, Advisory, Mute, Preventing. An unknown flag (missing or not recognized) is none of them: it is a configuration error, validated before execution and failing it visibly, never converted into off and never into enforcement. The library defines the file format, reads its text and judges and reports; it ships no flag and names no adopter. The adopter's controls instance owns the file and its values, and the first entries and each escalation are separate Owner decisions. Escalation is stepwise: no Preventing without the proof of an earlier Advisory run. D, I and T of DIRT do not change.
