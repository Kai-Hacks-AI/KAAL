# controls/I33 the required lane runs the controls suite, so a Case of controls cannot miss a merge

Two promotions into `main`, each green in the queue, turned `main` red: the Case T1574 (the Skill names no hosting term) was run by neither. The Cases of `@kaihacksai/kaal-controls` run only in an advisory job on a pull request and never in the merge group, because the package is not a workspace of the repository, so the required lane that runs the tests of every workspace skips it. The intent is that the Cases of controls run in the lane that is required, on the pull request and in the merge group, like every workspace, so that a change cannot land on `main` while a Case of controls is red, and two changes that are green alone cannot turn it red together unseen. The suite is the package's own and is not moved, copied or rewritten (engineering/N2).
