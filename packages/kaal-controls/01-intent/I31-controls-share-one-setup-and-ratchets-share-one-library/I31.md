# controls/I31 controls share one setup and ratchets share one library

Every control behaves the same way: it evaluates, it leaves evidence of what it judged, and it gives a verdict, and the controls library is where that is written once (controls/I19). A ratchet is a strategy of a preventive control, not a type of its own, and every ratchet uses the one ratchet library for its baseline, its comparison and its regression rule, so all ratchets behave the same. The controls library does not know the ratchet library; the ratchet library stands on the same small base contract as the controls library. A ratchet that computes its own allowance is a finding. Evidence is collected the same way for every control: one reader of the run lines and one ledger format in the controls library, with the judged-revision check inside it, so each capability only declares its own counts.

Why: today the mode judge of the controls library imports the ratchet, so a ratchet looks like a mode of the controls layer, and nothing proves that a control declared as a ratchet uses the library at all. Kai's model (27 November): specific controls sit on the controls library, specific ratchets sit on the ratchet library, and both live in the controls Skill.
