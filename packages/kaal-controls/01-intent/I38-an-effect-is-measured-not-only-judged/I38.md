# controls/I38 an effect is measured, not only judged

A control that only answers pass or fail cannot show what it changed: the saving of fewer API calls, the shrinking of a baseline, the cost of a check. The intent is that Controls and its children, such as ratchets, have one standard way to report a measured value, so the effect of a control or a change is visible and comparable over time, in the same record as the run, while a measurement never decides a verdict by itself. A measurement that is missing stays unknown: it is never read as zero, as no change or as success.
