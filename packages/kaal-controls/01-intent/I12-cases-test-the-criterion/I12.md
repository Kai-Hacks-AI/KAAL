# controls/I12 cases test the criterion

A control states what it is for, and its Test Cases point back at it. The package can count that the Cases ran GREEN often enough and that a provoked failure was caught, but a Case can pass reliably on something nearby and a provoked failure can be a fixture, so a control could show Tested while its stated criterion is unproven. Whether the Cases exercise the criterion is partly a result and partly a judgement. Every control can be verified and validated, whatever its type. Verification is a script's result: does the control do what it says. Validation is an agent's judgement: is what it says the right thing for its Intent. The package checks what a script can check for verification, such as that the provoked failure broke a mechanism and not a fixture, and says plainly what it cannot. For the rest the Skill has an agent record two judgements beside the results: whether the Cases cover the criterion (about verification), and whether the criterion serves the Intent (about validation). A result is what a script produced. A judgement is what an agent read. The report shows both and keeps them apart.
