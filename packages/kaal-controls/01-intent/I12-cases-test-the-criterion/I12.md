# controls/I12 cases test the criterion

A control states what it is for, and its Test Cases point back at it. The package can count that the Cases ran GREEN often enough and that a provoked failure was caught, but a Case can pass reliably on something nearby and a provoked failure can be a fixture, so a control could show Tested while its stated criterion is unproven. Whether the Cases exercise the criterion is partly a result and partly a judgement. The package checks what a script can check, such as that the provoked failure broke a mechanism and not a fixture, and says plainly what it cannot. For the rest the Skill has an agent read the criterion beside the Cases, say whether they cover it, and record that as a judgement beside the results. A result is what a script produced. A judgement is what an agent read. The report shows both and keeps them apart.
