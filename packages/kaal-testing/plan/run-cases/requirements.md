# Run Cases and report their outcomes: Requirements

Each Requirement names, in brackets, the Intent it serves. All answer testing/I40.

## Functional

- **testing/F138** [testing/I40]: **Counts over leaf tests.** `runCases({ files, root, timeoutMs, streamsDir })` runs each file with `node --test` and returns `counts { GREEN, RED, UNKNOWN }` and a `tests` list. The counted unit is the leaf test (a test with no tests under it). A suite, a passing parent, a parent that failed only because a child failed, and the file-level result Node reports for each file are not counted. A parent whose own assertion fails after its children passed is counted once, with `role: "parent"`. Counts are test counts, not Case counts.
- **testing/F139** [testing/I40]: **Classification.** RED only for an assertion failure (`ERR_ASSERTION`). Any other failure, a cancelled test, a timeout, a skip and a todo are UNKNOWN, with a `reason`. Skip and todo take precedence over pass and fail. A test that never finished is never GREEN.
- **testing/F140** [testing/I40]: **Identity.** A test's `id` is its repo-relative path with `/` separators, its ancestors' names, its name, and an ordinal (`#2`, `#3`) for same-named siblings, joined with ` > `. Ids are unique in a report. Two tests with the same name under the same parent give a `duplicate-name` diagnostic. A rename or move shows as one removed and one added test: nothing is guessed.
- **testing/F141** [testing/I40]: **Case attribution, kept apart.** Each test has `case: { namespace, number, raw } | null`, taken only from a leading `ns/T<n>` or bare `T<n>` form on its own name or on the nearest ancestor, never from a file name. Two different references on a test and its ancestor attribute no Case (`case: null`) and give a `conflicting-case-reference` diagnostic. Attribution never changes a count.
- **testing/F142** [testing/I40]: **Completeness.** `execution.complete` is true only when every file ran to its end and every result was recognised. Otherwise `execution.problems` lists `{ file, kind, detail }` with kind one of `file-failed` (a load error, crash or error after the tests; its diagnostic is kept), `timeout`, `cancelled` (a test was cancelled, so tests after it may not have run), `suite-failure`, `empty-inventory` (a file with no test) or `unrecognised-output`. A problem keeps the results that were observed, never makes up a RED Case, and never erases other files. Invalid input (no files, a relative root, a missing file, a path outside root) is rejected and no report is produced.
- **testing/F143** [testing/I40]: **Comparison.** `compareReports(base, head)` returns every changed outcome (both directions, so equal counts cannot hide a regression), every added and removed test, each side's problems and diagnostics, and whether both are complete. An added or removed test is `provisional: true` when the file's execution was incomplete or absent on the other side. It returns no verdict.
- **testing/F144** [testing/I40]: **Command line and streams.** `kaal-testing run [--root dir] [--timeout ms] [--streams dir] <files…>` prints the report as JSON. It exits 0 whenever a schema-valid report was produced, including one with RED, UNKNOWN or problems, and non-zero only for invalid input or when no report can be produced; nobody takes acceptance from its exit code. With `--streams` it keeps each file's reporter stream, and the report can be reproduced from a retained stream alone.

## Nonfunctional

- **testing/N30** [testing/I40]: **Boundary.** The runner depends on Hosting and Node only, adds one export (`./run`) and one bin (`kaal-testing`), changes no Skill and no existing export, and writes nothing under the root it is given. Its scratch space is Hosting's isolated environment. It judges nothing and enforces nothing.
- **testing/N31** [testing/I40]: **Node 24.** Reports are reproducible for Cases that do not depend on scheduling or shared mutable state. The package requires Node 24 (`engines >=24`). Acceptance of the DO needs the fixtures GREEN on CI's Node 24 and the exact `node --version` recorded in the report. The reporter and tree reconstruction are validated there; passing on Node 22 does not satisfy it.
