# Hold adapter: Architecture

Each element names, in brackets, the Requirements it answers.

- **testing/A54** [testing/F158, testing/F159, testing/N36]: **`lib/cases.mjs`, `./cases`.** `collectCases(root)` walks the tree once, selects Case files by name, reads `id` and `tests` as text with one pattern that accepts both quote forms, and returns the sorted list and the two findings that make a Case unusable (`no-id`, `duplicate-id`). Form rules stay with `testing/C69`; once both are merged `check-cases` may take its file list from this catalog, a small follow-up. It is the first element built: everything else takes its list.
- **testing/A55** [testing/F160, testing/F161, testing/N36]: **`lib/observe.mjs`, `./observe`.** `observeCases({ report, cases, revision, expectedRevision, runId, producedBy })` is pure. It groups the report's tests by file, looks each Case's file up in the list, applies the F160 rules, and wraps the result with the provenance (F161). A test is attributed to a Case by its file's catalog entry. The report's own `case` field is not used to decide it: that field is derived from names and can disagree with the file.
- **testing/A56** [testing/F162, testing/N36]: **`bin/kaal-testing.mjs observe`.** Reads the report, calls A54 then A55, writes the two files. It follows the existing `run` command's discipline: exit 0 once the files exist, 2 for invalid input.
- **Where the observation runs** (not built here). One job produces the report with `kaal-testing run` over the catalog's files and then `observe`, in the pull request's CI, and uploads both files with the revision and run id. The hold judge job is in the same workflow and `needs:` it, so the artifact travels inside one workflow and no `workflow_run` or `pull_request_target` is needed. The source of both jobs goes in `engineering/` under its owning capability first, and a WIRE installs it on Kai's go. Release (`release/C122`) and engineering own that; this PLAN fixes only the contract between them: the `--observed` map and the evidence file. Because the pull request produces its own report, a hold PASS is evidence, not enforcement.
- **Alignment with release** (their Change). Release confirmed the ids and the quote-form gap. Its library imports no other capability (`T1314` pins that), so `applicableCases` will not import this catalog. Release widens its own reading to both quote forms in a small Change after `release/C122`, with a Case that pins it. Two readings of "which Cases exist" then stay in step by Cases and not by import. The contract between the capabilities is the `--observed` map and the evidence file only.
- **Touches in the DO.** `package.json` `exports` and `scripts.test`; the export pin in `T369` (the precedent is `testing/C68`); the `kaal-testing` README and bin usage line.
