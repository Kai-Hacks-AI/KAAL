# Hold adapter: Requirements

Each Requirement names, in brackets, the Intent it serves. All answer `testing/I45`.

## Functional

- **testing/F158** [testing/I45]: **The Case catalog.** `collectCases(root)` lists every Case file under `root`: a file named `T<n>.red.mjs` or `T<n>.test.mjs`, wherever it sits, except under `node_modules` and `.git`. For each it gives `{ id, file, tests, parked }`: the id from `export const id`, the claims from `export const tests`, the file relative to `root` with `/`, and `parked` true for `.red.mjs`. Single and double quotes both read. The files are read as text and never imported or run. The list is sorted by id (numbers by value), then file, so the same tree gives the same list in any directory order. It assumes nothing about where a Case lives, which Change it belongs to or what its path says.
- **testing/F159** [testing/I45]: **A catalog defect never removes a Case from Hold's judgment.** `collectCases` also returns `findings` for the two things that make a Case unusable for an observation: a Case file without an `export const id` (`no-id`), and an id declared by more than one file (`duplicate-id`, naming every file). Neither is dropped silently, and each reaches the boundary Hold reads, in the way its shape allows:
  - **`duplicate-id`** has an id, so the id stays in the `--observed` map as UNKNOWN with the finding as its reason. A Case under that id can therefore never be read as GREEN.
  - **`no-id`** has no id to put in the map, so the map alone cannot carry it. The evidence file therefore states `catalog: { complete: false, unobservable: [<file>…] }`, and the contract with Hold is that `complete: false` is a reason for Hold not to PASS, whatever the map says. `catalog.complete` is always present, true when the catalog has no finding.
  Testing reports the finding and Release owns the verdict: Hold's reading of `catalog.complete` is Release's Change and Release's Case, and the producing-job Change (see the Architecture) does not wire until that Case exists. Whether a Case is well formed otherwise (first line, id shape, existing targets) is `testing/C69`'s, and this Change repeats none of it.
- **testing/F160** [testing/I45]: **Observing a Case.** `observeCases({ report, cases })` joins a `kaal-testing/run-report@1` report to the catalog by file and returns, for each Case in the catalog, GREEN, RED or UNKNOWN with a reason. A Case is GREEN only when its file was run, at least one test of that file is attributed to it, every one of those tests is GREEN, and no execution problem names its file. A run that is incomplete with no problem to say where makes every Case UNKNOWN; a problem in one file never makes another file's Case UNKNOWN. It is RED when any of its tests is RED. Everything else is UNKNOWN: not run, no test, a skipped, todo, cancelled or timed-out test, a problem of the file, a finding of the catalog. A Case that could not run (a load error, a missing setup) is UNKNOWN, never RED. The attribution is the catalog's id for the file, never a path or a test name. A report that is not a valid `run-report@1` gives every Case UNKNOWN. A test of the report in a file the catalog does not list is reported as uncataloged and decides nothing.
- **testing/F161** [testing/I45]: **Provenance, and no stale report.** The observation carries the exact revision the report was run at, the revision it was asked about, the run id (the recorder, `controls/C20`), and `producedBy`. With no report, with no revision, with no run id, or with a revision that is not the one asked about, every Case is UNKNOWN, and the evidence's `reason` says which. Evidence is labelled `producedBy: "pull-request"` whenever the run is the pull request's own CI, so a reader sees it was produced by the work under judgment.
- **testing/F162** [testing/I45]: **A command, and the file the judge reads.** `kaal-testing observe --root <dir> --report <run-report.json> [--form-report <case-form.json>] --revision <sha> --run-id <id> --produced-by <who> --observed <file> --evidence <file>` writes two files. `--observed` holds exactly `{ "<id>": "GREEN" | "RED" | "UNKNOWN" }`, the map `judge-act.mjs --observed` already reads. `--evidence` holds the revisions, run id, `producedBy`, the reasons, `catalog` (`complete`, the findings and the unobservable files) and the uncataloged tests. The command exits 0 whenever the files were written, UNKNOWN and RED included, and non-zero only for invalid input. Nobody takes a verdict from the exit code.

- **testing/F163** [testing/I45]: **One identity contract with `testing/C69`.** The catalog is the one reader of which Case files exist and which ids and claims they declare, exported as `collectCases(root)` and `readCase(text)`; `testing/C69`'s `check-cases` reads declarations through them and has no pattern of its own, so single and double quotes never give different coverage. A Case whose form is wrong (no first line, an id without a namespace, an id the file declares differently, a target that does not exist) stays in the catalog, and C69 reports it. The optional `--form-report` takes C69's `kaal-testing/case-form@1` report, and the evidence's `catalog.form` is `{ checked, findings }`: `checked` is false without a report, and the findings are copied from it. A form finding of an identity-affecting kind (`case-id`, `id-differs`, `duplicate-id`) sets `catalog.complete` to false, because the ids of the map can no longer be trusted to be the Cases that exist. `first-line` and `target-missing` are copied and leave `complete` as it is, since they do not change which Cases exist. A form report that is not `case-form@1` sets `complete` to false. Testing issues no verdict: Hold reads `catalog.complete` and the Cases of its own.

## Nonfunctional

- **testing/N36** [testing/I45]: **Boundary and determinism.** The catalog and the adapter are pure functions over files and a report. No new dependency, two exports (`./cases`, `./observe`) and nothing else added, one command added to the existing bin. Nothing is written under `root`. The same inputs give the same two files, byte for byte, in any file order. Node 24 or later. Testing decides no verdict and imports nothing from release.
