## Functional

- **testing/F165** [testing/I46]: **Seeded property guidance inside `## Testing loops`.** `testing/C76` adds one concise bold subsection `**Seeded property and adversarial testing.**` inside `## Testing loops` in `skills/kaal-testing/SKILL.md` (right after `**Targeted Mutation Verification.**` and before `**Uncovered behaviour.**`), keeping all eight top-level `## ` headings unchanged. The guidance must cover:
  - **Non-overlapping triggers ("when to use what"):** Behavioural RED (before coding: fail on assertion rather than setup), Targeted Mutation Verification (after GREEN: prove assertion sensitivity against selected contract violations), and Seeded Property & Adversarial Testing (for pure/algebraic/parser/validator contracts: explore input breadth across permutations, correspondence/conservation laws, non-mutation, and adversarial shapes that hand-picked examples miss).
  - **Real invariants & explicit pre-classification:** Verify structural, algebraic, correspondence, or crash-free-contract laws rather than vacuous/tautological setups, and decide upfront whether each property is an **authoritative invariant** (failure can establish a contract breach) or an **exploratory hypothesis** (failure raises an `unknown` question rather than automatically claiming a defect).
  - **Explicit seeds & minimal counterexamples:** Use a deterministic seed (never unseeded randomness) and shrink any failing input so failures reproduce identically as `verified failure`.
  - **Separate routing for passing tests vs. product breaches:** Check contract authority and consumers first via the four existing finding kinds (`unknown` for uncontracted edges, Defect + parked RED Case when a counterexample breaches an authoritative contract rather than breaking `npm test` or silently patching production). Promote only **passing** fixed-seed checks and **passing** justified regression cases into existing executed test suites, avoiding heavy fuzz loops in `npm test`.
