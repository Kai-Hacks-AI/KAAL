# Seeded Property and Adversarial Testing: Intent

This is `testing/C75`, a PLAN Change. It ships no package code and modifies no Skill. `testing/C76` (Skill DO, strictly sequential after `testing/C75` merges) adds Seeded Property and Adversarial Testing guidance inside `skills/kaal-testing/SKILL.md`. `testing/C77` (Pilot DO/Check, strictly sequential after `testing/C76` merges) applies the technique via a bounded one-off run on `packages/kaal-testing/lib/duplicates.mjs` and `packages/kaal-testing/lib/contracts.mjs`, promotes justified counterexamples or fixed-seed regression cases into existing executed tests, and records a BASS judgment. One collector ACT retrospective (`packages/kaal-testing/02-learnings/retros/RT2.md`, provisional `testing/RT2`, verified unique across all `kaal/testing/*` branches before ACT) closes `[testing/C75, testing/C76, testing/C77]` before promotion to `main`.

**What is missing.** Behavioural RED (`testing/C71`–`C73`) proves a test fails on behavioural assertions before coding, and Targeted Mutation Verification checks assertion sensitivity against known contract clauses. Neither addresses **input breadth**: pure and algebraic modules (`duplicates.mjs`, `contracts.mjs`, parsers, validators) are still tested mainly with hand-picked examples, leaving combinatorial permutations, floating-point accumulation edges, prototype/special keys (`toString`, `__proto__`, `-0`, `NaN`), and composed invariants under-explored. Meanwhile, the Skill needs clear, non-overlapping triggers telling agents when to reach for Behavioural RED vs. Targeted Mutation vs. Seeded Property & Adversarial Testing without mixing up their roles.

- **testing/I46**: `kaal-testing` teaches **Deterministic Seeded Property & Adversarial Testing** inside `## Testing loops` with clear, non-overlapping triggers alongside Behavioural RED and Targeted Mutation Verification, keeps guidance strictly BASS-ordered (`Skill` first, zero new `scripts/` files unless earned by repeated practice), avoids synthetic prompt benchmarks in favor of practical execution on real KAAL modules (`lib/duplicates.mjs` for algebraic laws and `lib/contracts.mjs` to test what properties catch beyond `testing/C73`'s mutations), and uses Testing's existing four finding kinds and ownership boundaries.

**Out of scope.** No `skills/kaal-testing/scripts/` runner yet (deferred unless earned by `testing/C77`'s BASS judgment), no extra `references/` files, no new package exports or runtime dependencies, no top-level `## ` heading churn in `SKILL.md`, no cross-package edits (`kaal-core`, `kaal-graph`), and no synthetic LLM evaluation trial.
