# Seeded Property and Adversarial Testing: Intent

This is `testing/C75`, a PLAN Change. It ships no package code and modifies no Skill. `testing/C76` (Skill DO, strictly sequential after `testing/C75` merges) adds Seeded Property and Adversarial Testing guidance inside `skills/kaal-testing/SKILL.md`. `testing/C77` (Pilot DO/Check, strictly sequential after `testing/C76` merges) runs a bounded one-off property & adversarial pilot over `packages/kaal-testing/lib/duplicates.mjs` and `packages/kaal-testing/lib/contracts.mjs`, adds only passing regression/fixed-seed tests to `scripts.test`, routes any contract-breaching product failures cleanly to a Defect + parked RED Case without silent production fixes, records pre-classified property/BASS/guidance judgments, and closes with one collector ACT retrospective (`packages/kaal-testing/02-learnings/retros/RT<n>.md`, provisional `testing/RT<n>`, verified unique across all `kaal/testing/*` branches and release settlement vs. `testing/C74`'s collector before ACT, reflecting `[testing/C75, testing/C76, testing/C77]`) before automatic promotion to `main`.

**What is missing.** Behavioural RED (`testing/C71`–`C73`) proves a test fails on behavioural assertions before coding, and Targeted Mutation Verification checks assertion sensitivity against selected violations of known clauses. Neither addresses **input breadth**: pure and algebraic modules (`duplicates.mjs`, `contracts.mjs`, parsers, validators) are tested mostly with hand-picked examples, leaving combinatorial combinations, correspondence invariants, and hostile/inherited inputs (`toString`, `__proto__`, `constructor`, `-0`, `NaN`, malformed structures) under-tested — as shown by the CTO's review finding on `classify()` (`toString` / `__proto__` / `constructor`), which `testing/C73`'s mutations missed. Meanwhile, the Skill needs crisp, non-overlapping triggers telling agents when to apply Behavioural RED vs. Targeted Mutation vs. Seeded Property & Adversarial Testing and how to separate contract invariants from exploratory hypotheses.

- **testing/I46**: `kaal-testing` teaches **Deterministic Seeded Property & Adversarial Testing** inside `## Testing loops` with clear, non-overlapping triggers alongside Behavioural RED and Targeted Mutation Verification, keeps guidance strictly BASS-ordered (`Skill` first, zero new `scripts/` files unless earned by repeated practice), pre-classifies properties into authoritative invariants vs. exploratory hypotheses, routes product failures cleanly through Defect + parked RED Cases rather than broken `npm test` suites or silent production fixes, proves the technique practically on `lib/duplicates.mjs` and `lib/contracts.mjs` while assessing Skill-guidance decisions transparently, and respects Defect, Review, and Architecture ownership boundaries.

**Out of scope.** No `skills/kaal-testing/scripts/` runner yet (deferred unless earned by `testing/C77`'s BASS judgment), no extra `references/` files, no new package exports or runtime dependencies, no top-level `## ` heading churn in `SKILL.md`, no silent production fixes to `lib/contracts.mjs` or `lib/duplicates.mjs`, no cross-package edits (`kaal-core`, `kaal-graph`), and no synthetic LLM comparison trial.
