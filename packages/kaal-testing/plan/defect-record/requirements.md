# kaal-defect record definition: Requirements

Each Requirement names, in brackets, the Intents it serves.

## Functional

- **testing/F98** [testing/I25, testing/I27]: A Defect record is plain data with these members: `id` (nonempty, assigned by the raising context, unique in its holder, no format prescribed), `context` (the raising context, nonempty), `expected` and `observed` (nonempty text), `where` (the subject or location observed), and `status`. It may carry `obligation` (an opaque reference to the Requirements obligation) and `tests` (the identities of the Test Cases that expose it). A missing or empty required member, a duplicate `id`, or a key the record does not define is a finding. `where`, `obligation` and `tests` are opaque to Testing.
- **testing/F99** [testing/I26]: `status` is one of `reported`, `confirmed`, `answered`. Any other word is a finding, never a default.
  - `reported` carries no `tests`.
  - `confirmed` names at least one Case in `tests`, and needs **one common confirming Run** in which every named Case is `failed`. Separate Runs, each failing only some of the Cases, do not confirm: a Defect is confirmed at one observation of one subject, not assembled from several.
  - `answered` needs, for **each** named Case, a later Run in which that Case is `passed`, with its provenance identifying **the same Case at the same version** as the confirming Run (a Case with no declared version is identified by its identity alone). The passing Runs for different Cases may differ. A pass of another version of the Case, or one that cannot be tied to the confirming Run's Case, answers nothing. The latest Run that observed the Case must be the passing one: a later `failed` or `unknown` outcome withdraws the answer.
- **testing/F100** [testing/I26]: `state(record, evidence)` derives what the evidence shows: the status the record can claim. A claim without its evidence is unknown, never accepted: a `confirmed` record whose Cases are not all `failed` in one common Run (a Case `passed`, `unknown` or absent), or an `answered` record without, for each Case, a later pass at the same Case version that is its latest observation, is a finding. Missing or contradictory provenance is a finding and counts for nothing: a Run whose provenance does not identify a named Case, or identifies it at a different version in the confirming and the answering Run, shows nothing for that Case. Evidence is data in Testing's own format: `state(record, { model, runs })` takes a model and Runs of it exactly as `kaal-testing/model` defines them (`id`, `of`, `outcomes`, `provenance`; `testing/F30`, `F31`), listed oldest first, and reads each Case's result through the model's `results`. A Run with model findings shows nothing: its Cases are not counted as `failed` or `passed`. There is no second evidence format.
- **testing/F101** [testing/I27]: Defect instances and their Test Cases sit with the owning capability, in its own Defect Plan and, once answered, its Regression Plan. Testing defines the record shape and the evidence rules above and hosts no other capability's Defect or Case. The record carries no Plan membership. Where the Case lives, the Defect Plan before the answer and the Regression Plan after, is Change's wiring; a Case keeps its identity across Plans and its evidence stays with the Runs (`testing/F25`, `F30`).

## Nonfunctional

- **testing/N21** [testing/I26]: `check` and `state` are pure and deterministic: they read nothing from the host, write nothing and do not read the clock. Time is the order of the Runs given.
