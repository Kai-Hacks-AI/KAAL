# Pull Promotion from file state: Requirements (target)

Scoped `pull/` (ids are global). Replaces the input and the judgments of pull/F21 to F24 for the capability; those stay as the record of what shipped.

**Input.** `facts.collectors[]`: `name`; `at`, the head being qualified; `delta`, the files that differ from `main` (`path`, `status` added, modified or removed); `tree`, every path of the collector at its head; `history`, the commits of the collector since it diverged from `main`, oldest first, each with an `id` and the `paths` it changed (the collector's own order, by ancestry, never by time); `texts`, the text of the files the judgment reads, by path; `executions`, one per run of a Test Case (`case`, `head` the exact head it ran at, `conclusion` success, failure or pending, `at`). `declaration`: `collectors` (`name`, in their promotion order) and `evidence`: `plan` and `do` (lists of path patterns, regular expressions), `cases` (`files`, a path pattern whose first group is the Case id, and optionally `required`, Case ids the collector must hold), `act` (`files` a path pattern and `headings` the four 4L headings).

**The unit.** PDCA is judged for the **collector at promotion time**: it may hold one or more PLANs, DOs and Changes with a complete CHECK, and exactly **one** concluding ACT for the collected work, never one per Change.

- **pull/F25. Walk the declared collectors.** One entry per collector the declaration lists, in the declared order, once each; a collector the host lacks is not judged naming it; a host collector the declaration does not list is named in `undeclared`; an empty declaration is a problem. The same facts in any order give byte-identical output. (Carried over from pull/F21.)
- **pull/F26. PLAN and DO from the head tree; the delta is what promotion changes.** Two things are kept apart. The **delta** (what differs from `main`) says whether there is anything to promote: an empty delta does not qualify, saying so. The **head tree** (the collector's authoritative state) says whether the collected work holds its PDCA evidence: a collector has PLAN when at least one file of its tree matches a `plan` pattern, and DO when at least one matches a `do` pattern. No PLAN or no DO in the tree means it does not qualify, naming which. A PLAN or DO file that is already in the tree and does not differ from `main` (it landed earlier, or arrived by a sync) counts exactly as a newly introduced one; no evidence file has to be a delta file. A file the tree no longer holds (removed) never counts, whatever the delta says. The judgment reads paths only, never a pull request, a title or a trailer.
- **pull/F27. CHECK is every expected Case, at the exact head.** The expected Cases are the ids of **every file of the head tree** that matches `cases.files`, so a Case the delta did not change is still required, plus the ids the declaration pins in `cases.required` (a pinned Case the tree no longer holds means it does not qualify, naming it, so a deleted Case cannot shrink the set). Each expected Case needs an execution at the current head (`at` of the collector); the latest one (by `at`) counts and must be a success. A failure means it does not qualify, naming the Case. An expected Case with no execution at the current head, or whose latest is pending, means not judged naming it. A tree with no expected Case is not judged naming "an expected Test Case". An execution at another head, or of a Case that is not expected, never counts.
- **pull/F28. Exactly one concluding ACT, ordered by the history.** The ACT files are the delta files that match `act.files` and whose text holds all four headings (the retrospective of the collected work is new work of the collector, so it is a delta file; an ACT already on `main` concludes work already promoted). None means it does not qualify, naming the ACT; two or more mean it does not qualify, naming them. The one ACT must **conclude** the collected work: no file matching a `plan`, `do` or Case pattern is changed in any commit of the `history` **after** the last commit that changed the ACT file, judged by the position in `history` and never by a timestamp, file time or modification time (a later change to anything else, such as a README, does not matter, and two changes in the same commit are not "after"). Otherwise it does not qualify, naming the file changed after it. The history must **end at the head being qualified**, so the CHECK of F27 is the check of the exact head that includes the ACT; if it does not, or if a file cannot be placed in the history, it is not judged, naming which. A candidate whose text was not read is not judged.
- **pull/F29. Declared evidence, not a default.** A declaration with no `evidence`, or with an empty `plan`, `do`, `cases` or `act` entry, makes every collector not judged naming the missing declaration, never a vacuous pass. (Carried over from pull/T25.)
- **pull/F30. Provenance is not evidence.** The capability reads no pull request, title, trailer or review. Facts that carry pieces or pull-request fields yield the same result as facts without them.
- **pull/F31. Prioritize and stay advisory.** The qualifiers are listed in the declared order and the first is named as `next`; none qualifying gives the reason and what is missing per collector. The output never says ready or blocked, never authorizes a promotion, never recommends an action. Read-only, imports only a file reader. (Carried over from pull/F23 and F24.)
- **pull/F32. A collector is qualified from the work it owns.** A declared collector may carry a `scope`: a non-empty list of path patterns naming the capability it owns (its files and the records of its Changes). With a scope, everything the judgment reads is read **inside the scope only**: the PLAN and DO evidence of the head tree, the expected Cases (F27), the ACT candidates and the ordering of the history (F28). A collector whose delta holds no change inside its scope does not qualify, saying so. A collector whose delta holds a file **outside** its scope does not qualify, naming those files, so a scope cannot hide owned work by being narrow. A scope that is empty or not a list of patterns makes the collector not judged, naming the scope. Without a scope the collector is judged as F26 to F28 say. Evidence inherited from `main` for another capability never qualifies a scoped collector.
- **pull/F33. Evidence discovery is declared; test-file completeness is enforced, the rest is reviewed.** `cases.files` and `act.files` may each be one pattern or a list of patterns. The expected Cases of F27 are the Case ids of every `cases.files` pattern over the scoped head tree, and the ACT candidates are the delta files of every `act.files` pattern (exactly one concludes the work, F28). What the **qualifier enforces** is the completeness of the Cases: every file of the scoped head tree whose name ends `.test.mjs` is either a Case (it matches a `cases.files` pattern) or is declared not to be one (it matches a `cases.other` pattern, a list that may be empty); a test file that is neither makes the collector not judged, naming it, so a Case shape the declaration omitted can never let a collector qualify. What the qualifier **cannot enforce**, and which stays a separately reviewed responsibility of the declaration, is that its PLAN, DO and ACT patterns name every record shape of the repository: a record no pattern names is not seen, and the declaration is reviewed like any other file. Missing or ambiguous evidence still never qualifies.
