# analyze Flow: Requirements (target)

Scoped `coordination/`. F are functional, N nonfunctional. The control is `analyze Flow`, a detective control: it makes the state of the flow transparent and authorizes nothing. It borrows its language from Lean and the Theory of Constraints: WIP limit, constraint, pull, expedite, andon (as `escalate`) and unblock. The layers, from the outcome backwards, are Publishing, Promotion, Integration, Development. The six specialized templates are HOTFIX, PROMOTION, SYNC, ACT, DO and PLAN, with DEFAULT as the fallback; HOTFIX is the expedite class, an exceptional route and never a step of the normal lifecycle.

- **coordination/F1. One script in the Skill, `analyze Flow`.** `skills/kaal-release/scripts/analyze-flow.mjs` exports `analyzeFlow(facts, declaration)` and prints the same from a command line (`node analyze-flow.mjs <facts.json> <declaration.json>`). `SKILL.md` names it, and the package carries it. It is read-only: it reads two files and prints; it opens no network connection, runs no git or host command and writes nothing.
- **coordination/F2. Facts input.** A JSON file with: the target head; each collector (`name`, `head`, `behindTarget`); each change request (`number`, `type`, `change`, `base`, `head`, `headSha`, `state` open or merged or closed, `mergeable` clean or conflicting or behind, `checks` as name and conclusion, `unresolvedThreads`, `review` with its state and the commit it was given at, `autoMerge`). `type` is the template type the gatherer read from the declared template, and `change` the Change id the request names. Neither is parsed from a title or from prose here. A `review` of `null` means no review exists. An absent key means the fact is unknown. An unknown fact is reported, never defaulted.
- **coordination/F3. Declaration input.** A JSON file the consumer owns: the promotion `target`; the template `types` (promotion, sync, change types, hotfix, fallback); `policy.wipLimit` (the WIP limit of the promotion layer, one); `freshnessChecks` (the checks that fail when a collector is behind the target); `promotions`, the **ordered** pair declarations, each a collector and the Change it promotes; the `holds`; the role names for `author`, `reviewer`, `owner`. The Script names no KAAL identity.
- **coordination/F4. Output.** An ordered list of findings. Each finding is a next action: `rank`, `rule`, `action`, `target`, `layer` (promotion, integration or development), `kind` (promotion, sync or change), `pair` (the collector of its pair, if any), `purpose` (promotion or development, for a sync), `change`, `class` (expedite, for a hotfix), `reason`, `dependency`, `authority`, `status` (ready, waiting, blocked, escalate) and `evidence`. A separate `notJudged` list holds everything it could not decide. The same inputs give byte-identical output, whatever the order of the requests.
- **coordination/F5. Actions.** OPEN PR, REVIEW PR, REVISE PR, ENABLE AUTO-MERGE, WAIT. No other. Nothing is executed. An open request yields at most one entry, by precedence: REVISE PR (changes requested, unresolved threads, a conflict or a branch behind its base, or a failing check that is not waiting on a sync), then WAIT on a sync (a freshness check fails while its collector is behind the target), then REVIEW PR (no approval at the current head), then ENABLE AUTO-MERGE (approved at the current head, auto-merge off), then WAIT.
- **coordination/F6. Promotion pairs are declared, never inferred from titles.** A pair is a declared collector and Change. Its sync member is a sync-type request whose base is the collector and whose `change` is the pair's Change. Its promotion member is a promotion-type request whose base is the target and whose head is the collector. A member that does not exist is OPEN PR: the sync when the collector is behind the target, then the promotion, waiting on the sync. An existing promotion whose sync is missing is waiting on it.
- **coordination/F7. A development sync serves a named Change.** A change request into a collector is blocked on collector synchronization only when a declared freshness check fails and its collector is behind the target. A conflict, a branch behind its base, any other failing check and a missing review are not a sync need; they are REVISE PR or REVIEW PR. The development sync names the blocked Change: an existing sync-type request into that collector with that `change`, or OPEN PR when none exists. The blocked request waits on it. A sync that matches neither a declared pair nor a blocked Change has no purpose and is reported.
- **coordination/F8. One active promotion pair (the WIP limit).** The active pair is the first declared pair not complete. A pair is complete when a merged promotion request carries the collector's current head. Every other pair waits on the active one, however many of its requests are already open; an open request never makes a pair active. A development sync is not a pair member and does not occupy the lane. Nothing but a merged promotion releases it.
- **coordination/F9. Order and layers.** The Promotion layer is the constraint, and every other layer is subordinated to it. The list is pulled backwards from the outcome and printed forwards: an entry follows the entry it depends on; among entries with no unmet dependency, the layer nearest the outcome comes first (promotion, integration, development); ties by request number. The publishing layer is reported as not modelled.
- **coordination/F10. Types.** A hotfix is the expedite class: it gets its next action, is marked `class: expedite`, is outside the WIP limit, never occupies the lane, and its unmodelled route is reported. A request of the fallback type, or of an undeclared type, is reported and not classified.
- **coordination/F11. Authority is never converted.** Every entry names who may do it (`author`, `reviewer`, `owner`). A hold in the declaration makes the entry `escalate` for the owner. The Script cannot authorize.
- **coordination/N1. Standalone.** No runtime dependency; the Script imports nothing but built-ins.
- **coordination/N2. Generic.** The Script, its fixtures and its README contain no KAAL-specific identity (release/F5, T5).
- **coordination/N3. Honest.** The README states that the Script recommends and verifies nothing.
