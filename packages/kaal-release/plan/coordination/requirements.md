# Show WIP: Requirements (v1, target)

Scoped `coordination/`. F are functional, N nonfunctional. The capability is **Show WIP** (mnemonic SWIPE: Show Work In Progress Expectations). It answers one question: **for each open piece of work, where is it and what is its expected next move: WORK, REVIEW or WAIT?** It is visibility. It makes no release-policy judgment, defines no CI policy, authorizes nothing and gates nothing. A failing check is an observed fact that shows as WORK, not a rule. Whatever the host does not say is shown as UNKNOWN, never guessed.

This is the landing-first version (CPO, 12 Nov 2026). Deferred, and not part of this delivery: the queue and WIP limit, pairs, deliveries and provenance, holds, freshness and readiness rules, the PLAN/DO/CHECK/ACT/SYNCHRONIZE/PROMOTE activities, Change ids and roll-up, role views, no-piece branches, the shared observation contract (E1/E2), a model-driven classifier, and Publishing.

**Words.** A **piece** is one open request to move work from one place **from** into another place **into**. Its **type** is the declared prefix of its title (PLAN, DO, ACT, SYNC, PROMOTION, HOTFIX) or `unknown`. A **station** is a group of pieces named by an explicit mapping of `from` and `into`.

- **coordination/F1. One Script in the Skill.** `skills/kaal-release/scripts/show-wip.mjs` exports `showWip(facts, config)` and `render(report)`, and prints the rendered report from a command line (`node show-wip.mjs <facts.json> <config.json>`). `SKILL.md` names it. It exits 0 when it printed a report and non-zero only when an input cannot be read.
- **coordination/F2. Facts.** A JSON file with `pieces`, each with: `ref` (shown as given), `title`, `from`, `into`, `draft`, `review` (`approved` at the current version, `changes`, or `none`), `threads` (the count of unresolved threads), `checks` (`success`, `failure`, `pending` or `none`), `fit` (`fits`, `conflicts` or `behind`), `landing` (true when the piece lands by itself on approval); and `gaps`, a list of what the supplier could not read. An absent key is a fact that was not observed.
- **coordination/F3. Config.** A JSON file the consumer owns: `types` (the declared title prefixes) and `stations`, an ordered list of `{ station, from?, into? }` whose patterns may use `*` for any text. The first entry that matches a piece's `from` and `into` places it. A piece no entry matches is placed in `unknown station`, last. There is no default mapping.
- **coordination/F4. Type.** The type is the text before the first `:` of the title when it is a declared type, else `unknown`.
- **coordination/F5. Disposition.** One per piece, with a short reason, from observed facts only. WORK, by the first that holds: it is a draft; changes were requested; it has unresolved threads; it conflicts with what it goes into; it is behind what it goes into; its checks fail; it is approved but does not land by itself. Otherwise, if `review`, `threads`, `checks` or `fit` (or `landing` for an approved piece) was not observed: UNKNOWN, naming what was not observed. Otherwise: WAIT when its checks are running; REVIEW when it has no approval at the current version; WAIT when it is approved and lands by itself. No other disposition exists.
- **coordination/F6. Report.** `showWip` returns `{ stations, notObserved }`. `stations` lists the stations in the order of the config, each with its pieces by reference, and `unknown station` last if it holds any; a station with no piece is omitted. Each piece is `{ ref, type, from, into, disposition, reason }`. `notObserved` holds each UNKNOWN piece with its missing facts, and every supplier gap. The same two files give the same report, whatever the order of the pieces.
- **coordination/F7. Render.** `render(report)` prints a line per station and one line per piece: `#ref TYPE from → into DISPOSITION reason`, then the not-observed list.
- **coordination/F8. The reader.** In the consumer's Delivery (`engineering/release-management/05-src/show-wip/read.mjs`), never in the Skill. `readOpenPulls(repo, gh)` reads every open piece through the host's API in light pages (20 pieces a page) following the cursor, and maps each to the facts of F2. The checks are the newest run of each check name; a piece whose checks are cut at one page is read by the host's own roll-up state. A list the host cut at one page (threads, reviews) is complete only for what it shows: an unresolved thread on the page is a fact, none on a cut page is not observed; an approval of the current version on the page is a fact, none on a cut page is not observed. An approval counts only for the current version. Changes requested are WORK whatever the version. A conflict is `conflicts`, behind is `behind`, an unknown merge state is not observed. A page limit or a missing cursor is a gap, never a silent drop.
- **coordination/F9. The command.** `engineering/release-management/05-src/show-wip/run.mjs <owner/repo> <config.json>` reads through the host's command line the executing environment is signed in to (read-only API calls, a gateway failure read again a few times), runs the Script and prints the report. It exits 0 when it printed a report and 2 naming what it could not read. No credential is introduced.
- **coordination/F10. Standalone and read-only.** The Script imports only built-ins, calls no network, process or write API, reads only its two files, and contains no KAAL-specific identity and no host term.
- **coordination/N1. Honest.** The README states that the Script observes and shows, and recommends, authorizes and verifies nothing.
