# Coordination: Requirements (target)

Scoped `coordination/`. F are functional, N nonfunctional.

- **coordination/F1. One script in the Skill.** `skills/kaal-release/scripts/coordinate.mjs` exports `coordinate(facts, declaration)` and prints the same from a command line (`node coordinate.mjs <facts.json> <declaration.json>`). It is read-only: it reads two files and prints; it opens no network connection, runs no git or host command and writes nothing.
- **coordination/F2. Facts input.** A JSON file with: the target branch head; each collector (`name`, `head`, `behindTarget`); each change request (`number`, `title`, `base`, `head`, `headSha`, `state` open or merged or closed, `ci`, `behind`, `unresolvedThreads`, `review` with its state and the commit it was given at, `autoMerge`). A `review` of `null` means no review exists. An absent key means the fact is unknown. An unknown fact is reported, never defaulted.
- **coordination/F3. Declaration input.** A JSON file the consumer owns: the promotion `target`; which title words mean a promotion, a sync or a change (`kinds`); `policy.promotionsInFlight`; the ordered `candidates`; the `holds`; the role names for `author`, `reviewer`, `owner`. The Script names no KAAL identity.
- **coordination/F4. Output.** An ordered list. Each entry: `rank`, `rule`, `action`, `target`, `kind` (promotion, sync or change), `purpose` (promotion or development, for a sync), `reason`, `dependency`, `authority`, `status` (ready, waiting, blocked, needs-authority) and `evidence`. A separate `notJudged` list holds everything it could not decide. The same inputs give byte-identical output, whatever the order of the requests.
- **coordination/F5. Actions.** OPEN PR, REVIEW PR, REVISE PR, ENABLE AUTO-MERGE, WAIT. No other. Nothing is executed. An open request yields at most one entry, by precedence: REVISE PR (changes requested, unresolved threads, red CI), then REVIEW PR (no approval at the current head), then ENABLE AUTO-MERGE (approved at the current head, auto-merge off), then WAIT.
- **coordination/F6. Rules, in order.** R1 finish the in-flight promotion pair. R2 the missing step of the declared next candidate, when the lane is free: its sync when it is behind the target, then its promotion, shown as waiting on the sync. R3 development syncs and requests that unblock development, nearest to the target first. R4 the rest. Ties by request number. The order is derived backwards from the target and printed forwards in execution order.
- **coordination/F7. The promotion lane.** Busy while a promotion request is open or a promotion sync is open. A candidate is promoted when a merged promotion request carries the collector's current head; the lane is then released. Nothing else releases it; distance from the target never does. A development sync does not occupy it. A sync is a promotion sync when its base is the declared current candidate or the head of an open promotion; any other sync is a development sync; if the declaration does not settle it, it is reported.
- **coordination/F8. Authority is never converted.** Every entry names who may do it (`author`, `reviewer`, `owner`). A hold in the declaration makes the entry `needs-authority` for the owner. The Script cannot authorize.
- **coordination/N1. Standalone.** No runtime dependency; the Script imports nothing but built-ins.
- **coordination/N2. Generic.** The Script, its fixtures and its README contain no KAAL-specific identity (release/F5, T5).
- **coordination/N3. Honest.** The README states that the Script recommends and verifies nothing.
