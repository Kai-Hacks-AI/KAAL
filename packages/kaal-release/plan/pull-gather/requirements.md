# Pull Promotion: ready stock items are listed from verdicts that already exist (target)

Scoped `pull/` (ids are global). Nothing of pull/F25 to F49 is relaxed. Everything is advisory and read-only. STOCK = the branch's checks, OUT = opening the PR, IN = the target's ruleset. Selection reads only STOCK.

- **pull/F50. The package turns normalized stock items into deliveries.** `resolveDeliveries(facts)` in `scripts/deliveries.mjs` takes `facts.classes`, `facts.candidates` (`{id, class, name, revision, stock}`), `facts.authorities` (one STOCK authority per class), `facts.verdicts` and `facts.registrations`. It returns `deliveries`, each `{class, source, name, revision, ready, pull}` with `source` the item id, opaque to the package. An item of an undeclared class is ignored and reported as a finding. No `value`, `size` or `unit` is produced. Facts that are missing or not lists give no deliveries and a finding, and the input is not changed.
- **pull/F51. Ready means a consumed STOCK verdict at the exact revision.** `ready` is true only when `facts.verdicts` holds `{candidate, verdict: 'PASS', revision, authority}` with `revision` equal to the item's `revision` and `authority` equal to the class's registered one. Everything else (no verdict, another revision, another authority, `FAIL`, `held`, any unrecognised value) is not ready. The package reads nothing behind a verdict, so different classes with differently shaped evidence give the same result. A "P green" collector is not ready: that is the producing authority's judgment, and a missing or contrary verdict is never ready. Nothing about OUT or IN is read or required.
- **pull/F52. The adapter lists this installation's stock, with GET calls only.** `gather.mjs` lists the branches `kaal/<capability>/*`, `hotfix/*` and `wire/*` (routes read from the Engineering `kaal-pull.json`, never a literal prefix), reads their head SHAs and the published verdicts, and returns the normalized facts. `main` and every other branch is not an item. It uses only read requests and sends nothing that creates, updates, merges, approves, comments or dispatches; a failed or incomplete read leaves what it could not read not ready.
- **pull/F53. The package is host-neutral.** The same unmodified `scripts/deliveries.mjs` gives correct results for a different host, naming and source representation, and its source contains none of `kaal/`, `hotfix/`, `wire/`, `github`, `branch`, `.kaal` or a file or network access.
- **pull/F54. Auto-pull is opt-in at stock level, judge-pull is surfaced.** `pull` is `auto` only when the item's `stock` is in `facts.registrations`; every other item is `judge` and is still returned. Registration decides the mode only and never makes an item ready. Nothing in the result approves or merges.
