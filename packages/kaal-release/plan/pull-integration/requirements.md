# Pull Promotion v1 command: Requirements (target)

Scoped `pull/` (ids are global). It integrates the v1 capability (`pull/C3`) with the host; the merged capability record is `pull/C1`, kept as history. It is a separate Change on its own collector and borrows neither another Change's ACT nor its completion evidence.

Three things stay apart: the **execution environment** (any runner with Node), the **authentication** (an explicit read-only credential) and the **decision authority** (the Owner authorizes promotion; the command only reports).

- **pull/F14. The command.** `run.mjs <repo> <declaration file>`, in `engineering/release-management/05-src/pull-promotion/`, gathers with a small gatherer of its own what the capability (`pull/C4`, from file state) reads for each declared collector the host has: the **delta** against `main` and the commits since the collector diverged from it (the host's three-dot comparison, with the files each commit changed, read as a **history** and checked to be a line by ancestry), the **tree** at the head, the **text** of the ACT candidates (the delta files inside the collector's scope that match an `act.files` pattern), and the **executions of Test Cases at the exact head** (read from the logs of the completed CI jobs of that head: the newest run of a job counts, a red job counts against the Case, and only a Case reported under its scoped id is found). It passes them with the declaration to the capability and prints its result. It reads no pull request, title, trailer or review. It imports nothing of Show WIP, neither output nor supplier. What the host cut (a list over its limits, a history out of ancestry, a log it no longer keeps) leaves that collector without its file state: it is reported as not judged with the reason, never guessed, and a collector the host does not have is reported as not judged. The declaration (`declaration.json`: the collectors in their promotion order, each with the scope of the work it owns, and the evidence patterns) is reviewed like any other PR. This replaces the gatherer of pieces, deliveries and Check checks that this requirement first described; that description stays in the history of this file.
- **pull/F15. Explicit credential, read-only.** The command needs Node and one credential named explicitly: a token in `GH_TOKEN` or `GITHUB_TOKEN`, or an already signed-in `gh`. It reads no other environment and fails naming the missing credential or the host it could not read. The gatherer issues only reads: its source holds no request that is not a GET, and a Case checks that.
- **pull/F20. Not a trigger.** The command is run by a person or an agent and by nothing else. No Git hook, CI workflow, scheduled job, required check, ruleset or Guard names it, and none is added.
