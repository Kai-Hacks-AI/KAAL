# C144 ownership-table: who owns what in Process

Capability: process. Target collector: `kaal/process/ownership-table`.
Markdown only: no code, Definition, package, workflow or policy change.
The id C144 is provisional until the CPO confirms the next free id.

This record carries the ownership table of the earlier Process record
(`26/11/03/02`, which exists only on `kaal/old/process` and was never
promoted) onto the new structure, with two Owner rulings applied.

## Ownership

| Piece | Owner | Why |
|---|---|---|
| The metamodel (Process, Activity, Role, State, Transition, Ordering, Entry/Exit) | Process | Process's whole scope. |
| **PDCA**, the generic learning and improvement cycle, as a reusable template | Process (incubated) | Generic, and no other capability's semantics. |
| A capability's own lifecycle and records (a Change's PLAN, DO, CHECK) | That capability | The adopter owns its instance. |
| Evidence and verification semantics | Testing | Unchanged. |
| Persistence and retrieval of learning | **Undecided**; Learning is a candidate | Still open. |
| **DevOps** | **Process, for now** | Owner ruling (3 Nov): Process owns it until the Owner decides to split Process up. It is a Process instance, not its own capability. |
| **ESSA** (Eliminate, Standardize, Simplify, Automate) | **Process, for now** | Owner ruling (3 Nov). A separate candidate method, not part of PDCA. CMM/CMMI stays context only. |

Template and instance: a template is a reusable process design Process owns
because it is generic (PDCA). An instance is what a capability creates when it
adopts a template, and the adopter owns it. Process keeps no registry of
instances.

## Not changed

ACT is learning (not a closure status). No ESSA capability, Definition or
package is proposed. No CMMI implementation is proposed. No SYNC, promotion
or publication.

## Open

Where and how learning persists, and whether Learning owns retrieval.
