F5 (P2) — A seal must pass Sealing's verification, not merely exist.
Against R6, R18 and 03-architecture.md:107,110,125. The section 7 prototype treats existence as sealing (index(), closedChanges(), the already-held branch), and check treats any BRAIN marker bytes as a seal. I replaced an established Learning's marker with the bytes "nonempty": Sealing's actual seal.mjs check exited 1, but learning.mjs check exited 0 and reported every Learning ok. Establishing a fresh Learning citing that target in the same BRAIN also exited 0. Supplying a prospective empty marker to registerSkill() does not validate the original marker it stands in for. Require the actual Node/Change seal to satisfy Sealing's empty-regular-file rule before it can support checking, citation, evidence or an already-held result. Demonstrate refusals for a nonempty marker and a directory at the marker path; apply the same rule consistently to existing artifacts.

F6 (P2) — An evidence path can resolve outside the sealed Change.
Against R12, R18 and 03-architecture.md:125 ("containing the named path as a regular file"). The Evidence grammar is only <ID> plus a non-space path; evidence() uses join(c.dir, path) and existence/isFile without confinement. In a synthetic sealed Change at record/changes/genesis/26/10/07/01, an Evidence line using its correct Change ID and ../../../../../../outside.md resolved to record/outside.md. establish accepted it and sealed the new Learning, although that file was never inside the Change and is not covered by its identity. Define Evidence paths as paths within the exact sealed evidence tree and enforce that boundary before accepting a line. Demonstrate refusal of an escaping relative path; a valid Change ID must not attest bytes outside that Change.

F7 (P2) — Discovery presents unsealed, wrongly typed candidates as Learnings.
Against R9, R10, R20 and R31. discover.mjs enumerates any Form-matching file in a BRAIN and labels it Learning without verifying its Learning type, own seal or admission. I added a file with name "Unsealed mismatch", a wrong type name, and no marker: find mismatch returned it as a Learning; near also listed it among Learnings resting on an evidence Change. This is not recognition by the Learning type, and it lets an invalid draft enter the Agent's knowledge path even though check/establish would refuse it. State and demonstrate the admission/validation policy of the read side. It must distinguish admitted Learnings from refused or unverifiable candidates and must not label the latter as established Learnings. Preserve the explicitly permitted reading of evidence without Records and the useful-before-any-BRAIN case.

F8 (P2) — A card-count limit does not bound context output.
Against R30 and 03-architecture.md:149–153. --limit bounds the number of cards, but discover.mjs prints Node names without a length limit; Form permits arbitrarily long names. With one sealed, typed Learning whose name was 100,011 characters, find boundprobe --limit 1 returned 100,394 bytes. The short measured outputs on five small Learnings therefore do not establish the claim that corpus growth cannot increase what reaches the Agent. show is also specified as printing a whole Node while the Architecture claims every command has an explicit output cap. Define the output budget for cards, neighbours and full-text reads, including names and omitted/truncated content, and a bounded way to continue reading. Demonstrate the bound with a long Node/name and a larger result set. No semantic index is required.

F9 (P2) — The neighbour model omits Changes' citations and earlier Learning references.
Against R32, R35 and 03-architecture.md:150,163. The Architecture says near answers which Changes cite a Learning and makes a Change that establishes a Learning discoverable through its citation. The prototype only joins Changes through a Learning's Evidence; it never extracts a Change's <name> <ID> citations. I supplied a second synthetic sealed Change whose Work cited an existing Learning, with that Learning's Evidence pointing to the first Change: near the Learning showed only the first evidence Change, and near the applying Change showed zero Learnings. The listed neighbour directions also omit the earlier Learning cited by a refinement (they show later Learnings citing it). Complete the derived neighbour contract for forward and reverse Node citations and for Change-to-Learning references, keeping evidence relationships distinct. Demonstrate a Change that establishes/applies a Learning and a refinement, traversed in both directions. The section 6 caveat that this link has not been shown is honest, but the link is now a requirement and a claimed capability.
