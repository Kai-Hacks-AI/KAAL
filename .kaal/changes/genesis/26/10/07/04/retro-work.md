# Retro

## Learned

That the Intent was mostly already true. I expected to build something and found an evaluator with acceptance tests behind most of what the Intent asks for; the real work was stating requirements precisely enough to see where it fell short. The shortfalls were in what an agent reads, not in what the evaluator derives: a `next` that did not say whose act it was, and a tampered tree answered as if it were merely open. The Reviewer then showed that each of my fixes claimed slightly more than the artifacts can know, first by treating any damage as a missing Change, then by tying a global fact to one address.

## Liked

That the order I was given kept me honest: requirements and an assessment before any edit, evidence generated by walking every stage rather than described. Each round named the exact Work it read, so a finding could not drift onto work that had already changed, and a fix moved the identity instead of arguing with the round.

## Lacked

A way to tell, before writing a `next`, which words an agent will read as an instruction and which as a description. I had no test for that beyond reading my own output, so the over-claim in the first damaged-history message was caught only from outside. I also lacked a shipped answer for a KAAL installed elsewhere, so the scope stayed repository-local and the Owner's question remains open.

## Longed

For `kaal-changing` to carry its own state evaluator, so that the Skill answers where a Change is wherever it is installed instead of by a repository helper. That is the Owner's decision, and I would want it taken as its own Change with the same walk of every stage as evidence.
