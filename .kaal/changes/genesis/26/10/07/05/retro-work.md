# Retro

## Learned

That the compass was never really an evaluator problem. The order of the process was already right in one place; what was missing was that the same place also decided which directory is a Change and which is a named tree, so moving the order meant moving that decision with it, or two definitions would have drifted at the first edit. I had expected a small move and got a split of the layout from the writing helpers. I also learned how much a thin seam can carry: handing the script its identity and seal readers as arguments let one file serve both the installed command and the repository's helpers without either knowing the other.

## Liked

That the existing acceptance tests were strong enough to be the proof of the move. With sixty-five of them passing unchanged except the one that scanned for host words, I could change where the process lives and know the behaviour had not. I liked comparing the repository command with the delivered script across every Change the repository holds, because it turned "the same answer" from a claim into something I could run. And the Intent was short enough that it never told me how, which is why the sealing question stayed visible instead of being decided for me.

## Lacked

An answer on the fork I put to the Owner. I stated the three options and my lean, then proceeded on the lean when none came, and the whole Work now rests on that choice, including the sibling `kaal-sealing` requirement. I could not run the installed path on a real embedding elsewhere than a temporary directory I built myself, so the one thing the Intent is about, an embedding that is not this repository, is shown by a stand-in I made. I also had no way to run the change against the review's own environment, which could not spawn subprocesses.

## Longed

For a declared place where a Skill can say it needs another Skill beside it, so the sibling requirement is something an installer can see and refuse on, instead of a sentence in `compatibility` and a refusal at the moment of use. I longed for sealing and closing to arrive the same way state now does, so an agent outside this repository can finish a Change and not only find out where it stands.
