   ```yaml
   compatibility: >-
     Needs Node.js 20 or later, and the kaal-sealing Skill installed beside this one. Written for a KAAL directory, by default .kaal/, whose changes/ holds the change records.
   ```

   The helper returns ` >-`, so selecting Changing alone yields no unmet needs. No Node or seal bytes were changed. This violates requirement 9 and the Architecture's promise to read the Agent Skills compatibility text. 2. **[P2] An unavailable dependency must remain unmet.** In `engineering/kaal-install/helpers/delivery.ts:170-173`, dependencies are discovered only by iterating packages that were loaded. Using Changing's unchanged payload in a throwaway package root without Sealing's payload makes its explicit "needs ... kaal-sealing" declaration disappear from the unmet set. This also applies when a dependency's package has no built `dist/index.js`, since `packages()` silently skips it. Retain/report the unmet requirement when its delivery is unavailable, refuse before host writes, and add acceptance for both install and check. If no exact selectable ID can be obtained, report that limitation rather than inventing an ID or reporting successful composition.
