# Retro

## Learned

A directory argument is a filesystem traversal, not merely a string to normalize. Reviewing it exposed distinct ways to lose the boundary: following an ancestor link, erasing a link with a later parent component, and erasing a missing or non-directory component. Checking each component before advancing made the actual traversal, rather than its simplified spelling, the basis for refusal.

Review provenance needed its own judgment. A round naming the correct Work identity can satisfy the artifact evaluator without meeting the independence arrangement. The Worker's correction and the user-directed review path made that distinction explicit; a shared GitHub identity alone could not establish it.

## Liked

Exact Work identities kept each round attached to what I had reviewed. Concrete commands and filesystem observations made the findings reproducible, and the earlier rounds remained intact while the mutable evidence was corrected.

The capability boundary stayed small throughout the fixes. Optional selection, separate Incident and Request forms, and preservation on an installed host could be assessed without designing collection or transport. Reading the Worker and Owner retrospectives afterwards added perspectives that the implementation checks could not supply.

## Lacked

I lacked a complete traversal-case matrix at the first independent pass. I found the ancestor link, the link erased by parent navigation, and the invalid component erased by parent navigation in successive rounds. Those were related cases under one existing contract, and considering them together earlier would have shortened the loop.

The record also lacked independently distinguishable authorship for the initial probes. Artifact structure and a convergence label could not compensate for that missing operational evidence.

## Longed

I want a reusable set of reviewed directory-boundary cases that future capabilities can exercise before their first review, with valid navigation tested alongside refusal. That would preserve useful filesystem behaviour without repeating this sequence of discoveries.

I also want to review a real client's carrier reaching KAAL through an available adapter. That would let me assess whether local preservation and the two-part forms support an actual exchange, beyond the isolated host tests.

Finally, I want Reviewer assignment to be explicit at handoff while remaining independent of any particular provider, account or host. The ability to create another context should not silently decide who holds the review seat.
