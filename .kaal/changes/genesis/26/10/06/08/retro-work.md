# Retro

## Learned

That once the earlier Changes were in, this one had almost nothing left to decide. The installer produced exactly the two files Core delivers, so the work was to show that it was the installer's output and that nothing else moved. The sequence did its job: the same step would have needed a tolerance or an exception if it had been taken first.

## Liked

That nothing is authored. The change is what the repository's own command writes, the check turns from red to green on exactly those two files, and the append-only rule is why existing seals and Changes are untouched.

## Lacked

A lineage control that would have told us the projection lagged without anyone running the check. The gap between 06/06 and now was visible only because the sequence tracked it.

## Longed

For the lineage currency control to arrive with the cutover, so the next Core change that precedes its projection is flagged on the branch rather than remembered, and for kaal-github to be the first Extension this path delivers for real.
