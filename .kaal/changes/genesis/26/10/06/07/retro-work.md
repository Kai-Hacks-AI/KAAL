# Retro

## Learned

That delivery was already shaped by Core's answer and not by the packages, so an Extension needed no new idea: ask Core which are installed, find the package by exact Node ID, register through Core. The one real decision was what an Extension's package is. It has no Agent Skill, so the rule that a package's name comes from its Agent Skill had to give way to its directory name, and a package installed as both kinds had to be refused rather than guessed.

## Liked

That nothing in the installer learned what an Extension means. It only asks the two questions Core answers and registers through the two registrations Core provides, and the throwaway package root let the delivery be proven with real sealed Nodes before any real Extension exists.

## Lacked

A real Extension package to deliver. Everything here is proven over a fixture root, so the first real package, kaal-github, is also the first time this path runs on this repository's own packages.

## Longed

For I to run install-kaal next, so the checked-in projection catches up with Core, and for the owner's ruling on whether a capability may ever be both a Skill and an Extension, since I refused it by choice and not by definition.
