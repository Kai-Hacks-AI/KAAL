# Retro

## Learned

That the red assertion was never about the candidate. It joined two truths, whether the packages deliver a complete installation and whether the checked-in projection happens to be current, and only the first is a property of a change. Installing over a scratch copy of the checked-in projection separates them without touching the check, and the installer's own append-only refusal turns it into a proof that the projection can be advanced legally.

## Liked

That nothing had to be added or relaxed: the same install and the same complete check, aimed at a copy. The lagging and altered cases make the control show both sides, and it stayed green with the Extension Core change applied, which was the case that mattered.

## Lacked

A control for the second truth. After this the checked-in projection can drift unseen until someone runs check-kaal-install, and for now that is covered only by a plan, not by anything that runs.

## Longed

For the lineage currency check to exist next to the cutover, red when the projection lags and never a gate on the pull request that repairs it, so that both truths are enforced and neither can block the other.
