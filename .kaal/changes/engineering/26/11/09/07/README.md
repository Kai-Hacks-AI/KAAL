# Engineering: T13 judges the end of the migration by its own end condition

Capability: Engineering. Target: `kaal/engineering-release-management`. Record number provisional until integration. Root cause found while planning the `.github` rewiring of `release.yml`: T13 used "no caller left" as the signal that the migration is done, but a shim with no caller is the normal pending state between the `.github` rewiring Change and the removal Change (`.github` travels alone), so T13 would have gone red on the rewiring Change itself. The Case now follows the requirement's stated end condition (the last shim is gone and nothing calls an old path): a called shim that is missing fails, a callerless shim passes with a diagnostic, and the requirement file remaining after the last shim is gone fails. The decision is a pure function (`judgeMigration`) with a fixture Case for each state. No behavior change in product code, no workflow change, no promotion, release or publication.
