# guard/C171 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it. It closes C171 in the collector. What `main` teaches can only be recorded after the promotion, and is not claimed here.

## Liked

The three CPO holds each named a gap that a green Case would not have shown: a registered check that is not the package's own suite, a removal rule that T1672 contradicted, and a report that was bound to an argument and not to the revision that ran. Each became a Case that is RED without the change and GREEN with it. Release answered the name question within minutes, which kept "Solution protection" free and the two pass rules equal.

## Learned

- A planned Case named `.test.mjs` inside the package falls into the shipped manifest's loops and fails the Guard job; `.red.mjs` keeps it out until the DO.
- Identifiers are unique across the package docs and the retained `engineering/guard/` files together, so `guard/N14` and `guard/A20` were already taken and the Change was renumbered to N15 to N17 and A21 to A25. Case ids are unique across every remote branch: T1680 to T1685 were release C173's, and the scan that found T1742 to T1749 free had to cover all branches, not the collector.
- A matrix reports one combined result in `needs`, so a fold cannot tell which entry is absent from job results. A report per check is the evidence, and it is also the report an agent needs.
- "Registered" is not "runs the suite", and a recorded `--head` is not the revision that ran. Both needed their own refusal.

## Lacked

Registrations. No package registers its suite yet, so the eight suites that motivated the Change still run in no required check. `templates/solution.yml` has not run in a real workflow, because nothing is wired, and the Windows form of `npm test` in `run` is untested here. `guard/T104`, which removes git from PATH, failed in my sandbox because my Node was not on an absolute path; the CI Guard checks on the final head completed with no failure, and I did not run it anywhere else.

## Longed For

Each capability registers its suite with a `guard.json` in its own Change: architecture, backlog, controls, defect, engineering, guard, research and retro. Then the WIRE of the template and a ruleset that requires `Solution protection`, each on the Owner's own go, then the Workspaces lane retired after replacement evidence and its own authorization. The `change` and `delivery` aggregates, and Release's aggregators consolidated into the fold after the 2 December migration and soak, are later Changes. Selection by changed paths stays out until a full run proves too slow.

## Closed

The mechanism is closed: Cases T1670 to T1679 and T1742 to T1743 are GREEN in the collector. The problem that motivated it is not closed until the suites register and the name is required. No WIRE, ruleset, registration or publication was done or implied.
