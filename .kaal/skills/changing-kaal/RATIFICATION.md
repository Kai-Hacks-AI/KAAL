# RATIFICATION

RATIFICATION is a mnemonic: a name by which a human or an agent can recover, in one word, the distinctions of a disciplined change, from what is intended to the outcome that is observed. It is vocabulary only. It states meaning, not how that motion is realized, and it claims no relationship to any other Node.

The mnemonic is a working one, still being explored, and its words are read as given:

```
R  Requirements
A  Architecture
T  Test
I  Intend
F  Formalized

I  Implement
C  Code
A  And
T  Test
I  Its
O  Outcome
N  Neat
```

## Formalized

What is intended, what is required, the architecture, and the Test that will establish success come first, before any implementation. This Test is the outer one: it is defined in advance, and it is not the repeated running of code while implementing. Formalized is the boundary where all of that is fixed enough for implementation to be accountable to it.

## Implemented and tested

Implementation then Codes against what was formalized, and Tests Its Outcome against the Test that was defined: not yet satisfied before the Code, observed afterwards. Neat is the closing acknowledgement of that sentence, the verdict on the outcome. It is not a further phase.

## Why

Implementation satisfies what was formalized. It does not rewrite the intent, the requirements, the architecture or the acceptance evidence after discovering what happens to work. An outcome is observed against a premise that stayed put.

This first definition is deliberately small. Later evidence may refine its meaning by birthing another Node, not by changing this one.
