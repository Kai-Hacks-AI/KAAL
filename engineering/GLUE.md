# GLUE

General Loose Unified Engineering.

Six disciplines form one causal cycle:

Detect Defects → Describe Intent → Define Requirements →
Design Architecture → Develop Code → Do IT → Detect Defects

Each discipline presupposes the one before it. A perceived defect or
gap motivates Intent. Requirements state what that Intent requires.
Architecture places the Requirements. Code embodies the Architecture.
Operation runs what was developed. Operation and observation reveal
defects, which feed renewed Intent.

Every discipline occurs, explicitly or implicitly. Work without a
written Requirement or Architecture still made those decisions. GLUE
shows where one was omitted, weak or unexamined.

Loose: the disciplines are loosely coupled, not unordered. The causal
order holds, but GLUE mandates no six-step ceremony and no artifact per
discipline. A context may impose the sequence, gates and controls it
needs.

Unified: the cycle recurs across layers. Developing within an enclosing
context may need the complete cycle in its own context, under the
enclosing boundary.

Feedback is explicit: what is detected returns as renewed Intent, within
a layer and across layers.

Each discipline is owned by its capability: kaal-intent,
kaal-requirements, kaal-architecture, kaal-coding, kaal-operations and
kaal-testing. Engineering integrates them and owns none.
