# controls/A16 records-and-admission

Records of control runs are JSON files in `engineering/controls/06-records/<control id with / as ->/<run>.json`, one record each in the shape of controls/F28, committed by the Change that produced the run and linked by name from that Change's ACT. A converter in `engineering/controls/05-src/` turns a `kaal-testing` report into records: a run against a fixture or a real X gives `{ case, x, run, outcome }` from the report's test and outcome, and a `:fail` X gives the head record with `base: { run, outcome }` taken from the base report by `compareReports` (a test RED on the base and GREEN on the head). The converter holds no rule of its own: it copies what the runner reported. Engineering's check passes the records folder to `check-controls.mjs --records`, so a control that claims `tested` without shown evidence fails it (controls/F23's check gains the option). The controls package judges; Engineering holds the numbers and the records.
