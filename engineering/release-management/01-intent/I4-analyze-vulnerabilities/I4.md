# release/I4 analyze Vulnerabilities

Contract: the control analyzes a defined set of dependencies for known vulnerabilities and says exactly what it analyzed and what it did not. The set it analyzes is its input and is part of every result. Today's realization analyzes only the dependencies a Change adds or changes (`C5-analyze-vulnerabilities/analysis-realization.md`, section Coverage). That is a coverage limit of the realization, not the scope of the control. The vulnerability state of dependencies already present, and advisories newly published against them, is not analyzed today; Dependabot reports on them and is not changed.

A Change never brings a dependency with a known vulnerability into a collector or into `main` unnoticed, so that the people who admit it decide knowingly, and so that an advisory published after the Change was reviewed is still seen before the Change is promoted. Owner: release management.
