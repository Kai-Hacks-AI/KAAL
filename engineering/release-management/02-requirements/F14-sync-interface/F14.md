# release/F14 sync-interface

The body of a SYNC pull request is a short interface of exactly three level-2 chapters in this order, Sync, Needed by and Resolutions, and nothing else: no other headings, attribution, link to a conversation, generated footer or separator. It reuses no heading of the PLAN, DO or ACT interface. A synchronization is not a Change and claims no Change Record, so it has no Change chapter.

- Sync: one line, `main <commit> into <collector>`, with the exact `main` commit taken in and the collector that receives it. It names a commit, never "main now" or the promotion that produced it, because `main` moves. It does not name the collector's tip, because that moves when Changes land.
- Needed by: what waits on the synchronization, by pull request number or Change id, in one short paragraph. It is the reason, which Git cannot show.
- Resolutions: `none`, or one line for each conflict path that the synchronization decides itself, with the path and what was decided. A path that takes `main`'s content unchanged is adopted, is named by the Branching check and is not listed. `none` is what separates a synchronization from new functionality.

Each chapter carries concise author guidance. The body does not repeat the diff, which is `main`'s own accepted content, nor the merge method, the rule of synchronization or the list of what `main` brought. Those live in the diff, the checks and `engineering/github/branching.md`. The interface guides the author and replaces no control. A worked body stands in `example.md`.
