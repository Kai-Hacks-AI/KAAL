# F1 plan-pr

verify Plan returns PASS, FAIL or UNKNOWN for a PLAN. A PLAN passes only when it satisfies all of these rules.

1. Every Change has at least one driver: it implements an Intent, resolves a Defect, or both. (F1/T1)
2. Every functional and nonfunctional Requirement serves an Intent. (F1/T2)
3. Every Architecture element addresses at least one functional Requirement, nonfunctional Requirement or Defect. `parent` is separate same-kind decomposition from child to parent: it exists, has the correct kind and forms no cycle, and it confers no coverage. (F1/T3)
4. Every Case tests one or more targets, every link resolves with the correct type, and ids are unique. Every node id, Case ids included, has the form `<capability>/<kind><n>`, and no id encodes where a node sits. Each Intent, Requirement, Architecture element, Defect and identified Change gap has at least one outer-loop Case, and a Case may cover several targets. (F1/T4, F1/T13)
5. Every Case sits at the place derived from its `tests` list: beside the nearest shared ancestor of its targets, then the common Intent, then the capability itself. Placement is validated separately from identity. A Case in the wrong place fails with a Recovery, and a Case whose place the PLAN does not state yields UNKNOWN. (F1/T5)
6. A PLAN contains at least one meaningful observed RED condition: an executed Case that fails because an Intent, Requirement, Architecture element, Defect resolution or expected behaviour is unfulfilled. Passing Cases are allowed. An unconditional failure alone is not that condition. (F1/T6)
7. Change-oriented Cases that prove identified gaps closed are kept apart from target-oriented Cases that prove the target, and a Case may cover several gaps. (F1/T7)
8. Every failure carries findings and a Recovery. Unreadable or unresolvable input, and missing evidence, yield UNKNOWN, and UNKNOWN never passes. Every template heading is parsed. (F1/T8)
