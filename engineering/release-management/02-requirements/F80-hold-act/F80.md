# release/F80 hold-act

A check on every pull request into a collector reads the checked-out tree and holds the ACT of a collector: a retro (the 4L of kaal-retro, in `02-learnings/retros/`) that reflects a Change the collector carries may stand only when every Case that applies to the carried Changes is really green. The carried Changes are given to the check as facts. A retro is found by what its front matter declares, `reflects: [C…]`, and nothing else of it is read (its id and its format are kaal-retro's). When no retro reflects a carried Change there is no ACT to hold and the check says PASS, whatever is red, so the PLANs and DOs that precede the ACT land; a retro of an earlier collector reflects other Changes and holds nothing here. With such a retro, the rest of this paragraph decides. The Cases that apply to the Change are those in its folder and those that test an element the Change justifies, that is the Intents its record implements and every element that reaches one of them along the one-way relationships (serves, addresses, has), whether the element is placed or still a draft in the Change folder. The check says PASS only when at least one Case applies, none is parked as a `.red.mjs`, and the observation of Testing is GREEN for each. It says FAIL, with the message `finish your work first` and the Cases named, when an applicable Case is parked red or observed RED. It says UNKNOWN, which never passes, when an applicable Case was not observed green or no Case applies. It reports the count of red, green and unknown Cases. It reads nothing of the history of the branch: the same tree gives the same answer however it was transported. An exit code is never a verdict: the check reads observations. It does not approve and does not merge. Judgement is kept apart from enforcement: the judge says PASS, FAIL or UNKNOWN and never blocks; the place that asks it decides what a verdict does (a report, an advisory check, a required check), and once the check is required UNKNOWN does not count as PASS.
