# release/F53 release-scope

A planned package version has one declared scope: the Changes it consists of, each marked `required` or `optional`.

- The scope is a manifest in Engineering's sources, one per planned version, named after the package and the version. It lists Changes by id and owning capability and nothing else.
- A judge reports each listed Change as `delivered` (its Change folder is on `main`) or `missing`. Readiness of the version is `ready` only when every `required` Change is `delivered`.
- The manifest is a plan, not a delivery. Declaring a scope publishes nothing, bumps no version and takes no promotion seat. Publishing to npmjs stays a separate step that needs the Owner's go.
- A scope changes by an ordinary Change. A Change that is not in the manifest is outside the version, however many PDCA cycles reach `main`.
