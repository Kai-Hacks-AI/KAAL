# release/F8 dependency-placement

Dependency Review states, for each of the four places a Change passes through, whether it applies there and how. The locator in the second column is the Owner's mapping aid, and it is not part of any name.

| Place | Locator | Applies | How |
| --- | --- | --- | --- |
| Development | OUT | yes, advisory | shows the author a finding before the Change is handed on. Declared, not built by this Change, because a developer can skip it |
| Integration | IN | yes, bound | judges a Change when it is admitted into a collector. Detective until the Integration ruleset requires `verify Dependencies (Integration)`, on the Owner's go |
| Promotion | IN | yes, bound after observation | judges what the promotion adds or changes relative to `main`, so an advisory newly published on that addition is seen then. Declared only once merge-group judging is observed (`acceptance.md` A4); then the Promotion ruleset requires `verify Dependencies (Promotion)`, on the Owner's go |
| Publishing | IN | no | publishing creates a tag on a commit whose dependencies were judged when they entered `main`, and adds or changes none. The control judges additions and changes only (release/I4), so there is nothing for it to judge here |

Opening a promotion from a collector (Integration OUT) has no application of its own: it is judged at Promotion. Dependabot, which watches dependencies already on a branch, is a different control and is not changed by this one. The control reports its verdict under the names of `naming.md`.
