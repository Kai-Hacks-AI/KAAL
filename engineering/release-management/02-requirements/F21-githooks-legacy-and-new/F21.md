# release/F21 githooks-legacy-and-new

The hooks of the Development place are kept in two clearly separated parts, so that the new concept is built forward from a clean slate while today's protection is retained.

- `.githooks/pre-push` is a thin dispatcher that holds no policy. It reads the pushed refs once and hands the same arguments and the same refs to the legacy hook and to every installed new hook, runs all of them, and fails if any of them fails. It fails closed: a missing or non-executable legacy hook, or a file of the new directory that cannot run, is a failure and never a silent skip, so the existing blocking protection cannot be removed by deleting or unmarking a file. The legacy hook is required; the new directory is optional, and only its `README.md` is not run.
- `.githooks/old/pre-push` is today's hook, moved unchanged. Its checks still run and still block. It is retired control by control, each retirement its own Change.
- `.githooks/new/pre-push.d/` holds the installed new hooks, one per control, each equal byte for byte to its tested source in the Engineering wiring source area. Nothing else is written there.
- The first step changes no behaviour: the same checks run and block as before.
