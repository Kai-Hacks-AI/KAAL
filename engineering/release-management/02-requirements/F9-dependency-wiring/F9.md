# release/F9 dependency-wiring

The verdict of Dependency Review is reported under one stable check name for every Change that a place admits, so that a ruleset can bind it. At Integration IN that is every pull request into a collector, at Promotion IN every pull request into `main` and every merge group the queue forms. A place where the name is not reported on every admitted Change must not be bound, because the admission would wait forever.

- What a ruleset needs from this control is prepared and listed in `ruleset-needs.json` of the Change, and is applied only on the Owner's go. The existing rulesets stay; nothing is rebuilt.
- Binding is `guard Integration`'s requirement. This control only reports, under the stable name.
- No ruleset is changed while the name is not yet observed on real admissions.
