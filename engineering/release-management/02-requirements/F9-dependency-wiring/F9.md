# release/F9 dependency-wiring

Dependency Review reports its verdict for each target on its own, under one check named `verify Dependencies (<target>)`, so that a ruleset can require it. Binding is one required context per target in the ruleset of that target, applied on the Owner's go and never by this Change.

- The check of a target reports for every Change that target admits: for Integration every pull request into a collector, for Promotion every pull request into `main` and every merge group the queue forms. A target where it does not report on every admitted Change is not declared and its context is not required, because the admission would wait forever.
- A verdict that is missing, late or UNKNOWN is not a pass.
- Until the context is required in the ruleset of a target, the control stays detective there and reports itself as not bound. It never claims to prevent.
- What the control needs from the rulesets is listed in `ruleset-needs.json`. Nothing else in a ruleset is asked for. A single check that fans in many controls is a later design and is not part of this Change.
