# release/F2 plan-structure

A PLAN has this structure, whatever platform it is produced on.

1. A Change, an Intent or Defect it implements or resolves, and the Gaps it closes.
2. Requirements that serve the Intent, and Architecture that addresses the Requirements or the Defect, each with the relationships of the shared relationship model.
3. Cases that test every Intent, Requirement, Architecture element, Defect and Gap, each Case pointing only at what it tests.
4. A red plan: at least one Case is expected to fail on an assertion while its target is unfulfilled, and the PLAN names the baseline that the red is observed against.
