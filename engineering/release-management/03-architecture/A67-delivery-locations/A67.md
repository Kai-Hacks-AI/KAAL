# release/A67 delivery-locations

This is the delivery architecture of KAAL for one concern, delivery locations: a declaration, `03-architecture/A67-delivery-locations/delivery-locations.json`, a list of named locations, each a root of the repository with a statement of what is delivered there and whether a WIRE may install into it (`wirable`): `.github`, `.githooks`, `.kaal`, `.agents` and `.claude`, all wirable. It also names, under `files`, the delivery files at the repository root, `package.json` and `package-lock.json`, which are delivery but not wirable. It is the declaration of the consumer, KAAL; another repository declares its own, with the same shape, whether or not it uses packages. It names things and places and holds no logic. The wider delivery architecture (installation, synchronization, activation, verification) is not declared here; this declaration is the first concern anchored in it, and the others join it in their own Changes.

One reader, `05-src/delivery/locations.mjs`, is the only code that knows the file's shape. `readLocations(path?)` reads and validates it (it throws on anything malformed: not JSON, no locations, a root with `/`, `..` or a leading `/`, a duplicate root, `wirable` that is not a boolean). `wirableTarget(path, locations)` answers whether a path is one file under a wirable root, and `isDelivery(path, locations)` whether a path is a delivery path: under a declared root, or a declared root file. The consumers import these; none spells a root.

Consumers: `wireTarget` and `decideFinal` of `05-src/promotion-raise/final-step.mjs` (`decideFinal` takes an optional reader `read`, `readLocations` by default), `judge` of `05-src/wiring/wire-judge.mjs` (the same optional reader), `deliveryMixed` of Change Isolation (`engineering/change-isolation/check.mjs`, detective: it reports a change that mixes delivery and solution and gates nothing), and `withDelivery` of Pull Promotion (`05-src/pull-promotion/delivery-evidence.mjs`, which adds the delivery patterns to the DO evidence). All read the declaration through the one reader; none spells a root. The WIRE consumers read it from the default branch, as the scripts do: a pull request cannot change what it is judged against.

Not here, named so they are not forgotten: making the delivery rule preventive is a decision of the Owner after the control has run for real, and checking what a package declares it installs against the delivery locations is a later question. Core's rule that Core travels alone and the rule that `.github` travels alone are unchanged.

What the solution declares it installs stays what it is. In KAAL a package is the solution unit and its contract (`assets[].target`) says what it installs, which is solution architecture; the delivery architecture says where this repository allows delivery. A repository without packages declares the same locations the same way. Checking the one against the other is a later question.
