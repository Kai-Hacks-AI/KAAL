# release/A43 pr template registry

The authoritative source of every pull request template and the mechanism that installs and verifies it. Engineering defines and qualifies, the mechanism installs and verifies identity, GitHub consumes.

**Registry.** `engineering/release-management/05-src/pr-templates/` holds one file per template TYPE, which is exactly the text to deploy, and `manifest.json`:

```json
{ "version": 1, "closed": false, "templates": [ { "type": "SYNC", "source": "sync.md", "target": ".github/PULL_REQUEST_TEMPLATE/sync.md", "sha256": "<hex>" } ] }
```

The `target` is the deployed copy, which is a copy and never a source.

**Mechanism.** `install.mjs` exports `check(root)` and `write(root)` and runs as `node install.mjs --check|--write [--root <dir>]`. Both return a verdict and one finding per entry.

- `check` is read-only. For each entry the sha256 of the source equals the manifest `sha256`, and the sha256 of the target equals that of the source. A missing or unreadable manifest, source or target is UNKNOWN, and a difference is FAIL. `closed` says whether every template installed in `.github` (`.github/PULL_REQUEST_TEMPLATE/*` and `.github/pull_request_template.md`) is registered. While `closed` is false an unregistered installed template is reported and does not change the verdict; once `closed` is true it is FAIL. The migration sets it to true when the last installed template is adopted. UNKNOWN never passes.
- `write` copies each source to its target byte for byte without normalizing any byte, then runs `check`.
- Exit status: 0 PASS, 1 FAIL, 2 UNKNOWN.

It reads files under a root and names no Git or GitHub reference. It is run by hand and is wired to nothing.
