# release/A71 hold-act-from-the-tree

The source `05-src/phase/judge-act.mjs` has three parts and reads a folder, never Git. `elementsOf(root, changeDir)` reads the elements of the tree, the Markdown files with a frontmatter id and the drafts fenced by five backticks in the Change folder (a placed element wins over its draft). `applicableCases(root, changeDir)` takes the Intents implemented by the Change record, widens them along the one-way relationships to every element that reaches one, and returns the Cases that are in the Change folder or test any of those elements, each parked red when any file carrying its id is a `.red.mjs`. `retrosOf(root)` lists the retros under `02-learnings/retros` by what they reflect: only `reflects` is read, since the id and the format are kaal-retro's, and its own finder replaces this reader once it is on `main`. `judgeHold({ changes, retros, observed })` takes the carried Changes with their applicable Cases and the retros, says PASS when no retro reflects a carried Change, and otherwise asks `judgeFinished`, which judges the Cases of all the carried Changes together with `judgeAct`; `judgeFinished` is also what the other controls of the ACT ask whether work is finished. `judgeAct({ applicable, observed, acted })` is a pure function of those and of the observations `{ <scope>/T<n>: GREEN | RED | UNKNOWN }` of Testing, and returns PASS, FAIL or UNKNOWN with the counts and the findings. The command line `--root --change --observed` exits 0, 1 or 2 for them, so a workflow or a hook can use it. Which folder is handed over is the wiring's decision. The control release/CTL24 declares it. The workflow, the hook mirror, the adapter from Testing's report, the control that authorizes what a pull request may change and the gate in a ruleset are later slices.
