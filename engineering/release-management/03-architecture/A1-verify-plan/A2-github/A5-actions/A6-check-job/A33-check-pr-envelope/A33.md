# release/A33 check-pr-envelope

The first check of verify Plan. It judges the envelope of a pull request, given its title, its body, its base and head names and its commits, and reports findings. The judgment holds no git or GitHub term beyond those facts, and a thin adapter is what gathers them. It runs by hand: `05-src/plan-body/verify.mjs <body file>` judges a PLAN body alone (release/F13), and `05-src/plan-body/envelope.mjs <facts file>` judges the whole envelope (release/F17). Both print the findings and exit 1 when there are any. The envelope judge holds the shared rules and the rows keyed by TYPE, takes the registry of types from release/A40, and reports what it did not judge, such as an unsupported TYPE.

The result carries a verdict beside `ok`, and a consumer relies on the verdict only (release/F17, section 4). The command line prints the verdict first, then the findings and the items not judged; only PASS exits 0, FAIL exits 1 and UNKNOWN exits 3, so a run that left something unjudged is never mistaken for a pass.
