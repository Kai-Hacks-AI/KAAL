# release/C94 verify Hotfix

Gives the Hotfix a control. release/CTL21 `verify Hotfix` is a detective control that has the Intent release/I10 (create Hotfix). A valid Hotfix is one Defect and at least one Case that verifies it, RED before and GREEN after, and the control proves exactly that from two trees. The concept is pure content: two branches or two file locations are the same to it, and only the GitHub adapter maps the default branch and a `hotfix/` head onto the two trees. A Hotfix brings its own Defect and Case. PASS is proven, not approved: whether a Case corresponds to its Defect, is honest, or whether the correction is minimal is content, for review and later the Inspector.

It replaces release/C31, which built a judge as a bare module with no control identity, classification or registration, and which read the Defect and its Case from a Git base. C31 is retired. This Change adds the control, its Requirement and Architecture, the reader, the reader of the Run of Cases and the GitHub adapter. It is Engineering source: nothing is installed, wired or required here.
