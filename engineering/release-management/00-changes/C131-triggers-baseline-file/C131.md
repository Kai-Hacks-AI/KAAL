# release/C131 verify Triggers keeps its accepted baseline in a file

The ratchet of `verify Triggers` (release/CTL20, adopted by release/C130) has no baseline file: its judge derives the accepted baseline from the workflows of the base commit each time, and `baseline-source` on the control is prose. Kaal-controls C24 makes the baseline a file named by `baseline-source`, checked by the finder, and the strict finder would list CTL20 as invalid. This Change gives CTL20 the file and makes its judge read the accepted baseline from that file in the base, so CTL20 is the same kind of ratchet as release/CTL36. It is the first step of the agreed sequence: release adopts first, on the current finder; controls' C24 collector is promoted after this is on `main`. It changes no ruleset, no workflow and no enforcement.
