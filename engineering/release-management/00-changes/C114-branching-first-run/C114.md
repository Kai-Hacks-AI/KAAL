# release/C114 the Branching verdict of a new pull request does not wait for auto-merge

The first Branching run of every new pull request into a collector fails, and a stale failure can be the verdict that stays: release/D12 (`D12-branching-first-run.md`). Two causes: the verdict judges the auto-merge method from the event's copy of it, and a pull request cannot be opened with auto-merge on, so `opened` fails; and the runs of one pull request are not ordered, so an older run can finish last. The gate stays, because it protects the merge method each flow lands by (a SYNC by merge commit, a Change and a PROMOTION by squash) before the merge rather than after. This Change keeps it and makes it judge what the pull request has: the method is judged only while auto-merge is on, by the method the pull request has when the run judges, and a pull request without auto-merge is not failed for it; one run per pull request decides, the newest event's. The workflow has no source under `05-src/wiring/workflows` (it was installed by hand): this Change gives it one, with the correction; the installed copy changes in the WIRE that follows, from that source.
