# release/C71 KAAL object metamodel and the views of the PR templates

The tracing chain (Intent, Requirement, Architecture, Control, Case, then code or ruleset) is an anchor for semantic reasoning, both when a Change is created and when it is understood afterwards. A reviewer, human or agent, who opens a pull request should be able to follow its template to one explained view and from there to one global model of KAAL's objects and relationships along that chain, without rebuilding KAAL's architecture from scattered documentation. This Change writes that model and a view for each PR template, records where the repository differs from the model, and proposes how each template points at its view.

Owner direction (CTO handover, 18 Nov 2026): the metamodel describes objects and their relationships, not the order of workflow steps; a pull request is a transport mechanism, not the authority for the lifecycle state of a Change; existing identifiers and terminology are preserved; the normative, the observed and the proposed are told apart. It is parallel to the release work and engineering takes it until a capability is chosen.

Follows release/C24 (the envelope cue) and release/C68 (verify Envelope) in how it treats the PR body: a template adds no chapter. It touches no active template, hook, workflow or ruleset.
