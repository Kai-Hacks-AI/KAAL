# release/C152 verify Sync decides what it applies to from the git content of the head, not from the pull request title

`verify Sync` (release/CTL7) judges from Git objects, but the pull requests it judges are picked by the title: the workflow runs it only for a title that starts with `SYNC:` (`sync-review.yml`, the `if:` of its three jobs) and the command line decides `isSync` the same way (`cli.mjs`). A pull request that is not a SYNC and carries that title fails the control, and the controls thread's #2575 to #2579 failed until they were retitled DO. A KAAL control decides from files and git content, never from GitHub titles or bodies. This PLAN records the Defect and settles the remedy. It is a PLAN: no source, workflow or WIRE change, no flag, no ruleset.
