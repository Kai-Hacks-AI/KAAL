# release/C79 the judge Cases derive their inputs from the real sources

The Cases of `verify Stages` build the judge's facts from two hand-kept copies: the controls list of the shared helper (`C35-stages/helper.mjs`) and the declared rules of the shared fixtures (`C70-stages-declared-rules/fixtures.mjs`). Every new control or declared key (release/C76, C77 and C78 each needed it) means a coordinated edit of both, and a copy that was not updated tests an input that no longer exists. This Change makes the positive inputs a read of the real tree, and keeps the negative inputs small, hand-made and independent.

It covers:

- a helper `derive.mjs` that returns the facts of the checkout with the judge's own reader (`read` of `05-src/stages/judge.mjs`): the real `stages.json`, the real ruleset sources, the controls found in `04-controls`
- Cases that show the judge passes on that derivation and that a removed setting, a forged check and a dropped control each make it fail
- Cases that show the shared helper and fixtures hold no hand-kept controls list

The chain is Intent release/I44, Requirement release/F61 (serves the Intent), Architecture release/A56 (addresses the Requirement), Test Cases beside what they test. No control is declared: this Change tests the judge, it does not add a protection. The principle is the one applied to guard: declare once, derive the rest, no hand-kept lists.

It is a source in Engineering: nothing is loaded, installed or switched here, no ruleset, setting or judge changes, and nothing under `.github` is touched.
