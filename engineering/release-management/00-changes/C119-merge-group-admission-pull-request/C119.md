# release/C119 the admission to the merge queue runs on pull_request

Fixes release/D13. The source `05-src/wiring/workflows/merge-group-admission.yml` triggers on `pull_request`, not `pull_request_target` (option C of release/C118, approved). The workflow judges nothing, holds no permission and reads nothing of the pull request, so a pull request that edits its own copy gains nothing: the merge group's own run of Change Isolation (review) judges at merge time. The job name `Change Isolation (review)` is unchanged, so the required context is retained.

Not in this Change: `.github/workflows/merge-group-admission.yml` stays as it is. A WIRE installs the source afterwards, and at that WIRE the engineering Cases that still pin the old trigger (engineering/T139 in `engineering/github/queue-workflows.red.mjs` and the line that sets the admission against the review on their events) are amended with it.
