# C132 baseline

The baseline is `main` after #2403. `.github/workflows/verify-triggers.yml` (source `engineering/release-management/05-src/wiring/workflows/verify-triggers.yml`) and `.github/workflows/verify-workflow-names.yml` (source `packages/kaal-engineering/13-source/workflows/verify-workflow-names.yml`, engineering C34, installed by #2408) each check out the base commit of the pull request, fetch the head as Git data and run `node <judge>` from the base checkout, with the step `test -f "$J" || { echo "UNKNOWN: the judge is absent on the base"; exit 2; }`. For a pull request into `main` the base is `main`, so the judge is main's. For a pull request into a collector the base is the collector, which holds the judge only after a SYNC has brought it. The Act judges (`controls-act.yml`) and the CodeQL gate jobs (engineering C33) check out the default branch for the judge and treat the pull request as data. Both judges read the accepted baseline from the base commit as Git data (`verify-triggers.mjs`, release C131, `judge-workflow-names` through `--previous`).
