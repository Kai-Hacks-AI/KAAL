# release/C70 verify Stages judges a ruleset against the rules its stage declares

The judge of `verify Stages` (`05-src/stages/judge.mjs`) holds the shape of a ruleset in code: the only rule of a branch ruleset must be `required_status_checks`, and its checks are derived from the stage's name and two special keys (`requires`, `also`). Adding a second rule, such as the approval of release/CTL10, would need one more exception in the judge. This Change removes the shape from the judge. The data declares and the judge interprets, as for `verify Envelope`.

The Owner's framing (17 Nov 2026): each ruleset setting is the answer to a control; the control answers an Intent, Requirements answer the Intent and Architecture answers the Requirements; Test Cases cover each setting and the ruleset source is the code that turns them from red to green. So a branch stage declares `rules`: the rules its ruleset source holds with every setting, a status-check rule listing its checks, and each rule and check traced to the control that requires it (`release/CTL1`, `release/CTL5`, `release/CTL10`). The judge passes when the source holds exactly the declared rules, checks and settings, one, two or N of them, and every one is traced to a control that is declared in `04-controls` and has an Intent. A rule, check or setting in the source that is not declared, a declared one that is missing or differs, and a trace to no control, to an undeclared control or to a control without an Intent each fail. An untraced setting is a finding.

It is the precursor of release/C66, as release/C59 was of release/C56, and replaces the two special keys. The judge of `Engineering / verify Stages` is the default branch's own, so a ruleset source that holds a second rule can only pass once main's judge interprets declared rules. Nothing under `.github` changes in this Change.
