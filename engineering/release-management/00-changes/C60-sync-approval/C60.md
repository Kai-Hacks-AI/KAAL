# release/C60 a refused SYNC approval names its setting and reaches a person

Follows release/C58. `approve Sync` (release/CTL8) approves a pure SYNC only when the repository lets Actions approve and the Owner has switched it on. Both are settings, and today a refusal of the approval call is an anonymous red job that leaves a pure SYNC unapproved and unnoticed, because `review Sync` (release/CTL9) acts only on a verdict that is not a pass.

This Change makes the refusal a named finding that says which setting is off, hands the SYNC to `review Sync` so a person sees it, and declares the two settings as part of CTL8. CTL8 reaches Running once a live run has approved a SYNC. No new control: the two settings belong to CTL8, the escalation to CTL9.

It is a source in Engineering. Nothing here changes `.github`, a ruleset or a setting.
