# release/C121 Promotion Source judges from the default branch through a relay and a handler

Fixes release/D14, by option B of release/C118 (approved). The sources `05-src/wiring/workflows/promotion-source-relay.yml` and `promotion-source.yml` replace the single `pull_request_target` workflow. The relay runs on plain `pull_request`, holds no permission and records only the pull request number. The handler runs on `workflow_run` of the relay, from the default branch: it sets the check `Promotion Source` in progress first, validates the number, reads every fact from the API, checks out the default branch only, judges with the checker the default branch holds, and always completes the check, as failed unless the judgment passed and the head did not move. The required check name `Promotion Source` is unchanged; the handler's job is named `Promotion Source (handler)` so the name belongs to the check run alone.

Not in this Change: `.github/workflows/promotion-source.yml` stays as it is. A WIRE installs both sources afterwards. Known limit, as in change-isolation-review: a pull request from a fork has no `pull_requests[0]` in the event, so its check is never created (it cannot merge), which is stricter than today.
