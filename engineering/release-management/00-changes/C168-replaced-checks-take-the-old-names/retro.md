## What we learned
- **The first plan was wrong for the merge queue.** Requiring the plain jobs' own names in the rulesets would have hung every merge into main, because the queue checks the required names on the merge group and the plain workflows run on `pull_request` only. Reading the live rulesets before the swap found it. The swap is by name transfer, and no ruleset edit is needed.
- **A DO cannot see the Cases it breaks until it runs the whole suite.** Seven Cases of earlier Changes pinned "no job takes the required context before the swap". They were found only by running every Case of release-management after the rename. The PLAN was amended before the DO changed them, as the rule asks. Next time a PLAN that moves a name should grep the Cases for that name first.
- **Legacy never enters a ruleset** is now a Case (T1645) and the names the rulesets require are a Case (T1646), so a rename without the ruleset, or the reverse, is seen.
