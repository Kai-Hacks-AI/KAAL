# release/C90 no workflow uses pull_request_target

Declares the directive Intent release/I50 (no workflow under `.github/workflows` uses `pull_request_target`; source https://github.blog/changelog/2026-11-02-pull_request_target-blocked-by-default-december-2/) and a detective ratchet, release/CTL19 `verify Triggers`: it compares the workflows of the base and the head of a pull request and fails when the number of workflows that use the trigger rises, or a workflow that did not use it on the base uses it on the head. The base branch is the baseline, so there is no list to keep.

It answers the Owner's decision of 18 Nov 2026: GitHub blocks `pull_request_target` by default from 2 Dec 2026, no Actions policy exception is taken, and the five workflows that use it (`change-isolation`, `lineage-synchronization`, `promotion-source`, `merge-group-admission`, `sync-review`) are replaced by 2 Dec. The ratchet starts at 5 and the replacements (the Inspector and the Dispatcher) drive it to 0, where the target Case asserts it.

It is Engineering source: nothing is installed, wired or required here. Registering the check in the Integrating and Promoting stations is a later WIRE, and making it required in `integrating` and `promoting` is the Owner's later step.
