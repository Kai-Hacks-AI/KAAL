# release/C107 a collector is promoted only when its queue is empty

On 20 Nov 2026 engineering's C26 PLAN (#2132) was based on the collector `kaal/engineering/setup`. The collector was promoted and deleted, and GitHub silently retargeted the pull request to `main`. Work written for a collector's stations could then have reached `main` without them. The Owner (20 Nov 2026): the promotion of a branch should be blocked while anything still points at it as its base; "plan the control". The CPO's direction on the first version of this PLAN: block the promotion, not the valid work that enters the collector; call the controls **check Queue** (detective) and **block Queue** (preventive), with a clear definition that this is the collector's own queue and not GitHub's merge queue; explore one judgement at several places, an advisory hook and an authoritative required check including the merge queue path, on fresh and complete facts, with UNKNOWN never passing where it is enforced.

This Change is the first slice: the Intent release/I57 (which defines the queue), the Requirement release/F83, the Architecture element release/A73 (the judge), the detective control release/CTL27 `check Queue`, the preventive control release/CTL28 `block Queue`, and the judge itself with its command line. The judge is pure: it is given the promoted branch, the promotion's own number (or the ref of its merge group) and the open pull requests, and says PASS, FAIL naming each pull request in the queue, or UNKNOWN. It reads nothing from Git or GitHub, and it never blocks: the place that asks decides what a verdict does.
