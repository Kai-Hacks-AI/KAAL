# C3 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it.

## Liked

Kai's corrections of the PLAN body. Each round made the contract smaller: one sentence, then four chapters, then the CPO's fixed structure. A small contract was easy to turn into a checker and into Cases that fail for one clear reason.

## Learned

"Short" does not test until it has a number, and a footer can hide inside a paragraph unless the check looks for provenance, not only for a rule line. The CPO found both gaps in two review rounds. A rename does not wire a Case: the Engineering job runs an explicit file list in `package.json`, so the twelve `.test.mjs` Cases of this Change run nowhere yet.

## Lacked

Any way to see which job runs a Case when it is added. Any way to try the template as an agent opens a PR, because the API ignores templates. And review cycles were lost to stale-head check failures and the first-run Branching trap, which could only be told apart by reading each run.

## Longed For

A single answer to "what enforces this?" next to each Case, so a green Case is never mistaken for an enforced one. A body check at the moment a PLAN PR is opened. A way for agent-opened PRs to receive the template.

## Sentence

Priorities Lead Agents Next Development, Optimising Code Health, Enabling Clear Knowledge About Collected Testing.
