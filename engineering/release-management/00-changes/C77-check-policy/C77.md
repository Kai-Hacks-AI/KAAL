# release/C77 a stage's required-check policy: judged on its own head, and a branch can exist before its checks

Declares the preventive control `settle Check Policy` (release/CTL14) and its answer chain for settings the new rulesets hold and no control states yet (release/C70, `change.md`, Left open). It covers:

- `strict_required_status_checks_policy`: `false` on every ruleset (a pull request is not forced to be up to date with its base)
- `do_not_enforce_on_create`: `true` on the branch rulesets of work branches (Integrating, Collecting, Hotfixing, Wiring), so a new `kaal/**`, `hotfix/**` or `wire/**` branch can be created before any check has run, and `false` on Promoting, so the default branch is never created or reset without its checks

The chain is the one the Owner asked for on 17 and 18 Nov 2026: control release/CTL14 answers Intent release/I42; Requirement release/F59 answers the Intent; Architecture release/A54 answers the Requirement; Test Cases cover each setting; the ruleset source and the stage declaration are the code that turns them from red to green. One Change covers several settings: what matters is the mapping from the control to each setting.

It is a source in Engineering: nothing is loaded, installed or switched here, no ruleset or setting changes, and nothing under `.github` is touched. It follows release/C70 (`verify Stages` judges a ruleset against the rules its stage declares), whose collector tip is its baseline.
