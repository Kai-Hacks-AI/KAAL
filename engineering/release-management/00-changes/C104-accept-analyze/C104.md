# release/C104 analyze Vulnerabilities is accepted from any current merge-queue run, and its equivalence to Dependency Review is stated

Closes release/G71 of release/C48 without a stored record. GitHub expires workflow runs, and a record that points at one loses its evidence and cannot be repeated. The acceptance is therefore a judge, `judgeAcceptance`, that decides from facts read from the host about the newest merge-queue run of the workflow, and a read-only command, `accept.mjs`, that reads them. Any promotion repeats the evidence; a queue run older than 14 days, or none, is UNKNOWN and never passes. Release/T583 is rewritten to say so.

It also states how release/CTL2 covers what the legacy `Dependency Review` covers, checked by a Case against the workflows.

Source, documentation and Cases only. No workflow, ruleset or `.github` file changes. Retiring `Dependency Review` is a WIRE with its own Owner decision, and so is loading the ruleset that requires the Promoting report.
