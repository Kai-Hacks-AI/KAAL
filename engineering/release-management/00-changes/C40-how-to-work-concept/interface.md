# HOW TO WORK

Human Observes Work. Testing Orchestrates Worker, Owner, Reviewer, Knowledge.

- **HOW** is the first word of the Definition `HOW ARE WE DOING?`, which Review owns. It is named here and not copied.
- **TO**: Testing orchestrates. Deterministic verification of the work is run in the order the phase needs and its result is evidence. Testing owns verification and Review owns validation (`engineering/VIVA-AQUA.md`): a Review judgment never replaces a check, and a passing check never replaces a Review.
- **WORK** names four parts. The **Worker** carries out the work. The **Owner** holds the target and the intent and stays out of the stroke. The **Reviewer** judges the observed work independently of the Worker. **Knowledge** is what the work and its review leave durable, in the place that owns its meaning.

HOW TO WORK names how work is done and observed. It is a mnemonic, not a procedure: it owns no instruction, no capability and no control, and it prescribes no step for a type of work.

## Resolution

A reference to a Definition is a path under `engineering/`, or a Node name that resolves through `kaal list --engine .kaal`. Where both exist, `engineering/` wins. No reference points into `packages/`.
