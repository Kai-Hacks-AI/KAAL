# C72 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it.

## Liked

Kai's slicing rule made the Change small enough to prove alone: the rule for when a PROMOTION is due is a pure function of facts, so five Cases settle it without an App, a token or a pull request. Splitting a SYNC after the ACT (it does not undo the ACT) from a PLAN or DO after it (it does) was found by writing the Cases first, and the CPO's note on the PLAN fits the shape: the ACT's title and body only fill a proposal.

## Learned

Whether a collector is ready is not a flag anyone sets; it follows from the newest merge into it that is not a SYNC. An open pull request into the collector is not a PROMOTION, so only an open one from the collector into main hides the decision. The first run of Branching on a new pull request fails before auto-merge registers, and the failures that remain after the toggle are stale runs, not the pull request's.

## Lacked

Real facts about a real collector: this slice proves the rule on stand-in facts, and the gathering is for a later slice. A way to create a collector branch without the first push becoming the collector's history: the first push of the PLAN commit under the wrong name could not be reset because the ruleset forbids it.

## Longed For

A dry-run workflow that reads the real collectors and shows what the decision would be next to what a person did, before the Dispatcher raises anything. The identity (release/C73) that lets the raised pull request get its checks.

## Left for the Owner

Nothing in this slice. The KAAL Dispatcher App (created from its manifest, its key stored as a secret) is due with release/C73, and the Owner's go.
