## What we learned
- **A valid configuration is not enforcement.** The CPO's HOLD on the PLAN asked for effective enforcement at each station, not only a valid flag file. T1796 and T1797 pin it: at every station a violation that the legacy rule fails exits 1 with the flag `on` and the declaration `preventive`, exits 0 with `advisory`, and a missing file, entry or value never exits 0.
- **Adoption cannot be its own WIRE.** The plain source already holds the aggregator that takes the required name (C168). Installing it before the legacy job is renamed would report two jobs of one name. So the adoption, the aggregator and the rename go together in one swap WIRE. The advisory phase therefore stays inert data (flags, declarations), and the live detective phase was the WIRE of C153.
- **A station written into a workflow would be wrong.** A check is judged on every pull request, whatever its target, so the station is the target's, derived once. The job names two files and no value.
- **A short Change can leave a big file empty.** Writing the Change's own index file with a shell redirect that opened the file before reading it left it empty in one commit. The next commit repaired it. Check the file after a scripted edit.
