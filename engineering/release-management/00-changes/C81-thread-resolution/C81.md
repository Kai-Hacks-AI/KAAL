# release/C81 a review thread on an integration pull request is resolved before it merges

Adds a second Intent to the preventive control `approve Integration` (release/CTL10): a pull request into `kaal/**`, `hotfix/**` or `wire/**` does not merge while a review thread on it is unresolved. It answers the Owner's decision of 18 Nov 2026 on the equivalence of the legacy rulesets: "keep thread resolution". The old integration ruleset (24952357) requires it (`required_review_thread_resolution` true); the `integrating` source of release/C66 leaves it off, so retiring the old approval rule would silently drop it.

The Owner's boundary is part of the Intent: bot output (release/CTL9 review Sync, and later the Inspector) is a plain comment or a check, never an inline review thread, so a SYNC stays hands-off and is never held by a thread no person can resolve.

It covers: the Intent, the Requirement and Architecture, the one setting in `integrating.json`, its declaration in `stages.json`, the amended control text, and the Cases that read all four. No new control is declared: CTL10 gains an Intent.

It is a source in Engineering: nothing is loaded, installed or switched here, no live ruleset or setting changes, and nothing under `.github` is touched. Loading stays the Owner's, with the rest of CTL10.
