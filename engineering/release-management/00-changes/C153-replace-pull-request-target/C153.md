# release/C153 replace the four required pull_request_target checks, then swap them in the rulesets

GitHub blocks `pull_request_target` by default from 2 December 2026, and the Owner rejected an Actions policy exception (release/C90). The old promotion and old integration rulesets still require checks that five workflows produce with that trigger. After the date those checks never report. The Owner chose: **replace, then swap**. Each required check gets a file-based replacement that runs detective first and builds run evidence; the ratchet (release/CTL19, C147) drives the count of workflows using the trigger down to 0; then, per check and on the Owner's go, the ruleset swaps to the replacement through a WIRE and the old workflow is deleted. Dropping a check is the fallback only for a check with no evidence by 2 December. This is a PLAN: it builds nothing, installs nothing, sets no flag, requires no check and changes no ruleset.
