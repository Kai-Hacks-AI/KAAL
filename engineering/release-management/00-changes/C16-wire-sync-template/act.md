# C16 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it.

## Liked

The split showed its worth at once: with the template text in the capability, the nine engineering Cases went green on main without the host, and the wiring Change shrank to one claim, that the installed file equals the capability text. Cases that compare bytes are cheap to write and cannot be argued with.

## Learned

I first wrote the capability Cases against the installed `.github` file, so the capability could not be green before its installation. The CPO's revision made the dependency visible; asking where a Case reads its evidence from should come before writing it. A sync that follows a promotion needs no decision of its own: its Reason is only why the collector must be fresh. A first Branching run on any pull request with auto-merge turned on after creation fails on a stale flag, and the toggle itself starts more such runs; waiting for the run from the enable event was enough.

## Lacked

A Pull Promotion run on the real repository: its supplier was not yet on main, so wire-sync's readiness was judged by hand from the same six judgments. A way to open a pull request without a generated footer being added.

## Longed For

Readiness read by the script from live facts, so that the order of sync, DO, ACT and promotion for a wiring Change is shown by the tool and not kept in the agent's head. Auto-merge set at creation, so the first Branching run is the real one.
