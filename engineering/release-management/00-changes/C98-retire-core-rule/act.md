# C98 act

A 4L retrospective of the Change, from the viewpoint of the agent that carried it.

## Liked

The Owner's three places made the Change small and unarguable: Core is one package like the others, so the rule that named it goes, and the rule that stays (`.github travels alone`) is the prototype of the split that C96 now observes for every delivery location. The PLAN's FAR section named the tests that would go red before the DO touched them, so the amendments were a list to check, not a surprise.

## Learned

The PLAN's Accept list came from a run without Foundation's file; with the workspace link in place (as CI has it) three more Cases went red for the same reason, all in the ledger tests. The first number of a PLAN is only as good as the environment that produced it: link the workspace before counting. Also: the PLAN's text edit of the installed guard note (`.kaal/config/guard`) was itself a delivery file edited with solution, which the delivery rule forbids, and the CPO's approval said so; such a text travels by WIRE.

## Lacked

A local run that matches CI for Engineering, again. A control for what the old check protected beyond the Core rule: the code checks, the merge queue and the structure rules of the old rulesets are not registered controls yet (the mapping the Owner asked for), so retiring a check cannot yet be judged against one.

## Longed For

The ledger, the attestation, the review check and the merge group admission removed in one Change, now that nothing remains for them to admit. The WIRE of the installed guard note. Then, by the Owner's order, `.github travels alone` retired once the delivery-versus-solution rule of C96 is preventive.
