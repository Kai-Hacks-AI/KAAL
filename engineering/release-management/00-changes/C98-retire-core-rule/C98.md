# release/C98 Core has no special rule in Change Isolation

Change Isolation (`engineering/change-isolation/check.mjs`) carries two rules: ".github travels alone" and "Core travels alone". The second is a special setup for one package. It names Core by path (`packages/kaal-core/` and the Engine files under `.kaal`), lists three supporting files that may travel with it (`CORE_SUPPORT`) and is the reason the transition ledger exists. Kai's concept is three places for every package: `packages/<cap>` develops, `engineering/<cap>` uses a non-published version, `.kaal/<cap>` uses a published one. Core is one package like the others, and the rule that treats its `.kaal` files as the same as the package is out of step with that. Kai decided (19 Nov): retire the special setup for Core.

This Change retires the rule and its two path lists in the checker. It is small and connected: one live gate, one rule. The ledger, the attestation and the review check exist only to admit exceptions to this rule; they are named in `change.md` as the next Change, not touched here.
