# Show WIP: the command for this repository

`node run.mjs <owner/repo> show-wip.json` reads every open piece of work through the `gh` command line the environment is signed in to (read-only API calls, 20 pieces a page, a gateway failure read again a few times), runs the Skill's `show-wip.mjs` and prints one line per piece:

```
#number TYPE from → into DISPOSITION reason
```

The disposition is WORK, REVIEW, WAIT or UNKNOWN, from what the host reports. The lines are grouped by the stations of `show-wip.json`, an explicit mapping of where a piece comes from and goes into; a piece no entry matches is listed under `unknown station`. Whatever the host did not report is listed under `not observed`, never guessed. After the board it prints a `Review sequence`: the REVIEW pieces in the order the config declares (station, then type, then number), each CLEAN, NOT CLEAN or UNKNOWN for review at that moment with the reasons and the exact head it was read at. CLEAN means suitable for review at that observed point in time; it authorizes nothing. It exits 0 when it printed a report and 2 naming what it could not read.

- `read.mjs` maps the host's records to the Script's facts (newest run per check, a cut list is not observed, an approval counts only for the current version).
- `show-wip.json` is this repository's config: the declared title prefixes, the station mapping and the review order (`review`: stations, types and the type of a sync).
- `evidence/` holds the run on the real repository (coordination/T39).

It observes and shows only. It makes no release-policy judgment and authorizes nothing.

With `branches` in the facts, the report also holds an `inventory`: one entry per branch in its place (`places`, `development` and `default` of the config), its open pieces as transports, and per package whether main holds stock (tags `@kaihacksai/<name>@<version>` against what npmjs publishes, the package's own changes after the tag; missing evidence is UNKNOWN). `run.mjs <owner/repo> <show-wip.json> overview` adds the overview of counts to the report, and `run.mjs <owner/repo> <show-wip.json> <place>` the full list of one place; without a view the command prints the open pieces only.

Per branch the reader also takes `head`, `ahead` (commits beyond the default branch, the host's comparison default...branch) and `settled` (the newest closed piece whose head is that branch and its head, read from the host's REST pull request list: delivered when it merged, only `closed` when it closed unmerged (the transport's outcome, not a decision about the work); `false` when none closed; not observed when the list is cut at one page or a call failed, named as a gap). The inventory then says what became of the work of each branch: `wip` (an open piece, or commits no settled piece covers), `delivered` (the newest piece merged and the branch tip is that piece's head, which holds for a squash promotion), `discarded` (an explicit, separate decision to discard, same tip rule; the reader reads none yet, so nothing is `discarded` today) or `UNKNOWN` (evidence missing or conflicting, or only a piece closed unmerged, which may be superseded, moved or reorganized: never settled). The overview counts delivered and discarded per place, a place view marks them, and `run.mjs <owner/repo> <show-wip.json> settled` lists only the settled branches, the cleanup candidates of someone with delete rights. It only reports: nothing in it deletes or changes a branch (release/C61).

Limits of `delivered` and `discarded` (a piece is a transport, not the authority over the work or its branch): a branch tip, the closure of a piece and its merge history are evidence, not a lifecycle state, and the verdict is advisory. Incomplete or ambiguous evidence (an open piece, commits after the last piece, a tip that differs from it, a cut list, a failed read) gives `wip` or `UNKNOWN`, never a settled verdict. KAAL does not yet record the lifecycle of a Change itself; Git and the host are the only evidence it has.

`build-page.mjs` turns what this command prints into one static page (`page.mjs`, theme `cvi.json`, the corporate visual identity): `node build-page.mjs cvi.json index.html <time> "Overview=overview.txt" "Settled=settled.txt"`. The text is shown as the command printed it, so what the command could not observe (`UNKNOWN`, `not observed`) stays on the page as it is; the page adds no verdict and authorizes nothing. If an input is missing or empty it names it, exits 2 and writes no page. The workflow source `05-src/wiring/workflows/show-wip-page.yml` runs it daily; installing it (a WIRE) and enabling Pages are separate steps of the Owner.
