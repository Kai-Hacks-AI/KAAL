# C144 requirements added (ids provisional until the collision check at the exact head)

**Headline principle: kaal-guard is opt-in.** [Owner, 2026-11-18] Guard guards only what declares itself, with a `kaal-guard.json`. Nothing is guarded, judged or refused because it exists, and Guard knows no list of what must opt in.

- **guard/F49 Inside a declared folder, a changed file that none of its checks cover fails.** [guard/I1, guard/I2] Guard guards only folders that have a declaration. A changed file with no `kaal-guard.json` above it is not Guard's business: it is neither judged nor refused, as F43 says today. For a changed file whose nearest `kaal-guard.json` (F43) declares no check that applies to it (no check without a `when`, and no `when` that matches the file's path relative to that file), Guard prints a `fail` for `registration`, naming every such path, what is missing and where to register (a check for it, or a wider `when`, in that `kaal-guard.json`). The selected checks still run. This is the whole rule; it adds no ownership model.
  - **No empty registrations.** [CPO, #1949] A `kaal-guard.json` that declares no check is a `fail` naming the file, when Guard discovers it (a changed file in its folder, or a full run). A registered check may be RED by design: Guard reports the actual result and never hides it (C143's runner already does), and whether a RED check may land is for the integration controls.
  - **Registration declares WHAT Guard executes, never WHERE or at which stage.** [CPO, Owner] A `kaal-guard.json` has `id`, `run` and `when` and no other member (F43). Guard runs the declarations wherever it has been wired and judges the same at every stage. F49 takes no stage, and Guard builds in no stage list and no Delivery location.
  - **Removed paths are not judged**, so deleting a file and closing a Change by removing its folder are never failed. An **unknown selection** (`--full`, or no changed files) runs every `kaal-guard.json` as F45 says and prints one note that registration was not judged, with the reason.
  - **Amends guard/F44 only.** F44 let a package remove checks; it may not remove all of them. F43 ("a file with no nearest `kaal-guard.json` selects no check") and guard/T209's fourth step stand unchanged.
  - **Not in this Change, and not Guard's run:** that every capability, Engineering area and Change *has* a declaration (CPO point 1), and that a PR changes Solution or Delivery, never both (CPO point 4). Each is a separate control. Guard does not know Solution from Delivery.

No DO, publication, wiring, SYNC or promotion is authorized by this PLAN.
