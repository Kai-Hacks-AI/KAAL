# C143 requirements added (CPO answers of review 5906850527 applied; ids provisional until the collision check at the exact head)

Terms. A *registration* is Guard's own check declaration (`Guard/Check` plus the member `capability`), not an instance of Core's Registration. Core owns capability and Change identity; Guard resolves a registration's owner against the ownership the **base** holds (`ownership.kaal.json`) and imports no Core registration semantics in this slice.

- **guard/F43 Sourced and installed, one truth.** A capability sources its registration in its own tree, `<owned path>guard/<name>.md`. The installed registration is `.kaal/guard/registered/<capability>/<name>.md`, byte for byte equal to its source. An installed copy that differs from its source, or has none, is cannot judge, naming it. The unchanged hook invocation and CI job run installed registrations beside the hard-wired checks; registering touches neither `.githooks`, CI nor a ruleset. (T209)
- **guard/F44 Base registrations are held.** A pull request may add registrations. A registration the base holds that the candidate deletes, renames, re-owns, or whose command, facts, outcomes or `capability` it changes is cannot judge, naming it, and the candidate's version never runs. Removal or weakening comes only from `main`. (T210)
- **guard/F45 In flight, conservatively.** The checks that run are those of the capabilities whose owned paths changed and of the capabilities that depend on them, transitively. Ownership and dependency edges are read from the **base** (ownership files, and package dependencies as the first source), never from a registration's own claim: a self-declared `depends` is ignored. A change no ownership claims, a capability with no known edges, or any ambiguity expands to every check, never to fewer. `--full` is unconditional. Hard-wired checks are never selected away. (T211)
- **guard/F46 No opt-out.** A registration cannot replace, shadow or switch off a check declared in `.kaal/config/guard/`; one named like it is cannot judge, and the hard-wired check still runs. New registrations stay separate from the hard-wired controls. (T212)
- **guard/F47 A pull request registers only for itself.** A registration is accepted only for a capability the pull request changes, judged by the ownership the base holds. A cross-owner addition, and an addition made after the same pull request altered the ownership, are cannot judge. (T214)
- **guard/A21 Registration and selection.** Discovery, the provenance comparison (F43), the base comparison (F44, F47) and the selection (F45) sit in the runner's declaration reading (guard/A1, guard/A3); the adapters are unchanged. The shape of the capability (ownership, definition, installation contract) follows Core's (T213).

Stated, not decided here: **the gate.** `--full` is run by the merge-queue job (the `merge_group` event into `main`, plus a periodic run), invoked by the wiring Change and not by this PLAN, which activates no hook, workflow or ruleset. Which gate invokes it, and who owns that job, is open question 3 on the PR. Strictness by place is a separate Change with one runner and an explicit verdict policy per place, not a registration inventory per place. This Change authorizes no publishing and does not imply that the other audited moves or the Foundation dependency are done; 0.0.5 stays the intended next release.
