# C144 requirements added (ids provisional until the collision check at the exact head)

- **guard/F49 Every changed file is owned, or Guard fails.** [guard/I1, guard/I2] *Owned* means the file's nearest `kaal-guard.json` (the deepest folder that holds it, F43) declares at least one check that applies to it: a check with no `when`, or a `when` that matches the file's path relative to that `kaal-guard.json`. This applies once the repository has any `kaal-guard.json`; a repository with none behaves as before.
  - **Unowned is a fail.** For each changed file that is not owned, Guard prints a `fail` for `ownership`, naming every such path, what is missing (no `kaal-guard.json` above it, or the nearest one names no check for it) and where to register: add a `kaal-guard.json` at the package root or in the open Change folder, or widen the `when` of the nearest one. Guard does not run everything for it and does not hide it: the checks that were selected still run, and the run's status is the fail's.
  - **The root `kaal-guard.json` is the owner of repo-level files.** A `kaal-guard.json` at the repository root registers the checks that run for root files and for delivery tooling, using `when` globs (for example `*`, `.github/**`, `.githooks/**`). What its checks are is the repository's choice; Guard stays generic. There is no implicit owner: a file the root file does not cover is unowned.
  - **Removed paths are not judged.** A changed path that no longer exists in the working tree (a deleted file, a closed Change's folder) has no owner to ask for, so closing a Change is never refused for removing it.
  - **An unknown selection judges nothing and says so.** When the changed files are not supplied, or `--full` is given, Guard runs every `kaal-guard.json` as F45 says and prints one note that ownership was not judged, with the reason.
  - **Amends guard/F43** (its sentence that a file with no nearest `kaal-guard.json` selects no check and is not unknown) **and guard/F45** (its statement that unclaimed means Engineering): both stand for selection, and F49 adds the judgement on top. The `kaal-guard.json` at the `.kaal/` root still runs on every run. C143's statement that the root files, `.github` and `.githooks` carry no `kaal-guard.json` no longer holds once the repository adopts discovery, because the root file carries their base. Guard T209's fourth step (a file with no `kaal-guard.json` selects nothing) is amended in the DO.
